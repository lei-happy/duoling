# 账号体系设计

> **最后更新**：2026-03-29
>
> **文档状态**：已完成
>
> **适用范围**：Console（运营后台）、Client（客户端/企业端）

## 1. 设计目标

- **统一登录标识**：使用手机号（phone）作为全平台唯一登录凭证，Console 和 Client 共用同一套登录体系
- **一号多企业**：同一手机号可关联多个租户，支持登录时选择企业、登录后切换企业
- **单一密码**：全平台一个用户仅一份密码，用户通过短信验证码自助重置密码
- **多种登录方式**：支持密码登录和短信验证码登录，Console 和 Client 均适用

### 3.5 sys_sms_code（短信验证码表）

数据库：`zt_platform`

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | bigint | PK, AUTO_INCREMENT | 主键 |
| phone | varchar(20) | NOT NULL | 手机号 |
| code | varchar(6) | NOT NULL | 验证码（6位数字） |
| purpose | smallint | NOT NULL | 用途：1-验证码登录 2-重置密码 |
| status | smallint | NOT NULL, DEFAULT 0 | 状态：0-未使用 1-已使用 2-已过期 |
| expire_at | datetime | NOT NULL | 过期时间 |
| client_ip | varchar(50) | | 请求 IP |
| created_at | datetime | NOT NULL | 创建时间 |

索引：`idx_phone_purpose (phone, purpose, status, expire_at)`

**验证码规则**：
- 6 位纯数字随机码，有效期 5 分钟
- 同一手机号同一用途 60 秒内不可重复发送
- 验证成功后标记为已使用（status=1）
- 已对接阿里云号码认证服务（DYPNS），通过 `SendSmsVerifyCode` 接口发送短信
- 短信签名：`速通互联验证码`（系统赠送签名）
- 模板映射：登录=100001、重置密码=100003、变更手机号=100004
- 开发环境可通过 `ALIYUN_SMS_ENABLED=false` 关闭实际发送，仅落表并返回明文验证码

## 4. 认证流程

### 4.1 Console 密码登录（平台管理员）

```
用户输入手机号 + 密码
        │
        ▼
  POST /api/console/auth/login
        │
        ▼
  AuthService.platform_login()
        │
        ├─ 查询 sys_user WHERE phone = ? AND is_deleted = 0
        │
        ├─ 校验 user_type == 0（仅平台管理员可登录）
        │
        ├─ 校验 status == 1（账号未停用）
        │
        ├─ verify_password（bcrypt 校验）
        │
        ▼
  签发 JWT Token（tenant_code = null）
        │
        ▼
  返回 access_token + refresh_token + user_info
```

### 4.2 Console 验证码登录（平台管理员）

```
用户输入手机号 → 获取验证码 → 输入验证码
        │
        ▼
  POST /api/open/sms/send { phone, purpose: 1 }
        │ → 生成6位验证码，写入 sys_sms_code，调用阿里云 DYPNS 发送短信
        │
        ▼
  POST /api/console/auth/sms-login { phone, code }
        │
        ▼
  AuthService.platform_sms_login()
        │
        ├─ SmsService.verify_code() 校验验证码
        │
        ├─ 查询 sys_user WHERE phone = ? AND is_deleted = 0
        │
        ├─ 校验 user_type == 0 AND status == 1
        │
        ▼
  签发 JWT Token（tenant_code = null）
```

### 4.3 Client 密码登录（企业用户）

```
用户输入手机号 + 密码
        │
        ▼
  POST /api/client/auth/login
        │
        ▼
  AuthService.client_login()
        │
        ├─ 查询 sys_user WHERE phone = ? AND is_deleted = 0 AND status = 1
        │
        ├─ verify_password
        │
        ├─ 查询 sys_user_tenant WHERE user_id = ? AND is_deleted = 0 AND status = 1
        │
        ├─ 关联查询 sys_tenant 获取企业名称
        │
        ▼
  判断关联企业数量
        │
        ├─ 0 个 → 抛出异常「未关联任何企业」
        │
        ├─ 1 个（或指定 tenant_code） → 直接签发带 tenant_code 的 JWT Token
        │
        └─ 多个（未指定 tenant_code） → 返回企业选择列表
                                            │
                                            ▼
                                  前端展示企业选择弹窗
                                            │
                                            ▼
                                  用户选择企业后，携带 tenant_code 再次请求登录
```

### 4.4 Client 验证码登录（企业用户）

```
用户输入手机号 → 获取验证码 → 输入验证码
        │
        ▼
  POST /api/open/sms/send { phone, purpose: 1 }
        │
        ▼
  POST /api/client/auth/sms-login { phone, code, tenant_code? }
        │
        ▼
  AuthService.client_sms_login()
        │
        ├─ SmsService.verify_code() 校验验证码
        │
        ├─ 查询 sys_user + sys_user_tenant
        │
        ▼
  判断关联企业数量（与密码登录逻辑一致）
        │
        ├─ 1 个 → 直接签发 JWT
        └─ 多个 → 返回企业选择列表
```

### 4.5 短信验证码重置密码

```
用户点击「忘记密码」→ 输入手机号 → 获取验证码 → 输入新密码
        │
        ▼
  POST /api/open/sms/send { phone, purpose: 2 }
        │ → 校验手机号已注册，生成验证码落表
        │
        ▼
  POST /api/open/sms/reset-password { phone, code, newPassword }
        │
        ▼
  SmsService.reset_password_by_sms()
        │
        ├─ verify_code() 校验验证码
        │
        ├─ 更新 sys_user.password（bcrypt hash）
        │
        ├─ 设置 force_change_pwd = 0
        │
        ├─ 查询 sys_user_tenant 获取所有关联 tenant_code
        │
        ├─ 遍历每个租户库，更新 biz_user.password WHERE phone = ?
        │
        ▼
  密码重置成功（全平台所有关联企业同步生效）
```

### 4.6 租户切换（登录后）

```
用户已登录租户 A，点击切换租户
        │
        ▼
  GET /api/client/auth/user-tenants  ← 获取当前用户可用租户列表
        │
        ▼
  前端展示租户切换下拉框
        │
        ▼
  用户选择租户 B
        │
        ▼
  POST /api/client/auth/switch-tenant  ← 传入目标 tenant_code
        │
        ▼
  AuthService.switch_tenant()
        │
        ├─ 从当前 JWT 获取 user_id
        │
        ├─ 校验目标租户关联有效（sys_user_tenant 中存在且 status=1）
        │
        ├─ 查询目标租户内的角色信息
        │
        ▼
  签发新的 JWT Token（tenant_code = 目标租户编码）
        │
        ▼
  前端更新 Token 并重新加载页面
```

## 5. JWT Token 设计

### 5.1 Token 载荷（TokenData）

| 字段 | 类型 | 说明 |
|------|------|------|
| user_id | int | 平台用户 ID（sys_user.id） |
| phone | str | 手机号 |
| user_type | int | 用户类型 |
| tenant_code | str \| None | 租户编码（Console 登录时为 null） |
| roles | list[str] | 角色编码列表 |

### 5.2 Token 生命周期

| Token 类型 | 有效期 | 用途 |
|-----------|--------|------|
| access_token | 由 `JWT_ACCESS_TOKEN_EXPIRE_MINUTES` 配置 | API 请求认证 |
| refresh_token | 由 `JWT_REFRESH_TOKEN_EXPIRE_MINUTES` 配置 | 刷新 access_token |

### 5.3 Token 存储

- 前端通过 `localStorage` 存储（支持 "记住我" 功能）
- 每次 API 请求通过 `Authorization: Bearer {token}` 发送
- 响应头若包含新 Token，前端拦截器自动更新

## 6. 平台同步机制

### 6.1 同步触发场景

企业端通过员工管理模块新增/编辑/删除员工时，`BizPlatformUserSync` 服务自动将变更同步到平台库。

### 6.2 同步策略（以 phone 为关联标识）

#### 新增员工

```
在租户库创建 biz_user
        │
        ▼
  BizPlatformUserSync.sync_employee_create()
        │
        ├─ 以 phone 查询 sys_user
        │
        ├─ 如已存在 → 复用该 sys_user
        │  ├─ 检查 sys_user_tenant 是否已关联当前租户
        │  ├─ 不存在 → 创建 sys_user_tenant 关联
        │  └─ 已存在但 is_deleted=1 → 恢复关联
        │
        ├─ 如不存在 → 创建新 sys_user + sys_user_tenant
        │
        ▼
  同步完成
```

#### 编辑员工

```
更新租户库 biz_user
        │
        ▼
  BizPlatformUserSync.sync_employee_update()
        │
        ├─ 以 phone 查找对应 sys_user
        │
        ├─ 同步更新 sys_user 的 real_name、email 等字段
        │
        ├─ 如手机号变更 → 更新 sys_user.phone
        │
        ▼
  同步完成
```

#### 密码管理

密码由用户自行管理，管理员不再具备重置他人密码的能力：
- **用户自助重置**：通过短信验证码重置密码（`/api/open/sms/reset-password`），更新 `sys_user.password` 后自动反向同步到所有关联租户库的 `biz_user.password`
- **登录后修改**：用户登录后可通过旧密码修改新密码（`/api/client/auth/password`）

| 0 | 平台管理员 | 可登录 Console 运营后台 |
| 1 | 租户管理员 | 企业超级管理员 |
| 2 | 租户用户 | 企业普通员工 |

### 7.2 企业用户类型（biz_user.user_type）

| 值 | 类型 | 说明 |
|----|------|------|
| 1 | 管理员 | 企业管理员 |
| 2 | 操作员 | 普通操作员 |
| 3 | 驾驶员 | 驾驶员（由专门的驾驶员管理模块维护） |

## 9. 安全设计

### 9.1 密码安全

- 使用 bcrypt 算法进行密码哈希存储
- 支持首次登录强制修改密码（`force_change_pwd` 标记）
- 密码由用户自行管理，管理员不具备重置他人密码的权限
- 用户可通过短信验证码自助重置密码

### 9.2 验证码安全

- 验证码为 6 位纯数字，有效期 5 分钟
- 同一手机号同一用途 60 秒内不可重复发送（防刷限制）
- 验证码使用后立即标记为已使用，不可重复验证
- 过期验证码自动标记为已过期
- 已对接阿里云 DYPNS 短信认证服务，验证码通过短信实际下发；`ALIYUN_SMS_ENABLED=false` 时仅落表不发短信，接口返回明文验证码便于调试

### 9.3 登录安全

- JWT Token 签名使用 HS256 算法
- Token 包含过期时间（exp），后端校验时自动拒绝过期 Token
- 租户中间件对需要认证的路径自动解析和验证 Token
- 登录失败返回统一的错误信息，不暴露具体失败原因给前端（后端日志记录详细原因）

### 9.4 数据隔离

- 平台库与租户库物理隔离（独立数据库）
- 租户中间件确保每个请求只能访问其 Token 中指定的租户数据
- 切换租户时需校验 `sys_user_tenant` 中的关联关系和状态

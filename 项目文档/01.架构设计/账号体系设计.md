# 账号体系设计

> **最后更新**：2026-03-29
>
> **文档状态**：已完成
>
> **适用范围**：Console（运营后台）、Client（客户端/企业端）

## 1. 设计目标

- **统一登录标识**：使用手机号（phone）作为全平台唯一登录凭证，Console 和 Client 共用同一套登录体系
- **一号多企业**：同一手机号可关联多个租户，支持登录时选择企业、登录后切换企业
- **单一密码**：全平台一个用户仅一份密码，任一租户内的密码重置影响所有已关联企业

## 2. 整体架构

       │                  │
       │   手机号 + 密码    │   手机号 + 密码 + 租户选择
       │                  │
       ▼                  ▼
┌─────────────────────────────────┐
│         FastAPI 后端             │
│   ┌─────────────────────────┐   │
│   │  AuthService            │   │

│   │  ├─ client_login()      │   │ ← Client 登录
│   │  ├─ get_user_tenants()  │   │ ← 获取可用租户列表

## 4. 认证流程

### 4.1 Console 登录（平台管理员）

```
用户输入手机号 + 密码
        │
        ▼
  POST /api/console/auth/login
        │
        ▼
  AuthService.platform_login()
        │
        ├─ 查询 sys_user WHERE phone = ? AND is_deleted = 0
        │
        ├─ 校验 user_type == 0（仅平台管理员可登录）
        │
        ├─ 校验 status == 1（账号未停用）
        │
        ├─ verify_password（bcrypt 校验）
        │
        ▼
  签发 JWT Token（tenant_code = null）
        │
        ▼
  返回 access_token + refresh_token + user_info
```

### 4.2 Client 登录（企业用户）

```
用户输入手机号 + 密码
        │
        ▼
  POST /api/client/auth/login
        │
        ▼
  AuthService.client_login()
        │
        ├─ 查询 sys_user WHERE phone = ? AND is_deleted = 0 AND status = 1
        │
        ├─ verify_password
        │
        ├─ 查询 sys_user_tenant WHERE user_id = ? AND is_deleted = 0 AND status = 1
        │
        ├─ 关联查询 sys_tenant 获取企业名称
        │
        ▼
  判断关联企业数量
        │
        ├─ 0 个 → 抛出异常「未关联任何企业」
        │
        ├─ 1 个（或指定 tenant_code） → 直接签发带 tenant_code 的 JWT Token
        │
        └─ 多个（未指定 tenant_code） → 返回企业选择列表
                                            │
                                            ▼
                                  前端展示企业选择弹窗
                                            │
                                            ▼
                                  用户选择企业后，携带 tenant_code 再次请求登录
```

### 4.3 租户切换（登录后）

```
用户已登录租户 A，点击切换租户
        │
        ▼
  GET /api/client/auth/user-tenants  ← 获取当前用户可用租户列表
        │
        ▼
  前端展示租户切换下拉框
        │
        ▼
  用户选择租户 B
        │
        ▼
  POST /api/client/auth/switch-tenant  ← 传入目标 tenant_code
        │
        ▼
  AuthService.switch_tenant()
        │
        ├─ 从当前 JWT 获取 user_id
        │
        ├─ 校验目标租户关联有效（sys_user_tenant 中存在且 status=1）
        │
        ├─ 查询目标租户内的角色信息
        │
        ▼
  签发新的 JWT Token（tenant_code = 目标租户编码）
        │
        ▼
  前端更新 Token 并重新加载页面
```

## 5. JWT Token 设计

### 5.1 Token 载荷（TokenData）

| 字段 | 类型 | 说明 |
|------|------|------|
| user_id | int | 平台用户 ID（sys_user.id） |
| phone | str | 手机号 |
| user_type | int | 用户类型 |
| tenant_code | str \| None | 租户编码（Console 登录时为 null） |
| roles | list[str] | 角色编码列表 |

### 5.2 Token 生命周期

| Token 类型 | 有效期 | 用途 |
|-----------|--------|------|
| access_token | 由 `JWT_ACCESS_TOKEN_EXPIRE_MINUTES` 配置 | API 请求认证 |
| refresh_token | 由 `JWT_REFRESH_TOKEN_EXPIRE_MINUTES` 配置 | 刷新 access_token |

### 5.3 Token 存储

- 前端通过 `localStorage` 存储（支持 "记住我" 功能）
- 每次 API 请求通过 `Authorization: Bearer {token}` 发送
- 响应头若包含新 Token，前端拦截器自动更新

## 6. 平台同步机制

### 6.1 同步触发场景

企业端通过员工管理模块新增/编辑/删除员工时，`BizPlatformUserSync` 服务自动将变更同步到平台库。

### 6.2 同步策略（以 phone 为关联标识）

#### 新增员工

```
在租户库创建 biz_user
        │
        ▼
  BizPlatformUserSync.sync_employee_create()
        │
        ├─ 以 phone 查询 sys_user
        │
        ├─ 如已存在 → 复用该 sys_user
        │  ├─ 检查 sys_user_tenant 是否已关联当前租户
        │  ├─ 不存在 → 创建 sys_user_tenant 关联
        │  └─ 已存在但 is_deleted=1 → 恢复关联
        │
        ├─ 如不存在 → 创建新 sys_user + sys_user_tenant
        │
        ▼
  同步完成
```

#### 编辑员工

```
更新租户库 biz_user
        │
        ▼
  BizPlatformUserSync.sync_employee_update()
        │
        ├─ 以 phone 查找对应 sys_user
        │
        ├─ 同步更新 sys_user 的 real_name、email 等字段
        │
        ├─ 如手机号变更 → 更新 sys_user.phone
        │
        ▼
  同步完成
```

#### 密码重置

```
任一租户管理员重置员工密码
        │
        ▼
  更新 sys_user.password（平台库）
        │
        ▼
  该用户在所有关联租户中均使用新密码
```

## 7. 员工类型说明

### 7.1 平台用户类型（sys_user.user_type）

| 值 | 类型 | 说明 |
|----|------|------|
| 0 | 平台管理员 | 可登录 Console 运营后台 |
| 1 | 租户管理员 | 企业超级管理员 |
| 2 | 租户用户 | 企业普通员工 |
| 3 | 驾驶员 | 驾驶员用户 |

### 7.2 企业用户类型（biz_user.user_type）

| 值 | 类型 | 说明 |
|----|------|------|
| 1 | 管理员 | 企业管理员 |
| 2 | 操作员 | 普通操作员 |
| 3 | 驾驶员 | 驾驶员（由专门的驾驶员管理模块维护） |

### 7.3 管理分工

- **管理员 / 操作员**：通过企业端「员工管理」模块进行增删改查
- **驾驶员**：通过企业端「驾驶员管理」专属模块进行管理，员工管理模块不处理驾驶员的新增操作

## 9. 安全设计

### 9.1 密码安全

- 使用 bcrypt 算法进行密码哈希存储
- 支持首次登录强制修改密码（`force_change_pwd` 标记）
- 密码重置由管理员操作，重置后自动设置 `force_change_pwd = 1`

### 9.2 登录安全

- JWT Token 签名使用 HS256 算法
- Token 包含过期时间（exp），后端校验时自动拒绝过期 Token
- 租户中间件对需要认证的路径自动解析和验证 Token
- 登录失败返回统一的错误信息，不暴露具体失败原因给前端（后端日志记录详细原因）

### 9.3 数据隔离

- 平台库与租户库物理隔离（独立数据库）
- 租户中间件确保每个请求只能访问其 Token 中指定的租户数据
- 切换租户时需校验 `sys_user_tenant` 中的关联关系和状态

# 汽车之家数据同步 — 技术维护手册

> **所属阶段**：阶段二 - 运营后台完善
>
> **文档状态**：已完成
>
> **优先级**：中
>
> **核心目的**：记录从汽车之家抓取品牌车系、经销商数据的完整技术方案，便于后期抓取失败后快速定位问题并调整抓取逻辑。

## 一、功能概述

系统需要从汽车之家（autohome.com.cn）获取两类基础数据：

1. **品牌车系数据**：品牌名称、Logo、车系名称、价格区间、车身尺寸等参配信息
2. **经销商数据**：经销商名称、类型、地址、经纬度坐标、主营品牌

两类数据通过运营后台「数据同步」模块触发，均支持增量同步（仅处理新增数据，跳过已存在记录）。

### 数据来源与目标表

| 数据类型 | 来源站点 | 目标表 | 去重字段 |
|---------|---------|--------|---------|
| 品牌 | autohome.com.cn | `basicdata_brand` | `autohome_brand_id` |
| 车系 | autohome.com.cn | `basicdata_car_series` | `autohome_series_id` |
| 经销商 | dealernew.autohome.com.cn | `basicdata_dealer_info` | `autohome_dealer_id` |

## 二、品牌车系同步

### 2.1 整体流程

```
触发同步(POST /ops/autohome-sync/trigger, jobType=full)
  │
  ├── 1. 请求品牌列表 API（JSON）
  │     URL: https://www.autohome.com.cn/web-main/car/brand/getbrand
  │     返回: { returncode: 0, result: { brandlist: [...] } }
  │
  ├── 2. 遍历每个品牌
  │     ├── 下载品牌 Logo 图片 → 保存到本地
  │     └── 写入/更新 basicdata_brand 表
  │
  ├── 3. 请求品牌报价页（HTML）
  │     URL: https://www.autohome.com.cn/price/brandid_{brand_id}
  │     解析方式: 正则匹配车系 JSON 片段
  │
  ├── 4. 遍历每个车系
  │     ├── 下载车系图片 → 保存到本地
  │     ├── 请求参配页 → 解析车身尺寸等参数
  │     └── 写入/更新 basicdata_car_series 表
  │
  └── 5. 完成，更新任务状态
```

### 2.2 数据源 URL 清单

| 用途 | URL | 返回格式 |
|------|-----|---------|
| 品牌列表 | `https://www.autohome.com.cn/web-main/car/brand/getbrand` | JSON |
| 品牌报价页 | `https://www.autohome.com.cn/price/brandid_{brand_id}` | HTML |
| 参配对比页 | `https://www.autohome.com.cn/config/series/{series_id}.html` | HTML |
| 参配对比页(备) | `https://car.autohome.com.cn/config/series/{series_id}.html` | HTML |
| 年代子页 | `.../config/series/{series_id}-{year_id}.html` | HTML |
| 单车型参配 | `.../config/spec/{spec_id}.html` | HTML |

### 2.3 品牌列表 API 解析

**请求**：`GET https://www.autohome.com.cn/web-main/car/brand/getbrand`

**响应结构**：

```json
{
  "returncode": 0,
  "result": {
    "brandlist": [
      {
        "id": 33,
        "name": "奥迪",
        "country": "德国",
        "logo": "//car3.autoimg.cn/cardfs/brand/...",
        ...
      }
    ]
  }
}
```

**解析逻辑**（`parse_brand_list_json`）：校验 `returncode == 0`，取 `result.brandlist` 数组。

**字段映射**：

| API 字段 | 数据库字段 | 说明 |
|----------|-----------|------|
| `id` | `autohome_brand_id` | 去重唯一键 |
| `name` | `brand_name_cn` | 品牌中文名 |
| `country` | `brand_country` | 品牌国别 |
| `logo` | `brand_logo` | 下载后保存为本地路径 |

### 2.4 车系报价页解析

**请求**：`GET https://www.autohome.com.cn/price/brandid_{brand_id}`

**解析方式**：正则表达式匹配 HTML 中嵌入的 JSON 数据片段。

**核心正则**：

- **完整匹配**（含价格）`SERIES_RE_FULL`：匹配包含 `seriesid`、`seriesname`、`seriesimg`、`seriesminprice`、`seriesmaxprice` 的 JSON 片段
- **简略匹配**（无价格）`SERIES_RE_SIMPLE`：仅匹配 `seriesid`、`seriesname`、`seriesimg`，用于补充未被完整正则覆盖的车系

**解析函数**（`parse_series_from_price_html`）：先用 `SERIES_RE_FULL` 匹配，再用 `SERIES_RE_SIMPLE` 补充，通过 `seen[sid]` 去重。

**字段映射**：

| HTML 字段 | 数据库字段 | 说明 |
|-----------|-----------|------|
| `seriesid` | `autohome_series_id` | 去重唯一键 |
| `seriesname` | `series_name` | 车系名称 |
| `seriesimg` | `series_image` | 下载后保存为本地路径 |
| `seriesminprice` / `seriesmaxprice` | `price` | 格式化为 `x.xx-y.yy万` |

### 2.5 参配页解析

**目标**：获取车身尺寸、能源类型、整备质量等结构化参数。

**解析方式**：

1. 在 HTML 中查找内嵌的 `config` JS 变量（标记：`var config =` 或 `window.config =`）
2. 使用括号配对算法（`_extract_balanced_json_object`）提取完整 JSON 对象
3. `json.loads` 解析后遍历参配表行

**参配字段映射**（通过中文标签匹配）：

| 参配页标签 | 数据库字段 | 说明 |
|-----------|-----------|------|
| 能源类型 | `energy_type` | 纯电动/插电混动等 |
| 长×宽×高 / 车长 | `length_mm` | 毫米 |
| 车宽 | `width_mm` | 毫米 |
| 车高 | `height_mm` | 毫米 |
| 轴距 | `wheelbase_mm` | 毫米 |
| 前轮距 | `front_track_mm` | 毫米 |
| 后轮距 | `rear_track_mm` | 毫米 |
| 接近角 | `approach_angle` | 度 |
| 离去角 | `departure_angle` | 度 |
| 整备质量 | `curb_weight_kg` | 千克 |

**请求策略**：先请求车系参配对比页 → 若无数据则尝试年代子页（最多 8 个）→ 仍无则取首个 spec 单车型页。

### 2.6 增量同步逻辑

当 `incrementalOnly = true`（前端默认）时：

- **品牌**：若 `autohome_brand_id` 已存在于 `basicdata_brand` 表 → 跳过 Logo 下载和品牌更新，仅从 DB 查 `brand_id` 供车系关联
- **车系**：若 `autohome_series_id` 已存在于 `basicdata_car_series` 表 → 完全跳过（不下载图片、不拉参配、不写库）
- 仍会对每个品牌请求报价页以发现新车系

## 三、经销商数据同步

### 3.1 整体流程

```
触发同步(POST /ops/dealer-sync/trigger)
  │
  ├── 1. 调用城市列表 API（JSON）
  │     URL: https://dealernew.autohome.com.cn/api/dealerlq/car/area/groupByCityByLetter
  │     返回全国约 370 个城市的 cityId / cityName / cityPinYin
  │
  ├── 2. 遍历每个城市
  │     ├── 调用经销商列表 API（JSON，分页）
  │     │   URL: /api/dealerlq/dealerlist/list/listPCDealers
  │     │   每页 20 条，通过 pageIndex 翻页
  │     │
  │     └── 3. 对每个新经销商
  │           ├── 请求详情页 HTML → 解析 NUXT payload 获取经纬度
  │           └── 写入 basicdata_dealer_info 表
  │
  └── 4. 完成，更新任务状态
```

### 3.2 数据源 URL 清单

| 用途 | URL | 返回格式 |
|------|-----|---------|
| 城市列表 | `https://dealernew.autohome.com.cn/api/dealerlq/car/area/groupByCityByLetter?_appId=dealer&_encoding=utf8` | JSON |
| 经销商列表 | `https://dealernew.autohome.com.cn/api/dealerlq/dealerlist/list/listPCDealers` | JSON |
| 经销商详情 | `https://dealernew.autohome.com.cn/{dealer_id}/` | HTML (Nuxt SSR) |

**请求**：`GET /api/dealerlq/car/area/groupByCityByLetter?_appId=dealer&_encoding=utf8`

**响应结构**：

### 3.4 经销商列表 API

**请求**：`GET /api/dealerlq/dealerlist/list/listPCDealers`

| `pageIndex` | 页码 | 从 1 开始 |
| `pageSize` | 每页条数 | 固定 20（10 可用，50 以上会报错） |
| `countyId` | `0` | 不筛选区县 |
| `brandId` | `0` | 不筛选品牌 |
| `factoryId` | `0` | 不筛选厂商 |

| `orderType` | `0` | 默认排序 |
| `isSales` | `0` | 不限 |

**响应结构**：

```json

  "message": "",
  "result": {
    "rowcount": 688,
    "pagecount": 35,
    "pageindex": 1,
    "list": [
      {
        "dealerId": 2029438,
        "kindStr": "4S店",
        "mainDealerSimpleName": "一汽服贸丰田丨厂家直营",
```

**字段映射**：

| API 字段 | 数据库字段 | 说明 |
|----------|-----------|------|
| `dealerId` | `autohome_dealer_id` | 去重唯一键 |
| `mainDealerSimpleName` | `dealer_name` | 经销商名称 |

**关于分页**：`pageSize` 最大支持 20，更大的值（如 50、100）会返回参数格式错误。

### 3.5 经销商详情页（坐标获取）

**为何需要详情页**：列表 API 不返回经纬度坐标，需要从详情页获取。

**请求**：`GET https://dealernew.autohome.com.cn/{dealer_id}/`

**页面技术栈**：Nuxt.js 3 SSR，数据嵌入在 `window.__NUXT__` IIFE 中。

#### NUXT IIFE 结构

详情页的服务端渲染数据以 IIFE（立即执行函数）形式嵌入 HTML：

```javascript
window.__NUXT__=(function(a,b,c,...,I,J,...){
  return {
    data: { ... },
    pinia: {
      app: {
        dealerInfo: {
          dealerId: e,         // e 是形参名，对应实参中的具体值
          longitude: I,        // I 对应实参 116.417635
          latitude: J,         // J 对应实参 39.723249
          address: "...",
          ...
        }
      }
    }
  }
}(0,"",1,null,2029438,...,116.417635,39.723249,...))
```

#### 解析步骤

1. **定位**：在 HTML 中查找 `window.__NUXT__=`，截取到 `</script>`
2. **提取形参**：正则 `\(function\(([^)]+)\)` 提取参数名列表（如 `a,b,c,...,I,J,...`）
3. **提取函数体**：从 `){` 开始，通过花括号深度追踪找到函数体结束的 `}`
4. **提取实参**：函数体结束后的 `(...)` 中为实参值列表
5. **构建映射表**：将形参名与实参值一一对应（如 `I → 116.417635`，`J → 39.723249`）
6. **从函数体提取数据**：用正则在函数体中匹配 `longitude:(\w+),latitude:(\w+)`，将匹配到的变量名通过映射表解析为实际数值

#### 提取的字段

| 正则 | 提取内容 | 数据库字段 |
|------|---------|-----------|
| `longitude:(\w+),latitude:(\w+)` | 经纬度 | `longitude` / `latitude` |
| `brandName:"([^"]*)"` | 主营品牌 | `main_brand` |
| `dealerName:(\w+)` | 经销商全称 | `dealer_name`（备用） |
| `address:"([^"]{5,})"` | 详细地址 | `address_detail`（备用） |

**坐标校验**：经度范围 73~136，纬度范围 3~54（中国境内）。

### 3.6 增量同步逻辑

经销商同步固定为增量模式：

1. 任务开始时一次性查询 `basicdata_dealer_info` 表中所有非空的 `autohome_dealer_id`，构建 `existing_ids: Set[int]`
2. 列表中的每个经销商：若 `dealerId in existing_ids` → 跳过（不请求详情页、不写库）
3. 新经销商写入成功后立即 `existing_ids.add(did)`，避免同一任务内重复处理
4. 仍会对每个城市调用列表 API 以发现新增经销商

### 3.7 数据库写入（_upsert_dealer）

- 按 `autohome_dealer_id` 查询是否已存在
- **已存在**：更新 `dealer_name`、`dealer_type`、`city`；`main_brand`、`address_detail`、经纬度仅在新值非空时更新
- **不存在**：插入新记录，`main_brand` 默认 `"未知"`，`address_detail` 默认 `"待补充"`
- 每条新经销商单独 `commit`

## 四、任务管理

两类同步共用 `autohome_sync_job` 表，通过 `job_type` 区分：

| job_type | 说明 |
|----------|------|
| `probe` | 品牌车系连通性探测 |
| `full` | 品牌车系全量/增量同步 |
| `dealer_sync` | 经销商同步 |

**任务状态流转**：`pending → running → success / failed`

**任务参数**（`payload_json`）：

品牌车系同步：

```json
{
  "maxBrands": 0,
  "delayMs": 400,
  "includeInactiveBrands": false,
  "fetchSpecs": true,
  "incrementalOnly": true
}
```

经销商同步：

```json
{
  "maxCities": null,
  "delayMs": 400
}
```

## 六、请求控制

| 参数 | 品牌车系 | 经销商 | 说明 |
|------|---------|--------|------|
| `delayMs` | 默认 400ms | 默认 400ms | 请求间隔，降低对汽车之家压力 |
| `maxBrands` | 可配置 | — | 限制处理品牌数量，0=全部 |
| `maxCities` | — | 可配置 | 限制处理城市数量，null=全部 |

**重试策略**：HTTP 请求失败后最多重试 3 次，间隔为 `1.5 × 重试次数` 秒。

**User-Agent**：固定使用 Chrome 122 Windows UA。

## 七、常见故障排查指南

### 7.1 品牌车系同步

| 故障现象 | 可能原因 | 排查方向 |
|---------|---------|---------|
| 获取品牌列表失败 | API 地址变更或被封 | 浏览器访问 `getbrand` API 验证 |
| 车系数据为空 | 报价页 HTML 结构变更 | 查看日志中的 HTTP 状态码，手动访问报价页对比 HTML 结构 |
| 车系正则匹配失败 | HTML 中的 JSON 字段名或格式变更 | 下载报价页 HTML，搜索 `seriesid` 关键字，对比正则 `SERIES_RE_FULL` |
| 参配数据为空 | 参配页 JS 变量格式变更 | 访问参配页，查看 `config` 变量是否存在，检查 `_CONFIG_MARKERS` |
| 图片下载失败 | CDN 地址变更或防盗链 | 检查 Logo/图片 URL 是否可访问 |

### 7.2 经销商同步

| 故障现象 | 可能原因 | 排查方向 |
|---------|---------|---------|
| 获取城市列表失败 | API 地址变更 | 浏览器访问城市 API 验证 |
| 经销商列表为空 | 列表 API 参数变更 | 手动拼接 URL 在浏览器测试，检查 `returncode` |
| 新增 0 跳过 0 | API 返回了空列表或字段名变更 | 检查 API 响应中的 `list` 数组和 `dealerId` 字段 |
| 坐标全部为空 | 详情页 NUXT 结构变更 | 访问详情页，查看 `window.__NUXT__` 中是否仍有 `longitude`/`latitude` |
| 所有都显示跳过 | 数据库中已有对应记录 | 确认 `basicdata_dealer_info.autohome_dealer_id` 字段数据 |

### 7.3 通用排查步骤

1. **查看任务日志**：在前端「数据同步」页面点击任务行的「日志」按钮
2. **检查 HTTP 可达性**：在服务器上用 `curl` 测试目标 URL 是否可访问
3. **对比页面结构**：将最新页面与代码中的解析逻辑对比，确认字段名/结构是否一致
4. **小范围测试**：使用 `maxCities=1` 或 `maxBrands=1` 限制范围进行测试
5. **查看服务端日志**：后端日志中搜索 `dealer sync` 或 `full sync` 相关错误

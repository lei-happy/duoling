# 运营后台 - 数字员工管理

> 父文档：[00.模块总览.md](00.模块总览.md)
>
> 对应代码：`frontend/console/src/views/ai/employee/` · `backend/app/modules/ai/api/console/employee.py` · `backend/app/modules/ai/services/employee_service.py`

## 一、功能概述

「数字员工」是 AI 数字人模块的角色定义单位，对应一种岗位职责（录单员、数据分析员、档案管理员等）。运营在本页面定义员工的基础信息、欢迎语、提示词、模型配置、可调用工具，以及该员工对哪个产品版本可见。每个数字员工是**全局元数据**，所有租户共享同一份定义，但运行数据（会话/消息）落在各自的租户库。

## 二、需求详情

### 2.1 列表页

工具栏：

- 关键字搜索（编码 / 名称模糊匹配）
- 员工类型下拉：录单员 / 数据分析员 / 档案管理员 / 自定义
- 状态下拉：启用 / 停用
- 「新增数字员工」按钮

列表字段：

| 列 | 说明 |
|----|------|
| 编码 | 全局唯一员工 code |
| 名称 | 用户侧可见名 |
| 类型 | `form_recorder` / `data_analyst` / `archivist` / `custom` |
| 描述 | 一句话简介 |
| 工具数 | 已绑定且 `enabled=1` 的工具数量 |
| 状态 | 启用 / 停用 Tag |
| 操作 | 编辑 / 删除 |

排序：`sort_order ASC, id ASC`。分页 10/20/50。

### 2.2 新增 / 编辑弹窗

宽 780px，分为以下区块：

#### 2.2.1 基础信息

| 字段 | 类型 | 必填 | 校验/规则 |
|------|------|------|-----------|
| 员工头像 | 上传或 URL | 否 | PNG/JPG/WebP/GIF，≤2MB；通过 `/api/console/system/file` 上传得到 URL 自动回填；也可手动填写绝对/相对 URL |
| 员工编码 | 字符串 | **是** | 全局唯一；新建后不可修改（编辑时禁用） |
| 员工名称 | 字符串 | **是** | — |
| 员工类型 | 下拉 | **是** | `form_recorder` / `data_analyst` / `archivist` / `custom` |
| 状态 | 开关 | — | 1=启用 / 0=停用，默认启用 |
| 简介 | 文本域 | 否 | 客户端列表可见的一句话介绍 |

#### 2.2.2 对话引导

| 字段 | 类型 | 说明 |
|------|------|------|
| 欢迎语 | 文本域 | 新会话首条 assistant 消息（空对话时展示在欢迎卡片中） |
| 建议提问 | 字符串数组 | 动态条目，支持增/删；提交时过滤空白；客户端展示为 chip，点击直接发送 |

#### 2.2.3 系统提示词

文本域。两种使用方式：

1. **直接写**：完整的 role prompt，会被 `PromptBuilder` 拼接到 system 段。
2. **引用模板**：以 `@template:模板编码` 开头时，从 `ai_prompt_template` 加载对应模板内容。详见 [03.提示词模板.md](03.提示词模板.md)。

提示词中可使用以下占位符（在装配阶段被 `PromptBuilder.render` 替换）：

| 变量 | 含义 |
|------|------|
| `{{tenant_code}}` | 当前租户编码 |
| `{{user_id}}` | 当前用户 ID |
| `{{user_phone}}` | 当前用户手机号 |
| `{{user_roles}}` | 角色码列表（逗号分隔） |
| `{{now}}` | `YYYY-MM-DD HH:MM:SS` |
| `{{today}}` | `YYYY-MM-DD` |
| `{{employee_name}}` | 数字员工名称 |
| `{{employee_type}}` | 员工类型 |

#### 2.2.4 模型配置（写入 `ai_employee.model_config`，JSON）

| 字段 | 类型 | 默认/范围 | 含义 |
|------|------|----------|------|
| `provider_code` | string | 留空使用默认 Provider | 指定使用某个 Provider 的 `code` |
| `model` | string | 留空使用 Provider 默认模型 | 模型 ID 覆写（如 `qwen-plus`、`deepseek-chat`、`kimi-k2.5`） |
| `temperature` | number | 0~2，步长 0.1 | 采样温度（部分 thinking 模型会被 Provider 强制覆盖） |
| `max_tokens` | int | ≥64，步长 64 | 单轮回复 token 上限 |
| `max_tool_loops` | int | 1~20，默认 6 | LLM ↔ 工具往返最大轮次 |
| `context_window` | int | 4~100，默认 20 | 装配 messages 时取最近 N 条历史 |

未填的字段以 Engine 的默认值兜底（见 `engine/runtime_context.py:EngineContext`）。

#### 2.2.5 工具绑定

按 `category` 分组的复选框（默认分组：waybill / vehicle / customer / file / 未分类）。每勾选一项表示在 `ai_employee_tool` 写入一条 `(employee_id, tool_id, sort_order=按勾选顺序, enabled=1)`。

> 当前版本未提供「自定义工具描述」`custom_description` 的可视化编辑入口，留作远期扩展位。

### 2.3 删除

软删除（`is_deleted = 1`），不级联清理 `ai_employee_tool` 关联。被删除的员工：

- Console 列表不再展示
- 客户端 `GET /api/client/ai/employee` 不再返回
- 历史会话仍以冗余字段（`employee_code`、`employee_name`）展示

## 三、数据模型设计

### 3.1 `ai_employee`（数字员工角色定义）

平台库；`is_deleted` 软删除，无租户隔离。

| 字段 | 类型 | 索引 | 说明 |
|------|------|------|------|
| id | BIGINT PK | — | 自增主键 |
| code | VARCHAR(64) | UK | 员工编码（全局唯一） |
| name | VARCHAR(64) | — | 员工名称 |
| employee_type | VARCHAR(32) | — | `form_recorder/data_analyst/archivist/custom`，默认 `custom` |
| description | VARCHAR(255) | — | 用户侧简介 |
| avatar | VARCHAR(255) | — | 头像 URL 或预置 icon code |
| system_prompt | TEXT | — | 角色提示词（可 `@template:xxx` 引用） |
| welcome_message | VARCHAR(500) | — | 欢迎语 |
| suggested_questions | JSON | — | 建议提问数组 |
| model_config | JSON | — | 模型配置 KV（见 2.2.4） |
| feature_code | VARCHAR(50) | idx | 关联产品功能编码（为空则随 `ai_assistant` 总开关） |
| sort_order | SMALLINT | — | 排序号，默认 0 |
| status | SMALLINT | idx | `0`=停用 `1`=启用，默认 1 |
| created_at / updated_at | DATETIME | — | 自动维护 |
| is_deleted | SMALLINT | — | 软删除 |

### 3.2 `ai_employee_tool`（员工 ↔ 工具绑定）

平台库；联合唯一索引 `(employee_id, tool_id)`。

| 字段 | 类型 | 索引 | 说明 |
|------|------|------|------|
| id | BIGINT PK | — | — |
| employee_id | BIGINT | UK 联合 | 数字员工 ID |
| tool_id | BIGINT | UK 联合 | 工具 ID |
| sort_order | SMALLINT | — | 工具排序号（编辑表单的勾选顺序） |
| enabled | SMALLINT | — | `0`=禁用 `1`=启用，默认 1 |
| custom_description | VARCHAR(255) | — | 自定义工具描述（覆盖默认描述，便于角色化提示）；当前未在 Console 暴露 |
| created_at / updated_at / is_deleted | — | — | — |

绑定关系**全量覆盖式更新**：编辑保存时先 `DELETE WHERE employee_id = ?`，再按提交的 `toolIds` 顺序逐条 `INSERT`，参见 `EmployeeService._sync_tool_bindings`。

### 4.2 创建 / 更新

请求体（`POST` 必填项见 schema，`PUT` 全部可选）：

```json
{
  "code": "form_recorder_default",
  "name": "录单员小智",
  "employeeType": "form_recorder",
  "description": "...",
  "avatar": "...",
  "systemPrompt": "...",
  "welcomeMessage": "...",
  "suggestedQuestions": ["问题1", "问题2"],
  "modelConfig": {
    "provider_code": "default",
    "model": "qwen-plus",
    "temperature": 0.2,
    "max_tokens": 2048,
    "max_tool_loops": 10,
    "context_window": 30
  },
  "featureCode": "ai_assistant",
  "sortOrder": 0,
  "status": 1,
  "toolIds": [3, 4, 5, 6, 7]
}
```

校验规则：

- `code` 全局唯一；重复时返回 `员工编码 {code} 已存在`。
- `PUT` 只更新非空字段，`toolIds` 传 `null` 表示不动绑定，传 `[]` 则清空全部绑定。

## 五、前端页面设计

- 路由：`/ai/employee`
- 列表：`frontend/console/src/views/ai/employee/index.vue`
- 编辑弹窗：`frontend/console/src/views/ai/employee/components/employee-edit.vue`

页面交互要点：

- 工具复选框按 `tools` 接口返回值的 `category` 分组排序。
- 头像区：左侧 80×80 上传卡片 + 右侧 URL 输入框，二选一（上传成功后自动写入右侧）。
- 模型配置使用 `el-input-number`，留空（`null`）表示沿用默认值。

## 六、测试要点

1. 新增数字员工：编码必填校验、重复编码报错、保存后列表立即可见。
2. 编辑：编码字段禁用；模型配置 JSON 字段任一项留空时不进入 `model_config`，避免被解析为 `null` 覆盖默认值。
3. 软删除：`is_deleted=1` 后客户端 `/api/client/ai/employee` 不返回；`PermissionGuard.check` 内对该员工调用工具时返回 `已停用` 提示。
4. 工具绑定：勾选 5 个工具保存 → 重新打开后顺序与勾选顺序一致；取消勾选所有工具 → `ai_employee_tool` 中该员工的记录全部物理删除。
5. 客户端列表：`status=0` 的员工不出现在客户端选员工的左栏。
6. 头像：上传 PNG ≤2MB 成功；超 2MB 拒绝；URL 模式下相对路径会被前端自动加 `/` 前缀。
7. `featureCode`：当前版本与产品功能开通联动逻辑为空（所有 `enterprise` 租户均可见），保留字段供未来按子能力开通使用。

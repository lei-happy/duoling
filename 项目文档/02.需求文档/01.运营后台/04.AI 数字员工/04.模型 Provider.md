# 运营后台 - 模型 Provider

> 父文档：[00.模块总览.md](00.模块总览.md)
>
> 对应代码：`frontend/console/src/views/ai/provider/index.vue` · `backend/app/modules/ai/api/console/provider.py` · `backend/app/modules/ai/services/provider_service.py` · `backend/app/modules/ai/llm/openai_compat.py` · `backend/app/modules/ai/llm/factory.py` · `backend/app/modules/ai/security/crypto.py`

## 一、功能概述

「模型 Provider」管理 LLM 服务接入。当前实现统一走 **OpenAI 兼容 `/chat/completions` 协议**，因此运营在 Console 上配置一次 `(base_url, apiKey, model)` 即可支持通义千问 / DeepSeek / Kimi / OpenAI / Azure OpenAI 等主流厂商。Provider 配置的 apiKey 通过对称加密落库，前端列表只显示掩码版本。

## 二、需求详情

工具栏：

- 关键字搜索（编码 / 名称模糊）
- 状态下拉（启用 / 停用）

列表字段：

| 列 | 说明 |
|----|------|

| 类型 | `openai_compat / openai / azure_openai` |
| 默认模型 | `model_name`（如 `qwen-plus`） |
| Base URL | `base_url`（如 `https://dashscope.aliyuncs.com/compatible-mode/v1`） |

| 默认 | 默认 Provider 显示「默认」Tag；非默认显示「设为默认」按钮 |
| 状态 | 启用 / 停用 |
| 操作 | 编辑 / 删除 |

### 2.2 新增 / 编辑弹窗

宽 680px。

| 字段 | 类型 | 必填 | 规则 |
|------|------|------|------|
| 编码 | string | **是** | 全局唯一；编辑时禁用 |
| 名称 | string | **是** | — |
| 类型 | 下拉 | — | `openai_compat`（默认）/ `openai` / `azure_openai` |
| 超时（秒） | int | — | 5~600，默认 60 |
| Base URL | string | 否 | 不填走 OpenAI 默认 `https://api.openai.com/v1` |

| API Key | string | 新建必填 | 编辑时留空表示不修改（保留密文） |

| 状态 | 开关 | — | 0=停用 / 1=启用 |

> 当前实现在 `OpenAICompatProvider` 内统一走 OpenAI Python SDK；`provider_type` 字段仅用于 Console 展示分类，运行时未做差异化分支处理。Azure OpenAI 用户需在 `extra_params` / `base_url` 中显式配置 `azure_endpoint` / `api_version` 等。

### 2.3 设默认与默认选择策略

- 设默认操作：
  - 列表内点「设为默认」按钮 → 调 `PUT /api/console/ai/provider/{id}/default`，后端把当前行 `is_default=1`，其余 `is_default=0`，**互斥**。
  - 编辑弹窗内打开「设为默认」开关 → 同样互斥（保存接口里处理）。
- 引擎选择 Provider 优先级（`LLMProviderFactory.get`）：
  1. 数字员工 `model_config.provider_code` 指定 → 精确匹配启用中的 `code`；找不到报错。
  2. 未指定 → 取 `is_default=1 AND status=1`。
  3. 仍找不到 → 取 `status=1` 中 id 最小的兜底，并 logger.info 提示「建议在 Console 设默认」。
  4. 仍找不到 → `BizException("未找到可用的 LLM Provider...")`。
- 缓存：工厂内进程级 `cache_key = provider_code or "__default__"`；Provider 信息变更后由 `ProviderService` 调 `LLMProviderFactory.invalidate(code)` 失效缓存（含 `__default__`）。

### 2.4 高级参数 `extra_params`

JSON 对象，键值会**透传**到 `client.chat.completions.create()` 调用，但有 4 个**控制键**会被引擎单独消费而非透传：

| 键 | 类型 | 用途 |
|----|------|------|
| `fixed_temperature` | number | 强制 temperature 值（覆盖数字员工 `model_config.temperature`）。用于 OpenAI o1 / Kimi K2.5+K2.6 这类只允许 `temperature=1` 的 thinking 模型 |
| `omit_params` | string[] | 列出要从最终请求 body 中剔除的字段，如 `["temperature","max_tokens"]`，避免被厂商 400 |
| `include_usage` | boolean | true 时在 `stream_options` 添加 `include_usage`；Kimi/Moonshot、Doubao 不支持，**默认关闭** |
| `disable_tools` | boolean | true 时不下发 `tools` / `tool_choice`，强制降级为纯文本回复（用于不支持 function calling 的模型） |

非控制键照常透传，例如 `{"frequency_penalty": 0.1}`、`{"top_p": 0.9}`、`{"response_format": {"type": "json_object"}}`、`{"reasoning_effort": "low"}` 等。

### 2.6 删除

软删除（`is_deleted=1`）。删除时若该 Provider 是当前默认（`is_default=1`），不会自动选举新默认；运营需手动指定下一个默认。

## 三、apiKey 加密机制

### 3.1 加密 / 解密

实现：`backend/app/modules/ai/security/crypto.py`。

- 密钥派生：`Settings.APP_SECRET_KEY` → `hashlib.sha256(...).digest()` → `base64.urlsafe_b64encode(...)` → 32 字节 Fernet key。
- 落库前：`encrypt_api_key(plain) → "enc::" + token`。
- 读出时：`decrypt_api_key(stored)` 自动判断前缀 `enc::`，无前缀视为兼容老明文。
- 列表展示：`mask_api_key(plain)` 统一返回 `XXXX****YYYY`（长度 < 8 时返回 `****`）。

### 3.2 修改 apiKey 流程

| 操作 | 行为 |
|------|------|
| 新增 Provider 时填写 apiKey | 服务端 `encrypt_api_key` 后写入 `api_key_encrypted` |
| 编辑 Provider 时 apiKey 留空 | 服务端忽略 apiKey 字段，密文保持不变 |
| 编辑 Provider 时填写新 apiKey | 服务端覆盖加密存储；并失效 `LLMProviderFactory` 缓存（无论 code 是否改变） |

### 3.3 故障兜底

- 解密失败（如 `APP_SECRET_KEY` 被改）：`LLMProviderFactory` 走兜底 `api_key = stored_string`（即把密文当明文给 SDK）；下游 401 会被 logger 警告并向客户端推 `error` SSE。修复方式：在 Console 重新填写 apiKey 即可。

### 5.2 新增

请求体（apiKey 必填明文）：

```json
{
  "code": "qwen",
  "name": "通义千问",
  "providerType": "openai_compat",
  "baseUrl": "https://dashscope.aliyuncs.com/compatible-mode/v1",
  "modelName": "qwen-plus",
  "apiKey": "sk-xxxxxx",
  "extraParams": { "include_usage": false },
  "timeoutSeconds": 60,
  "isDefault": true,
  "status": 1
}
```

服务端：

- `code` 重复 → 报错。
- `apiKey` → `encrypt_api_key` 后存 `api_key_encrypted`。
- `isDefault=true` → 把同表其余行 `is_default=0`。
- 调 `LLMProviderFactory.invalidate()` 全量清缓存。

### 5.3 修改

请求体全部可选；`apiKey` 留空表示保持密文不变。同步更新 `is_default` 互斥。命中即清缓存。

### 5.4 设为默认

`PUT /api/console/ai/provider/{id}/default`，无请求体。等价于把指定行 `is_default=1`，其它 `is_default=0`。

### 5.5 删除

`DELETE /api/console/ai/provider/{id}` → `is_deleted=1`，并清缓存。

## 六、前端页面设计

- 路由：`/ai/provider`
- 主组件：`frontend/console/src/views/ai/provider/index.vue`
- 编辑弹窗：嵌在主组件内的 `el-dialog`。

页面交互要点：

- 「设为默认」按钮在非默认行展示，需 `ElMessageBox.confirm` 二次确认；当前行 `status !== 1` 时按钮 `disabled`。
- 「默认」Tag 用 `type=warning` 突出显示，避免与「启用」Tag 混淆。
- API Key 输入框 `type="password"` + `show-password`，编辑模式 placeholder 为「不修改请留空（当前已加密保存）」。
- 高级参数文本域提供示例：`{"fixed_temperature": 1, "omit_params": ["max_tokens"], "disable_tools": false}`，并在下方文字提示 4 个控制键的作用。
- 保存前对高级参数文本做 JSON 校验（必须是 JSON 对象，不接受数组），失败 `ElMessage.error`。

## 七、测试要点

1. 新增 Provider：apiKey 写明文 → DB `api_key_encrypted` 以 `enc::` 开头；列表掩码显示。
2. 编辑 Provider：apiKey 留空保存 → 密文保持不变；写新 apiKey → 密文被覆盖且解密结果与新值一致。
3. 设为默认：调用接口后 SQL `SELECT code FROM ai_model_provider WHERE is_default=1 AND is_deleted=0` 应仅返回一条。
4. 数字员工 `model_config.provider_code='qwen'` 时调用 LLM → factory 取到 `qwen` 行，cache_key `qwen` 命中。
5. 数字员工未指定 provider → 取默认；如默认被停用 → 自动回退到 `status=1` 中 id 最小的，logger 出现回退提示。
6. 修改 Provider 后下次对话：缓存被 invalidate，新对话用最新 apiKey / model_name / extra_params。
7. `extra_params` 控制键测试：
   - `fixed_temperature=1` → 即使数字员工 `model_config.temperature=0.2` 也按 1 发送。
   - `omit_params=["max_tokens"]` → 请求体不含 `max_tokens`。
   - `include_usage=true` → 流式响应末尾收到 `usage` chunk；前端 SSE 收到 `usage` 事件。
   - `disable_tools=true` → 即使有可用工具，请求体不含 `tools`，LLM 只能纯文本。
8. APP_SECRET_KEY 改变后旧密文解密失败 → 前端调用对话报 LLM 401，需 Console 重新填 apiKey；不会丢失数据库其他字段。

> **优先级**：高（核心业务）

## 一、功能概述

运单（计划）是物流公司的上游客户下达的运输任务。在商品车运输领域，一条运单代表「从 A 地运输指定品牌/车型的商品车到 B 地，送至指定经销商/门店」。运单是物流公司计算收入的核心依据。

核心设计原则：

- **商品车运输专用**：运单字段针对商品车运输场景设计，包含品牌/车型、经销商门店、台数等商品车特有字段
- **自动计费与手动兼容**：通过系统配置项控制运费计算策略，支持自动计费、手动填写或两者结合
- **与计费引擎解耦**：运单模块通过 Service 接口调用计费引擎，引擎不可用时不影响运单基本录入功能
- **语义化命名**：使用 `biz_waybill`（运单）替代原通用的 `biz_order`（订单），更贴合商品车运输的业务语义

## 二、业务背景

### 核心业务诉求

1. **计划录入**：物流公司收到上游客户的运输计划后，在系统中录入运单，记录客户、出发地、目的地、品牌/车型、收车门店等核心信息
2. **自动计算收入**：录入运单时，系统基于客户合同中维护的运价信息自动计算运费，作为公司收入的依据
3. **灵活的计费策略**：不同公司管理要求不同，有的要求必须自动计费才能保存，有的允许手动填写运费。通过系统配置项控制

### 3.3 运费计算交互

运单录入时，运费金额的处理逻辑取决于系统配置项 `waybill.freight_calc_mode`：

**模式一：强制自动计费（`auto_required`）**
- 用户填写完客户、出发地、目的地后，运费字段自动触发计费并填入结果
- 如果计费引擎无匹配结果，运费字段显示「未匹配到运价」，保存按钮禁用
- 用户需要先去「计费管理」维护运价合同后才能保存

**模式二：优先自动 + 允许手动（`auto_preferred`，推荐默认值）**
- 用户填写完客户、出发地、目的地后，自动触发计费并填入结果
- 如果计费引擎无匹配结果，运费字段变为可编辑状态，用户可手动填写
- 运费为空也允许保存（运费待定）

**模式三：仅手动（`manual_only`）**
- 不触发自动计费
- 运费字段始终可编辑，用户自行填写
- 运费为空也允许保存

### 3.4 运单状态

| 状态值 | 状态名称 | 说明 |
|--------|---------|------|
| 0 | 待确认 | 新录入，待确认信息 |
| 1 | 已确认 | 信息已确认，待调度 |
| 2 | 已调度 | 已安排车辆和司机 |
| 3 | 运输中 | 装车发出，在途运输 |
| 4 | 已送达 | 到达目的地 |
| 5 | 已完成 | 业务闭环 |
| 6 | 已取消 | 取消运输 |

### 3.5 删除运单

- 软删除（`is_deleted = 1`）
- 仅「待确认」和「已取消」状态的运单可删除
- 其他状态的运单禁止删除

### 3.6 系统配置 - 运费计算策略

配置路径：系统管理 → 业务参数配置

| 配置键 | 配置名称 | 配置值 | 默认值 |
|--------|---------|--------|--------|
| `waybill.freight_calc_mode` | 运费计算模式 | `auto_required` / `auto_preferred` / `manual_only` | `auto_preferred` |

## 六、运单保存流程

```
用户提交运单
    │
    ▼
读取系统配置 waybill.freight_calc_mode
    │
    ├── auto_required（强制自动计费）
    │       │
    │       ▼
    │   调用 BillingEngineService.calculate_freight()
    │       │
    │       ├── 匹配到运价 → 填入运费 + freight_source=0 + freight_price_type → 保存
    │       └── 未匹配 → 拒绝保存，返回错误「请先维护运价合同」
    │
    ├── auto_preferred（优先自动 + 允许手动）
    │       │
    │       ▼
    │   调用 BillingEngineService.calculate_freight()
    │       │
    │       ├── 匹配到运价 → 填入运费 + freight_source=0 + freight_price_type → 保存
    │       └── 未匹配 → 用户填了运费？
    │               ├── 是 → 保存手动运费 + freight_source=1（freight_price_type 不设置）
    │               └── 否 → 保存运单（运费为空）
    │
    └── manual_only（仅手动）
            │
            ▼
        保存用户填写的运费 + freight_source=1 → 保存
```

## 九、测试要点

1. 新增运单：填写必填字段，验证运单号自动生成和手动输入

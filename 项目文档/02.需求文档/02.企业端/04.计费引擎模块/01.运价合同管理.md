# 企业端计费引擎模块 - 运价合同管理

> **所属阶段**：阶段四/五 - 计费引擎（跨阶段通用服务）
>
> **文档状态**：已完成
>
> **优先级**：高（运单自动计费的前置依赖）

## 一、功能概述

计费引擎是一个通用的费用计算服务模块。第一个计费场景是「运单运费计算」：基于客户与物流公司签订的运价合同，当录入运单时，根据客户 + 出发地 + 目的地自动匹配运价并计算运费收入。

核心设计原则：

- **通用引擎架构**：计费引擎不仅限于运单运费，后续可扩展承运商成本计算、司机结算、附加费等场景
- **与运单模块解耦**：计费引擎通过 Service 接口被调用，调用方不直接访问计费数据表；计费引擎无匹配结果时返回 None 而非抛出异常
- **多级匹配优先级**：支持从精确到宽泛的多级运价匹配，适配不同精细度的定价需求

## 二、业务背景

### 核心业务诉求

1. **自动计算运费**：物流公司与上游客户签订运价合同，约定从 A 地到 B 地运输商品车的单车运费。录入运单时，系统自动查找匹配的运价并计算运费金额
2. **合同生命周期管理**：运价合同有生效/失效日期，系统只在有效期内匹配运价
3. **灵活定价**：不同客户、不同线路、不同品牌/车型可以有不同的运价，支持精细化定价

### 后续扩展场景

| 场景 | 说明 | 预计阶段 |
|------|------|----------|
| 运单运费（收入） | 基于客户合同计算 | 当前 |
| 承运商成本 | 基于承运商合同计算运输成本 | 阶段六 |
| 司机结算 | 基于司机薪资规则计算结算费 | 阶段六 |
| 附加费 | 超里程、等待费、装卸费等 | 阶段六 |

#### 3.2.2 新增/编辑运价明细

| 字段 | 说明 | 规则 |
|------|------|------|
| 计费模式 | 计价方式 | 必填，单选：台单价(0)/单公里单价(1)/整单价格(2)，默认「台单价」 |
| 出发地 | 出发城市/地区 | 必填，地区级联选择器（省/市/区县三级），从基础数据地区库获取 |
| 目的地 | 到达城市/地区 | 必填，地区级联选择器（省/市/区县三级），从基础数据地区库获取 |
| 商品车品牌 | 适用的品牌 | 选填（整单价格模式下隐藏），下拉选择器，从基础数据品牌车型库获取，为空表示不限品牌 |
| 商品车车型 | 适用的车型 | 选填（整单价格模式下隐藏），下拉选择器，根据所选品牌联动加载车系数据，为空表示不限车型 |
| 线路公里数 | 出发地到目的地的公里数 | 单公里计费模式时必填，客户标准公里数 |
| 单价 | 运费单价 | 必填，数值 > 0；台单价=元/台，单公里=元/台/公里，整单=元/整单 |
| 运价类型 | 明确运价/预估运价 | 必填，单选，默认「明确运价」 |
| 生效日期 | 该运价的生效时间 | 选填，默认使用合同生效日期 |
| 失效日期 | 该运价的失效时间 | 选填，默认使用合同失效日期 |

> **计费模式说明**：
> - **台单价**（`billing_mode = 0`）：按每台车固定运费计价，运费 = 单价 × 台数
> - **单公里单价**（`billing_mode = 1`）：按每台车每公里计价，运费 = 单价 × 公里数 × 台数；需维护客户标准公里数
> - **整单价格**（`billing_mode = 2`）：按整单打包价计价，运费 = 单价（不乘台数）；不区分品牌车型，只看出发地-目的地

> **运价类型说明**：
> - **明确运价**（`price_type = 0`）：客户合同中确认的正式运价，匹配时优先使用
> - **预估运价**（`price_type = 1`）：运营人员根据经验预估的运价，用于客户运价信息后置但需确保运单有收入的场景；当无明确运价时作为备选匹配

### 3.3 计费引擎 - 运费计算

#### 3.3.1 计费入口

计费引擎通过 `BillingEngineService.calculate_freight()` 方法对外提供服务，输入参数：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| customer_id | int | 是 | 客户 ID |
| origin_code | str | 是 | 出发地编码 |
| destination_code | str | 是 | 目的地编码 |
| vehicle_brand | str | 否 | 商品车品牌 |
| vehicle_model | str | 否 | 商品车车型 |
| quantity | int | 否 | 台数，默认 1（用于计算运费总额） |
| billing_date | date | 否 | 计费日期，默认当天 |

返回值：`FreightResult | None`

```python
class FreightResult:
    unit_price: Decimal      # 单价（含义随 billing_mode 变化）
    billing_mode: int         # 计费模式：0-台单价 1-单公里 2-整单价
    distance_km: Decimal      # 公里数（模式1时有值）
    total_amount: Decimal     # 计算后的运费总额
    contract_id: int          # 匹配的合同 ID
    contract_no: str          # 合同编号
    rate_id: int              # 匹配的运价明细 ID
    match_level: str          # 匹配级别：exact/brand/general
    price_type: int           # 运价类型：0-明确运价 1-预估运价
```

> **运费总额计算公式**（由引擎内部完成，调用方直接使用 `total_amount`）：
> - 台单价(0)：`total_amount = unit_price × quantity`
> - 单公里(1)：`total_amount = unit_price × distance_km × quantity`
> - 整单价(2)：`total_amount = unit_price`（不乘台数）

#### 3.3.2 匹配优先级

按以下优先级从高到低匹配，命中即返回。**在每个匹配级别内，优先选择「明确运价」（price_type=0），其次选择「预估运价」（price_type=1）**：

1. **精确匹配**：客户 + 出发地 + 目的地 + 品牌 + 车型 → 明确优先，其次预估
2. **品牌匹配**：客户 + 出发地 + 目的地 + 品牌（车型为空）→ 明确优先，其次预估
3. **通用匹配**：客户 + 出发地 + 目的地（品牌和车型均为空）→ 明确优先，其次预估

> 匹配逻辑示意：
> ```
> 精确匹配（品牌+车型）→ 明确运价 > 预估运价
>       ↓ 无匹配
> 品牌匹配（仅品牌）  → 明确运价 > 预估运价
>       ↓ 无匹配
> 通用匹配（不限品牌）→ 明确运价 > 预估运价
>       ↓ 无匹配
> 返回 None
> ```

#### 3.3.3 匹配规则

- 只匹配状态为「生效」的合同（`status = 1`）
- 只匹配在有效期内的运价明细（`effective_date <= billing_date <= expiry_date`）
- 在同级别匹配中，优先取明确运价（`price_type = 0`），相同类型则取最近创建的一条
- 整单价格（`billing_mode = 2`）的运价条目品牌/车型必须为空，自然归入"通用匹配"级别
- 三种计费模式的运价共存时，按现有 精确 > 品牌 > 通用 的层级自然分层
- 引擎匹配成功后，内部根据 `billing_mode` 自动计算 `total_amount`，调用方无需再关心计费公式
- 无任何匹配返回 None
- 匹配结果包含 `price_type` 和 `billing_mode` 字段，调用方可据此判断运费来源和计费方式

#### 3.3.4 批量计费

`BillingEngineService.batch_calculate()` 支持批量运单的运费计算（如 Excel 导入场景），内部优化查询次数。

## 八、测试要点

1. 新增合同：填写合同编号、选择客户、设置日期，验证数据正确写入
2. 合同编号唯一性校验
3. 合同状态流转：草稿 → 生效 → 过期/终止
4. 运价明细 CRUD：在合同详情中添加/编辑/删除运价
5. 计费引擎匹配测试：
   - 精确匹配（客户+出发地+目的地+品牌+车型）
   - 品牌匹配（客户+出发地+目的地+品牌）
   - 通用匹配（客户+出发地+目的地）
   - 无匹配返回 None
6. 运价类型优先级测试：
   - 同级别同时存在明确运价和预估运价时，匹配结果应为明确运价
   - 同级别仅有预估运价时，匹配结果为预估运价且 `priceType = 1`
   - 不同级别不受运价类型影响，仍按精确>品牌>通用优先
7. 合同过期后不参与匹配
8. 计费 API 预览：前端调用计费接口实时展示运费，包含运价类型信息

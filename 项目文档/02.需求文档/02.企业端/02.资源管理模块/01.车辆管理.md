# 企业端资源模块 - 车辆管理

> **所属阶段**：阶段四 - 企业端资源模块
>
> **文档状态**：已完成
>
> **优先级**：高（资源模块核心基础）

## 一、功能概述

车辆管理是物流运力体系的基础模块。对于物流车队来说，一个可用的运力由**司机 + 车辆（+ 挂车）**构成，本模块聚焦车辆与挂车两大实体的全生命周期管理，为后续运单派车、调度排班提供运力数据支撑。

核心设计原则：

- **核心表 + 扩展表分离**：车辆和挂车均采用「核心表只存业务必须字段（车牌号、状态）+ 扩展表存储其他详细属性」的架构，核心表结构稳定、扩展表可按需增列，降低后期字段扩展的迁移成本
- **状态可被外部模块驱动**：车辆状态（正常、维修/保养、保险续期等）由统一的状态变更接口管理，当前版本支持手动修改，后续维修保养模块、车险管理模块可直接调用该接口驱动状态流转，无需改动车辆模块代码
- **挂车为可选关联**：适配「有挂车」和「无挂车」两种车队场景，车辆可选择性地关联一辆挂车

## 二、业务背景

### 核心业务诉求

1. **运力基础数据**：车辆和挂车是物流运力的物理载体，所有业务模块（运单、调度、结算）都需要引用车辆信息，因此车辆管理是业务开展的前置条件
2. **灵活的字段扩展**：不同规模的物流企业对车辆信息的管理精细度不同，小型车队可能只需车牌号和状态，大型车队则需要 GPS 设备、保险信息、年检信息等，采用扩展表模式可以在不影响核心业务的前提下按需扩展
3. **状态驱动的业务联动**：车辆状态直接影响运力可用性，后续模块（维修保养 → 车辆进入「维修中」、保险管理 → 车辆进入「保险续期」）需要统一的状态变更入口

## 三、需求详情

### 3.1 车辆管理

#### 3.1.1 车辆列表

- 分页表格展示，支持排序
- 列表字段：车牌号、车辆类型、品牌/型号、核定载重、关联挂车（显示挂车车牌号）、保险到期、年检到期、状态、操作
- 支持按车牌号/品牌/型号关键字模糊搜索
- 支持按状态筛选（正常、停用、维修中、保险续期、已报废）
- 工具栏：新增车辆、批量删除
- 行操作：编辑、删除

#### 3.1.2 新增/编辑车辆

表单分为**基础信息**（核心表字段）和**详细信息**（扩展表字段）两个区域：

**基础信息（核心表 `biz_vehicle`）**：

| 字段 | 说明 | 规则 |
|------|------|------|
| 车牌号 | 车辆唯一标识 | 必填，租户内唯一，格式校验（如：京A12345） |
| 关联挂车 | 关联的挂车 | 选填，下拉选择（显示挂车车牌号），只能选择未被其他车辆关联的挂车 |
| 状态 | 车辆当前状态 | 新增时默认「正常」，编辑时可手动切换 |

**详细信息（扩展表 `biz_vehicle_ext`）**：

| 字段 | 说明 | 规则 |
|------|------|------|
| 车辆类型 | 如重型货车、轻型货车等 | 选填，建议通过数据字典 `vehicle_type` 管理 |
| 品牌 | 车辆品牌 | 选填 |
| 型号 | 车辆型号 | 选填 |
| 颜色 | 车辆颜色 | 选填 |
| 车架号(VIN) | 车辆识别代号 | 选填 |
| 发动机号 | 发动机编号 | 选填 |
| 核定载重(吨) | 行驶证核定载质量 | 选填，数值，精度 2 位小数 |
| 核定容积(m³) | 车厢容积 | 选填，数值，精度 2 位小数 |
| 购买日期 | 车辆购入时间 | 选填，日期选择 |
| 保险到期日 | 交强险/商业险到期 | 选填，日期选择 |
| 年检到期日 | 年度检验到期 | 选填，日期选择 |
| GPS设备ID | 车载 GPS 终端标识 | 选填 |
| 备注 | 补充说明 | 选填，文本域 |

#### 3.1.3 删除车辆

- 软删除（`is_deleted = 1`），车辆数据不物理删除
- 删除前校验：如车辆已关联正在进行中的运单，则禁止删除并提示
- 删除时自动解除与挂车的关联关系

#### 3.1.4 车辆状态定义

| 状态值 | 状态名称 | 说明 |
|--------|---------|------|
| 1 | 正常 | 车辆可用，可被派单 |
| 0 | 停用 | 车辆人为停用，不可派单 |
| 2 | 维修/保养 | 车辆正在维修或保养中（后期由维修保养模块驱动） |
| 3 | 保险续期 | 车辆保险到期待续（后期由车险管理模块驱动） |
| 9 | 已报废 | 车辆报废，终态 |

#### 3.2.2 新增/编辑挂车

**基础信息（核心表 `biz_trailer`）**：

| 字段 | 说明 | 规则 |
|------|------|------|
| 挂车车牌号 | 挂车唯一标识 | 必填，租户内唯一 |
| 状态 | 挂车当前状态 | 新增时默认「正常」 |

**详细信息（扩展表 `biz_trailer_ext`）**：

| 字段 | 说明 | 规则 |
|------|------|------|
| 挂车类型 | 平板/厢式/罐式/集装箱/侧翻等 | 选填，通过数据字典 `trailer_type` 管理 |

| 车厢宽度(m) | 车厢内部宽度 | 选填，数值，精度 2 位小数 |

| 车位数 | 轿运车的车位数量 | 选填，整数 |

| 备注 | 补充说明 | 选填，文本域 |

#### 3.2.3 删除挂车

- 软删除（`is_deleted = 1`）
- 删除前校验：如挂车已关联车辆，则禁止删除并提示「请先解除与车辆的关联」

### 3.3 车辆-挂车关联

- 在车辆的新增/编辑表单中，通过下拉选择器关联挂车
- **约束**：一辆车最多关联一辆挂车，一辆挂车最多被一辆车关联（1:1 可选关系）
- 下拉选择器只展示**未被其他车辆关联的挂车**（已关联到当前车辆的除外）
- 支持清空选择以解除关联
- 车辆列表中展示已关联的挂车车牌号，挂车列表中展示已关联的车辆车牌号

### 3.4 状态扩展机制（预留设计）

当前版本仅实现手动状态变更，但在架构上为后续模块预留扩展能力：

- 车辆核心表设置 `status_source` 字段，记录最近一次状态变更的来源模块
- 定义统一的状态变更服务方法 `VehicleStatusService.change_status(vehicle_id, new_status, source)`
- 当前版本 `source` 固定为 `manual`（手动操作）
- 后续维修保养模块可调用 `change_status(id, 2, "maintenance")` 将车辆标记为维修中
- 后续车险管理模块可调用 `change_status(id, 3, "insurance")` 将车辆标记为保险续期
- 维修完成或保险续期完成后，对应模块调用 `change_status(id, 1, "maintenance"/"insurance")` 恢复正常

### 6.4 前后端字段适配方案

前端 TypeScript 模型使用小驼峰命名（`plateNumber`、`loadCapacity`），后端 ORM 使用下划线命名（`plate_number`、`load_capacity`）。在**后端 Schema 层的 `from_model()` 方法中做映射转换**，与项目现有模式一致。

创建/更新请求中核心字段与扩展字段合并提交，后端 Service 层负责拆分：
1. 从请求体中提取核心字段，写入 `biz_vehicle` / `biz_trailer`
2. 从请求体中提取扩展字段，写入 `biz_vehicle_ext` / `biz_trailer_ext`
3. 查询响应时 LEFT JOIN 扩展表，合并输出

## 八、测试要点

### 8.1 车辆管理

## 一、模块定位

「AI 数字人模块」是企业端用户与 AI 数字员工对话的工作区，提供**自然语言驱动业务操作**的能力。用户可以与录单员、数据分析员等不同角色的数字员工聊天：让 AI 帮忙查运单 / 车辆 / 客户、上传 Excel 自动批量录入、执行多步骤业务流程，并在涉及高风险动作（批量入库等）前由用户显式确认。

模块由 1 个主入口页面 + 4 张租户库表 + 后端 SSE 流式编排引擎 + 多个内置工具构成。

## 三、三栏布局

```
┌──────────────┬─────────────────────────────────┬──────────────┐
│  左 260px     │            中 1fr               │   右 280px    │
│              │                                 │ (<1200 隐藏)  │
│  ┌─员工列表─┐ │  ┌──────会话主区────────────┐  │  ┌─可用工具─┐ │
│  │ 录单员    │ │  │ 欢迎语 + 建议提问 chip    │  │  │ 工具1   │ │
│  │ 数据分析员 │ │  │                          │  │  │ 工具2   │ │
│  │ ...      │ │  │ 消息气泡 (用户右/AI左)     │  │  │ ...    │ │
│  └─────────┘ │  │   ├─ 文本+附件             │  │  └────────┘ │
│              │  │   └─ 工具时间线             │  │              │
│  ┌─历史会话─┐ │  │      (tool.call/result)   │  │              │
│  │ 会话1    │ │  │                          │  │              │
│  │ 会话2    │ │  ├──────输入栏──────────────┤  │              │
│  │ ...      │ │  │ 文本输入 + 附件 + 发送/中止│  │              │
│  └─────────┘ │  └──────────────────────────┘  │              │
└──────────────┴─────────────────────────────────┴──────────────┘
```

- **左栏**：上半屏数字员工列表（横向滚动 chip 形式或列表），下半屏当前员工的历史会话列表（含「新建」「重命名」「删除」）。
- **中栏**：会话主区，自上而下=空状态欢迎卡片 + 消息流 + 输入栏。
- **右栏**：当前选中员工的可用工具列表（只读展示，含名称 / 描述 / 风险标签）；视口宽度 < 1200px 自动隐藏。

详细组件契约见 [01.数字员工对话页.md](01.数字员工对话页.md)。

## 四、整体调用时序

```mermaid
sequenceDiagram
    autonumber
    participant U as 用户
    participant FE as 客户端 (Vue)
    participant API as 客户端 API
    participant ORC as Orchestrator
    participant LLM as LLM Provider
    participant TOOL as 工具 (registry)
    participant DB as 租户库

    U->>FE: 输入消息 + (可选)附件
    FE->>API: POST /api/client/ai/chat (SSE)
    API->>ORC: run(session, user_msg, attachments)
    ORC->>DB: 写 user message + 推 message 事件
    ORC->>LLM: chat_stream(messages, tools)
    LLM-->>ORC: delta(文本) ×N
    ORC-->>FE: SSE delta(文本) ×N
    FE-->>U: 打字机平滑层吐字

    LLM-->>ORC: tool_call_done(tool_calls)
    ORC->>ORC: PermissionGuard.check
    alt 普通工具
        ORC-->>FE: tool.call
        ORC->>TOOL: handler(ctx, params)
        TOOL-->>ORC: ToolResult
        ORC->>DB: 写 tool message + tool_call_log
        ORC-->>FE: tool.result
        ORC->>LLM: 续跑下一轮 (含 tool 消息)
        LLM-->>ORC: delta(总结) ...
        ORC-->>FE: delta + done
    else 高风险工具
        ORC->>DB: 写 pending_confirm 日志 (含 confirm_token)
        ORC-->>FE: confirm.required + done(finish_reason=confirm_required)
        U->>FE: 点确认/取消
        FE->>API: POST /chat/confirm (sessionId, confirmToken, approved)
        API->>ORC: resume_after_confirm
        ORC->>TOOL: 执行 (approved=true) or 写 cancelled (false)
        ORC-->>FE: tool.result + 续跑 LLM + done
    end

    ORC-->>FE: usage (prompt/completion tokens)
    FE-->>U: 渲染最终消息
```

## 六、产品功能与表自愈

### 6.1 产品功能开关

`sys_product_feature` 中：

| feature_code | 名称 | required_tables | 默认开通版本 |
|--------------|------|-----------------|--------------|
| `ai_assistant` | AI 数字员工 | `["biz_ai_session", "biz_ai_message", "biz_ai_tool_call_log", "biz_ai_context"]` | `enterprise` |

只有开通了 `ai_assistant` 的租户：

- 客户端菜单 `dashboard:ai-assistant` 可见。
- `/api/client/ai/employee`、`/api/client/ai/session`、`/api/client/ai/chat` 可用。
- 运营端「调用观测」中能查到该租户。

### 6.2 租户表首访自愈

后端 `app.core.dependencies.ensure_biz_ai_tables` 依赖项：

- 进程内缓存 `_ai_checked_tenants`，每个租户 code 只检查一次。
- 用 SQLAlchemy `MetaData.create_all` 按需创建 4 张 `biz_ai_*` 表（已存在不重复创建）。
- 仅挂在 `chat` / `session` 路由组（`employee` / `file` 不读业务表）。

老租户（在 `ai_assistant` 上线前已开通 `enterprise`）由 `backend/scripts/fix/fix_ai_tenant_tables.py` 一次性批量补建。

## 八、SSE 9 类事件速查

完整字段定义见 [01.数字员工对话页.md](01.数字员工对话页.md) §3。这里只列名字与触发时机：

| 事件 | 触发时机 |
|------|---------|
| `session` | 会话建立或识别 |
| `message` | 用户消息落库 |
| `delta` | LLM 文本增量 |
| `tool.call` | 工具开始调用 |
| `tool.result` | 工具执行完成（含 success/failed/denied/cancelled） |
| `confirm.required` | 高风险工具待用户确认 |
| `usage` | LLM 用量回报 |
| `done` | 一轮对话完成 |
| `error` | 异常 |

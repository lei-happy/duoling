# 企业端基础模块 - 组织架构与权限

> **所属阶段**：阶段三 - 企业端基础模块
>
> **文档状态**：已完成
>
> **优先级**：高（企业端核心基础）

## 一、功能概述

企业端基础模块是整个客户端产品的基石，实现「组织架构管理 → 员工管理 → 角色管理」三大核心功能，并建立基于 RBAC（基于角色的访问控制）的权限体系。

核心设计原则：

- **组织架构**：支持无限层级的树形结构，满足总部、分公司、事业部、部门、小组等多种组织形态
- **员工管理**：以基础字段为核心，预留扩展能力，支持与部门和角色的灵活关联
- **角色权限**：RBAC 模型，一个用户可关联多个角色，角色关联菜单权限；菜单由运营后台（Console）统一配置并按产品版本下发，客户端不做菜单管理

## 二、业务背景

系统采用 SaaS 多租户架构，每个企业（租户）拥有独立的业务数据库（`zt_biz_{tenant_code}`）。企业内部的组织架构、员工、角色等数据均存储在各自的租户库中，实现数据隔离。

### 核心业务诉求

1. **多级组织架构**：不同企业的组织形态差异大，需要灵活的树形结构来支撑总部-分公司-部门等多种层级
2. **RBAC 权限控制**：通过角色聚合权限，用户关联角色来获得权限，降低权限管理复杂度
3. **菜单由平台下发**：客户端的功能菜单由运营后台（Console）定义和管理（`sys_menu` 中 `app_type=client`），根据租户开通的产品版本过滤菜单后同步至租户库 `biz_menu`，企业管理员只需将菜单分配给角色即可

### 权限流转全链路

```
Console 运营后台                              Client 客户端
─────────────────                            ────────────────

1. 定义客户端菜单                    ┌──→  4. 企业管理员创建角色
   (sys_menu, app_type=client)       │       (biz_role)
        │                            │            │
2. 配置产品版本包含的功能             │     5. 为角色分配菜单权限
   (sys_version_feature)              │       (biz_role_menu ← biz_menu)
        │                            │            │
3. 为租户开通版本授权                 │     6. 创建员工并关联角色
   (sys_tenant_product)               │       (biz_user + biz_user_role)
        │                            │            │
   授权时同步菜单到租户库 ────────────┘     7. 员工登录，按角色返回可见菜单
   (biz_menu)                                (GET /auth/user-info)
```

## 三、需求详情

### 3.1 组织架构管理

管理企业的组织架构（`biz_department`），以树形结构展现，支持无限层级嵌套。

#### 3.1.1 组织节点层级说明

通过部门类型（`dept_type`）区分不同层级的组织节点，类型通过数据字典 `org_type` 管理：

| 字典项值 | 字典项名称 | 说明 |
|----------|-----------|------|
| company | 公司 | 集团/总公司级别 |
| branch | 分公司 | 分公司/子公司 |
| division | 事业部 | 事业部/业务单元 |
| department | 部门 | 职能部门 |
| group | 小组 | 最小组织单元 |

运营人员可在数据字典中扩展更多类型，无需修改代码。

#### 3.1.2 组织架构列表

- 树形表格展示，支持展开/折叠全部
- 列表字段：部门名称、部门编码、部门类型、负责人、联系电话、排序号、状态、创建时间
- 支持按部门名称关键字筛选
- 支持新增、新增下级、编辑、删除操作

#### 3.1.3 新增/编辑部门

| 字段 | 说明 | 规则 |
|------|------|------|
| 上级部门 | 所属上级节点 | 下拉树选择，顶级部门的上级为 0 |
| 部门名称 | 组织节点名称 | 必填，同级下唯一 |
| 部门编码 | 部门唯一编码 | 选填，便于外部系统集成 |
| 部门类型 | 组织类型 | 从数据字典 `org_type` 加载选项 |
| 负责人 | 部门负责人 | 选填，文本输入 |
| 联系电话 | 部门联系电话 | 选填 |
| 排序号 | 同级内排序 | 默认 0，数值越小越靠前 |
| 状态 | 正常/停用 | 默认正常 |
| 备注 | 补充说明 | 选填 |

#### 3.1.4 删除校验规则

- 存在子部门时禁止删除，提示「请先删除子节点」
- 存在关联员工时禁止删除，提示「该部门下存在员工，无法删除」

### 3.2 员工管理

管理企业内部的员工（`biz_user`），支持与部门的外键关联和多角色绑定。

#### 3.2.1 基础字段设计

以核心字段为主，支持后期通过新增字段扩展：

| 字段 | 说明 | 规则 |
|------|------|------|
| 用户名 | 登录账号 | 必填，租户内唯一 |
| 密码 | 登录密码 | 新增时可设置，默认 `123456` |
| 姓名 | 员工真实姓名 | 必填 |
| 昵称 | 显示昵称 | 选填，未填时用姓名代替 |
| 手机号 | 联系电话 | 选填 |
| 邮箱 | 电子邮箱 | 选填 |
| 性别 | 0-未知 1-男 2-女 | 默认未知 |
| 头像 | 头像图片 URL | 选填 |
| 所属部门 | 关联部门 | 下拉树选择，关联 `biz_department` |
| 用户类型 | 1-管理员 2-普通员工 3-驾驶员 | 默认普通员工 |
| 角色 | 关联角色列表 | 多选，关联 `biz_role` |
| 状态 | 0-正常 1-停用 | 默认正常 |
| 备注 | 补充说明 | 选填 |

**扩展字段预留**（后期按需新增，当前不实现）：
- 职位（`position`）
- 工号（`employee_no`）
- 入职日期（`entry_date`）
- 紧急联系人（`emergency_contact`）

#### 3.2.2 员工列表

- **左侧**：组织架构树（可搜索、可折叠面板），点击节点筛选右侧列表
- **右侧**：员工分页表格
- 列表字段：用户账号、姓名、性别、角色（标签组）、创建时间、状态（开关）、操作
- 操作项：编辑、更多（重置密码、删除）
- 工具栏：新增、批量删除、导入
- 支持按用户名/姓名/手机号关键字搜索、按状态筛选

#### 3.2.3 新增/编辑员工

- 弹窗表单，字段见 3.2.1
- 新增时必须设置用户名，用户名在租户内唯一校验
- 编辑时用户名不可修改
- 部门通过树形下拉选择
- 角色通过多选下拉选择

#### 3.2.4 其他操作

- **重置密码**：弹窗输入新密码（5-18 位非空白字符），默认 `123456`
- **修改状态**：列表行内开关直接切换
- **批量删除**：多选后批量删除，管理员账号不可删除
- **导入员工**：Excel 文件导入

#### 3.2.5 员工详情

- 独立页面（路由 `/system/user/details/:id`），展示完整用户信息
- 包含基本信息、角色信息、操作日志等 Tab

### 3.3 角色管理

管理企业的角色（`biz_role`），实现 RBAC 中的角色层。

#### 3.3.1 角色列表

- 分页表格展示
- 列表字段：角色名称、角色标识、备注、创建时间、操作
- 操作项：编辑、分配权限、删除
- 工具栏：新增、批量删除
- 支持按角色名称、角色标识关键字搜索

#### 3.3.2 新增/编辑角色

| 字段 | 说明 | 规则 |
|------|------|------|
| 角色标识 | 角色编码（如 `admin`、`operator`） | 必填，租户内唯一，编辑时不可修改 |
| 角色名称 | 角色显示名（如「管理员」「操作员」） | 必填 |
| 排序号 | 角色列表排序 | 默认 0 |
| 备注 | 角色说明 | 选填 |

#### 3.3.3 分配权限

- 弹窗展示菜单权限树（数据来源 `biz_menu`）
- 树形勾选，支持全选/反选
- 保存时全量替换角色-菜单关联（`biz_role_menu`）
- 重新打开时回显已分配的菜单

#### 3.3.4 内置角色保护

- 角色标识为 `admin` 的内置管理员角色不可删除
- 管理员角色默认拥有本租户所有可用菜单权限

### 3.4 权限机制说明

本节说明客户端权限体系的完整运作机制，非独立功能模块。

#### 3.4.1 菜单来源

客户端不提供菜单管理功能。菜单的完整生命周期如下：

1. **Console 定义菜单**：运营后台在「客户端菜单管理」中维护所有客户端菜单（`sys_menu`，`app_type=client`），每个菜单关联 `feature_code`
2. **版本关联功能**：在产品版本管理中，配置各版本包含的功能模块（`sys_version_feature`）
3. **租户开通版本**：为租户授权产品版本后，系统根据版本关联的 `feature_code` 集合，将对应菜单同步至租户库 `biz_menu`
4. **角色分配菜单**：企业管理员在角色管理中，从 `biz_menu` 中选择菜单分配给角色

#### 3.4.2 登录权限加载

员工登录后，客户端调用 `GET /api/client/auth/user-info`，后端根据以下逻辑返回数据：

1. 查询用户关联的角色列表（`biz_user_role` → `biz_role`）
2. 汇总所有角色关联的菜单 ID（`biz_role_menu`）
3. 从 `biz_menu` 中查询这些菜单的完整信息
4. 管理员用户（`user_type=1`）返回租户全部可用菜单
5. 前端根据返回的菜单动态生成路由和侧边栏

#### 3.4.3 权限粒度

| 粒度 | 实现方式 | 说明 |
|------|---------|------|
| 菜单级 | `biz_menu.menu_type=0/1`（目录/菜单） | 控制侧边栏菜单可见性和路由访问 |
| 按钮级 | `biz_menu.menu_type=2`（按钮），`menu_code` 为权限标识 | 前端通过 `v-permission` 指令或 `authorities` 数组控制按钮显隐 |

## 六、前端页面设计

### 6.1 组织架构管理页

- **组件**：`views/system/organization/index.vue`
- **子组件**：

  - `organization-edit.vue`：新增/编辑弹窗
  - `organization-select.vue`：部门树选择器（被用户管理等模块复用）

- 树形表格，`row-key` 为 `organizationId`，默认展开全部

- 删除时如有子节点，前端先拦截提示

### 6.2 员工管理页

- **路由**：`/system/user`

**页面交互**：

### 6.5 前后端字段适配方案

由于前端 TypeScript 模型（参考 Console 端代码风格）使用 `organizationId`、`organizationName` 等命名，而后端 ORM 使用 `dept_name`、`dept_code` 等，需要在**后端 Schema 层做映射转换**，确保 API 响应字段与前端模型一致。

具体做法：修改 `backend/app/modules/client/schemas/department.py` 中的 `DepartmentOut.from_model()` 方法，将后端字段映射为前端期望的字段名（详见第五章字段映射表）。

## 七、测试要点

### 7.1 组织架构

1. 创建多级部门（至少 4 级），验证树形结构正确展示
2. 编辑部门名称/类型/排序后，列表数据正确刷新
3. 删除有子部门的节点，验证拦截提示
4. 删除有关联员工的部门，验证拦截提示
5. 停用部门后，该部门下的员工功能不受影响（仅影响部门自身展示）

### 7.2 员工管理

1. 创建员工并关联部门和多个角色，验证关联关系正确
2. 用户名唯一性校验：同一租户内不可重复
3. 左侧切换组织树节点，右侧列表按部门正确筛选（含子部门下的员工）
4. 批量删除员工，管理员账号不可删除
5. 重置密码后使用新密码登录验证
6. 修改状态为停用后，该员工无法登录
7. Excel 导入员工数据，验证去重和格式校验

### 7.3 角色管理

1. 创建角色，角色编码唯一性校验
2. 分配权限后，使用该角色的员工登录，验证菜单可见性符合预期
3. 修改角色权限后，该角色下的员工重新登录后菜单更新
4. 管理员角色（`admin`）不可删除
5. 删除角色后，关联该角色的用户权限自动调整

### 7.4 权限链路

1. Console 新增客户端菜单 → 为版本配置功能 → 租户 `biz_menu` 同步验证
2. 创建角色 A 分配菜单 [M1, M2] → 用户 U1 关联角色 A → U1 登录只能看到 M1、M2
3. 用户 U2 关联角色 A + 角色 B → U2 登录看到两个角色菜单的并集
4. 管理员用户登录，验证能看到全部可用菜单
5. 按钮权限验证：菜单页面内的操作按钮根据 `authority` 标识正确显隐

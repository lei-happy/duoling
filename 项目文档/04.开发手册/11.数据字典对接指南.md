# 数据字典对接指南

> 适用于 **企业客户端**（`frontend/client`）及租户端业务模块：将「可由租户自定义名称/取值」的选项接入系统数据字典，与代码内写死的业务枚举区分使用。

---

## 1. 何时用数据字典，何时不用

| 场景 | 建议 |
|------|------|
| 租户希望自行维护选项名称与取值（如车辆类型、自定义标签） | 使用数据字典 |
| 与业务流程强绑定、状态机、权限相关的固定值（如运单状态、审核状态） | **不要**放入数据字典，应在业务代码或常量中维护 |
| 全系统统一、极少变更的枚举 | 优先常量或后端枚举，避免过度字典化 |

---

## 2. 字典由谁维护

| 角色 | 职责 |
|------|------|
| **开发者** | 在 `backend/scripts/seed/seed_client_dicts.py` 的 `DICT_DEFS` 中定义字典及默认选项。部署时自动初始化到所有租户。 |
| **租户用户** | 在客户端「系统管理 → 数据字典」中，对已有字典**增删改选项**，不可新增/删除字典本身。 |

### 新模块上线检查

1. 在 `DICT_DEFS` 中新增字典定义（dict_code、名称、默认项）。
2. 在 `frontend/client/src/constants/dict-codes.ts` 中增加对应常量。
3. 运行 `bash deploy.sh db-sync`（或开发环境重跑 `init_dev_env.py`），自动同步到所有租户。

---

## 3. 字典编码常量

在客户端为每个业务场景定义 **字典编码常量**，避免魔法字符串散落。

推荐位置：`frontend/client/src/constants/dict-codes.ts`

```ts
/** 须在「数据字典」中创建同名字典 */
export const DICT_CODE_VEHICLE_TYPE = 'vehicle_type';
```

新模块需要新字典时：在此文件增加常量，并在 `seed_client_dicts.py` 的 `DICT_DEFS` 中新增定义。

## 4. 前端集成步骤

### 4.1 拉取字典数据

使用 `useDictData`（内部会请求 `/system/dictionary-data` 并写入 Pinia 缓存）：

```ts
import { useDictData } from '@/utils/use-dict-data';
import { DICT_CODE_VEHICLE_TYPE } from '@/constants/dict-codes';

const [vehicleTypeDict] = useDictData([DICT_CODE_VEHICLE_TYPE]);
```

在模板中与 `FloatingLabel` 的 `select` 搭配：

```vue
<floating-label v-model="form.vehicleType" label="请选择车辆类型" type="select" clearable>
  <el-option
    v-for="item in vehicleTypeDict"
    :key="item.dictDataCode"
    :label="item.dictDataName"
    :value="item.dictDataCode"
  />
</floating-label>
```

表单字段（如 `vehicleType`）绑定值为 **字典数据值**（`dictDataCode`），与后端实体字段类型一致（一般为 `string`）。

### 4.1.1 字典下拉的引导提示（推荐）

凡由 **`useDictData` + `FloatingLabel`（type=`select`）** 承载字典选项的表单或搜索条件，建议在控件右侧增加统一提示，引导用户到「系统管理 → 数据字典」自行维护选项，避免误以为选项只能找管理员改代码。

使用封装组件 **`DictSelectHintWrap`**（`dictName` 与数据字典左侧字典名称一致）：

```vue
import DictSelectHintWrap from '@/components/DictSelectHintWrap/index.vue';

<dict-select-hint-wrap dict-name="车辆类型">
  <floating-label v-model="form.vehicleType" label="请选择车辆类型" type="select" clearable>
    <el-option
      v-for="item in vehicleTypeDict"
      :key="item.dictDataCode"
      :label="item.dictDataName"
      :value="item.dictDataCode"
    />
  </floating-label>
</dict-select-hint-wrap>
```

说明：

- **`dict-name`**：须与租户「数据字典」里该字典的展示名称一致（如「性别」「机构类型」「车辆类型」「挂车类型」），提示文案中会引用该名称。
- 若使用 **`DictData`** 的 `type="select"` 作为筛选项，同样需要时可在外层套同一组件或沿用相同文案与图标样式。
- 业务里 **写死的 `el-option`**（非字典驱动）不需要套此组件。

### 4.2 列表/详情展示字典名称

使用 `DictData` 组件，将存库值映射为字典项名称展示：

```vue
<dict-data
  type="text"
  :code="dictCodeVehicleType"
  :model-value="row.vehicleType"
/>
```

`type` 还可为 `tag`、`select` 等，见 `frontend/client/src/components/DictData/index.vue`。

### 4.3 与现有模块对齐

可参考（均已用 `DictSelectHintWrap` 包裹字典下拉）：

- 表单 + 下拉：`views/system/organization/components/organization-edit.vue`（机构类型 `organization_type`）
- 员工表单性别：`views/system/user/components/user-edit.vue`（`sex`）
- 自有运力车辆 / 挂车：`views/capacity/self_capacity/vehicle/components/vehicle-edit.vue`、`trailer-edit.vue`
- 表格展示：`views/system/organization/index.vue`（`#organizationType` 插槽）
- 字典驱动筛选项：`views/system/user/components/user-search.vue`、`organization-search.vue`、`views/capacity/self_capacity/vehicle/components/vehicle-search.vue`、`trailer-search.vue`

## 5. 示例：车辆类型 `vehicle_type`

| 项目 | 说明 |
|------|------|
| 字典编码 | `vehicle_type`（常量 `DICT_CODE_VEHICLE_TYPE`） |
| 表单 | `views/resource/vehicle/components/vehicle-edit.vue` |
| 列表展示 | `views/resource/vehicle/index.vue` 中 `#vehicleType` |
| 搜索 | `views/resource/vehicle/components/vehicle-search.vue` |

后端若支持按类型筛选（如 `vehicleType` 查询参数），搜索条件传 **字典数据值**（`dictDataCode`）即可。

### 挂车类型 `trailer_type`

| 项目 | 说明 |
|------|------|
| 字典编码 | `trailer_type`（常量 `DICT_CODE_TRAILER_TYPE`） |
| 表单 | `views/capacity/self_capacity/trailer/components/trailer-edit.vue` |
| 列表展示 | `views/capacity/self_capacity/trailer/index.vue` 中 `#trailerType` |
| 搜索 | `views/capacity/self_capacity/trailer/components/trailer-search.vue` |

挂车类型与「车辆类型」中的「挂车」不同：前者表示挂车子类（平板、骨架等），租户在「数据字典」中自行维护选项。

## 6. 联调检查清单

- [ ] `seed_client_dicts.py` 的 `DICT_DEFS` 已新增字典定义，且 **dictCode** 与前端常量一致。
- [ ] 已维护至少一条字典数据（默认项），否则下拉为空。
- [ ] 列表/详情使用 `DictData` 或 `useDictData` 展示，避免只显示原始 code。
- [ ] 表单/搜索里字典驱动的 **`FloatingLabel` 下拉** 已用 `DictSelectHintWrap`（或等价交互）提示用户可到数据字典维护选项。
- [ ] 未将业务状态机枚举误放入字典（见第 1 节）。
- [ ] 执行 `bash deploy.sh db-sync` 或开发环境重跑 `init_dev_env.py`，确认字典已同步到租户库。

# 文件上传与静态资源服务

> **适用范围**：客户端（及未来其他端）需要上传图片并在页面展示的场景，例如用户头像、运单照片、车辆/证件图等。  
> **设计原则**：文件按**业务场景**分子目录落盘；**数据库只存相对访问路径**（如 `/uploads/waybill/xxx.png`），不存绝对 URL。

## 1. 整体架构

```
┌─────────────┐     POST /api/client/file/upload      ┌─────────────┐
│  浏览器/前端 │ ────────────────────────────────────► │   FastAPI   │
│  (multipart)│                                       │  校验+写盘   │
└─────────────┘                                       └──────┬──────┘
       │                                                       │
       │  返回 data.url = "/uploads/{scene}/{uuid}.ext"        │
       │                                                       ▼
       │                                               backend/uploads/
       │                                               ├── avatar/
       │                                               ├── waybill/
       │                                               └── ...
       │
       │  GET https://同域/uploads/...  （或经网关反代）
       ▼
┌─────────────┐
│  业务表字段  │  varchar 存相对路径，如 /uploads/waybill/abc.png
└─────────────┘
```

| 环节 | 说明 |
|------|------|
| 上传入口 | 需登录；`Content-Type: multipart/form-data`，字段 `file` + 可选 `scene` |
| 存储位置 | 仓库/容器内 `backend/uploads/{scene}/`，文件名 `UUID + 原扩展名` |
| 对外访问 | 应用根路径挂载静态目录 **`/uploads`**，与 **`/api/client`** 前缀独立 |
| 库表字段 | 建议注释为「相对路径」；与 `biz_user.avatar` 一致 |

## 2. 后端

### 2.1 接口说明

| 项目 | 内容 |
|------|------|
| 方法路径 | `POST /api/client/file/upload` |
| 鉴权 | Bearer Token（与客户端其他接口相同） |
| 表单字段 | `file`：文件；`scene`：场景标识，默认 `avatar` |
| 成功响应 | `{ "code": 0, "data": { "url": "/uploads/{scene}/{文件名}", "name": "原始文件名" } }` |

### 2.2 代码位置

| 文件 | 职责 |
|------|------|
| `backend/app/modules/client/api/file.py` | 上传逻辑、`ALLOWED_SCENES`、扩展名与大小校验 |
| `backend/app/modules/client/api/__init__.py` | 路由前缀 `/file` |
| `backend/app/main.py` | `StaticFiles` 挂载目录 `/uploads` → `backend/uploads` |

### 2.3 当前约定

| 配置项 | 当前值 |
|--------|--------|
| 允许的图片扩展名 | `.jpg` `.jpeg` `.png` `.gif` `.webp` `.bmp` |
| 单文件大小上限 | 5MB |
| 已注册场景 `scene` | `avatar`（用户头像）、`waybill`（运单）、`vehicle`（车辆）、`document`（通用文档图）、`brand_logo`（运营后台品牌 Logo）、`car_series`（运营后台车系图） |

**新增业务场景时**：在 `file.py` 的 `ALLOWED_SCENES` 中增加小写英文标识，与目录名一致即可（见 [5. 新模块接入步骤](#5-新模块接入步骤)）。

### 2.4 管理后台（Console）

管理后台已挂载 **`POST /api/console/file/upload`**，与客户端相同：表单字段 `file` + `scene`，返回 `data.url` 相对路径。实现复用 `backend/app/common/local_image_upload.py` 中的 `save_scene_image`。

## 3. 前端（客户端）

### 3.1 上传 API

文件：`frontend/client/src/api/system/file/index.ts`

```ts
import { uploadFile } from '@/api/system/file';

// 第四个参数为 scene，与后端 ALLOWED_SCENES 一致
const { url, name } = await uploadFile(file, undefined, file.name, 'waybill');
// url 示例: "/uploads/waybill/xxxxxxxx.png"
```

- 请求走统一 `axios` 实例，`baseURL` 为 `VITE_API_URL`（如 `/api/client`），故实际请求为 **`POST /api/client/file/upload`**。

### 3.2 展示地址（重要）

接口返回的 `url` 为**站点根相对路径**（`/uploads/...`）。浏览器会请求**当前页面所在域名**下的该路径，因此：

- **开发**：`vite.config.ts` 需将 `/uploads` 代理到后端（与 `/api/open` 同源），否则头像等资源 404。  
- **生产**：Nginx 站点（如 `wuliu.zhitu.me`）需增加 `location /uploads/` 反代到后端，见 `deploy/nginx/client.conf`。  
- **特殊部署**：若前端域名与静态资源域名不一致且无法同域反代，可在构建环境配置 **`VITE_UPLOAD_BASE_URL`**（后端根地址，无尾斜杠），工具函数会把 `/uploads/...` 拼成绝对 URL。

工具函数：`frontend/client/src/utils/upload-url.ts` 中的 **`resolveUploadUrl`**。

**用户信息里的头像**：在 `frontend/client/src/store/modules/user.ts` 的 `setInfo` 中已对 `avatar` 调用 `resolveUploadUrl`，顶栏、个人中心等依赖 store 的场景一般无需再处理。  
**列表/详情中的图片字段**：从接口拿到相对路径后，在绑定 `:src` 前使用 `resolveUploadUrl(path)`。

### 3.3 可选组件

项目内另有 `CommonUpload` / `ImageUpload` 等封装，底层可接 `uploadFile`；新页面优先复用现有组件，并传入正确的 `scene`。

### 3.4 参考实现：个人中心头像

`frontend/client/src/views/user/profile/components/user-card.vue`：裁剪得到 base64 → 转 `File` → `uploadFile(..., 'avatar')` → 将返回的 `url` 写入用户资料接口（如 `PUT /auth/user` 的 `avatar` 字段）。

## 4. 运行与部署

### 4.1 本地开发（客户端）

| 配置 | 说明 |
|------|------|
| `frontend/client/.env` | `VITE_API_PROXY_URL` 指向后端时，Vite 会代理 `/api/client`、**`/api/open`**、**`/uploads`** 到同一后端主机 |
| 可选 | `VITE_UPLOAD_BASE_URL`：见 `upload-url.ts` 注释 |

修改 `vite.config.ts` 后需重启前端 dev 服务。

### 4.2 生产环境（Docker + Nginx）

| 配置 | 说明 |
|------|------|
| `deploy/nginx/client.conf` | `location /uploads/` → `http://backend:8000/uploads/` |
| `deploy/nginx/console.conf` | 同上，便于控制台同域访问上传资源 |
| `deploy/nginx/api.conf` | 全站反代到后端，已包含 `/uploads`，一般无需额外段落 |

更新 Nginx 配置后需重新构建/重载 Nginx 容器（如 `bash deploy.sh update`）。

### 4.3 磁盘与持久化

默认上传目录在容器内随镜像/容器生命周期变化。**生产环境**若需持久化，应在 `docker-compose` 中为 `backend` 服务挂载卷到 `uploads` 对应路径（按你们运维规范配置），避免容器重建丢文件。

## 5. 新模块接入步骤

按顺序检查即可完成接入。

1. **定场景名**  
   与产品/后端约定英文小写标识，例如 `order_attachment`、`driver_license`。

2. **后端**  
   在 `backend/app/modules/client/api/file.py` 的 `ALLOWED_SCENES` 中加入该标识。

3. **数据库**  
   业务表增加或沿用 `varchar` 字段存储**相对路径**（如 `image_url`），长度建议 ≥ 255，注释标明「相对路径，如 /uploads/scene/xxx.png」。

4. **业务接口**  
   保存记录时写入上传接口返回的 `data.url`，不要拼死域名。

5. **前端**  
   - 上传：`uploadFile(file, …, scene)`。  
   - 展示：`resolveUploadUrl(字段值)` 或确保用户态数据经 store 已解析。  
   - 列表缩略图、预览组件同样使用解析后的 URL。

6. **联调**  
   本地确认 `/uploads/...` 能直连打开图片；线上确认域名下 `/uploads/...` 未被 SPA 的 `try_files` 吃掉（Nginx 已配置 `/uploads/` 反代）。

## 6. 注意事项

| 类别 | 说明 |
|------|------|
| 安全 | 上传接口需登录；已限制扩展名与大小。后续若开放非图片类型需单独评审。 |
| 旧文件 | 当前实现**不**自动删除被替换的文件；若需清理可后续加定时任务或替换时删旧路径。 |
| 跨域 | 小程序/App 若直接请求上传接口，需按平台配置合法域名与 HTTPS。 |
| 与对象存储 | 若未来切换 OSS/COS，可保持库表仍存「路径或 key」，仅改上传实现与 `resolveUploadUrl` 解析规则。 |

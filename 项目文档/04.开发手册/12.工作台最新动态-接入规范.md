# 最新动态（企业协作）— 事件接入规范

## 1. 模块定位

- **功能**：在同一租户内展示「对大家协作有意义」的业务动作摘要，帮助成员了解彼此在系统内的关键操作。
- **数据表**：租户库 `biz_company_activity`（与平台/模块审计日志分工不同）。
- **展示**：客户端工作台「最新动态」卡片仅展示 **当日**（按 **Asia/Shanghai** 日历日）记录，按时间倒序。

### 与下列能力的区别

| 能力 | 说明 |
|------|------|
| `biz_operation_log` | 接口级操作审计，字段偏技术与合规 |
| `biz_capacity_log` | 运力模块变动明细，偏业务单据追溯 |
| **最新动态** | 面向人的一句话摘要，跨模块聚合，频率可控 |

## 2. 纳入 / 不纳入原则

### 建议纳入

- 动作结果会被其他角色感知并可能影响下一步协作（如：创建运单、运力上下车、审批通过/驳回）。
- 频率可控，不会在正常工作流下刷屏。
- 文案可脱敏后安全展示（不出现密码、完整身份证号等）。

### 建议不纳入

- 纯查询、列表浏览、导出下载（除非产品明确要求）。
- 登录/登出、Token 刷新。
- 失败重试、草稿自动保存等技术噪声。
- 与协作无关的琐碎配置修改（除非版本升级另有约定）。

具体事件是否纳入以产品评审为准；新增类型时在本文档「事件清单」中登记。

## 3. `event_code` 命名约定

- 格式：`域.模块.动作`，全小写，分段用英文句点。
- 示例：
  - `capacity.self_bind` — 自有运力上车（司机-车辆绑定）
  - `capacity.self_unbind` — 自有运力下车（解绑）
  - `partner.customer_created` — 合作伙伴-新建客户
  - `partner.customer_updated` — 合作伙伴-编辑客户
  - `partner.customer_deleted` — 合作伙伴-删除客户
  - `waybill.created` — 运单创建
  - `waybill.updated` — 运单编辑
  - `waybill.status_changed` — 运单状态变更
  - `waybill.deleted` — 运单删除

同一 `event_code` 的展示句式应保持稳定，避免前端或报表难以对齐。

### 客户名称脱敏（摘要文案）

- **摘要（`summary`）中禁止出现客户全称**，须使用 `app.common.mask_display.mask_organization_name` 生成展示片段后再拼进句式。
- 规则要点：
  - 名称 **≥4 字**：**第 1 字** + 固定 `***` + **最后 2 字**（如「小***公司」）；
  - 名称 **<4 字**：仅保留第 1 字，其余字符全部为 `*`（单字名只显示该字）。
- **`payload` 中勿写入客户全称**，仅需业务主键等（如 `customer_id`），避免库表导出时二次泄露。

## 4. 接入步骤（后端）

1. 在业务事务 **提交成功路径** 内调用 `CompanyActivityService.record`（与主业务同一数据库会话，失败则整体回滚）。
2. 传入字段：
   - `occurred_at`：事件发生时间（通常与业务日志时间一致）。
   - `event_code`：见上节。
   - `summary`：**完整可读的中文一句话**，可直接展示在时间轴上。
   - `actor_user_id` / `actor_display_name`：操作人（系统任务可空）。
   - `payload`（可选）：JSON，存放结构化 ID、单号、车牌等，便于后续扩展跳转或统计。

3. 确保路由层已触发租户表存在性检查：工作台列表使用 `ensure_biz_company_activity_table`；运力上下车在绑定接口上已挂载同一依赖，避免旧租户库缺表。

4. **禁止** 由前端随意 POST 伪造动态；开发环境如需演示数据，仅可使用 `POST /api/client/workbench/activities/demo-seed`（且 `APP_ENV=development` 时可用）。

## 5. `payload` 约定示例（运力）

| event_code | 建议 payload 字段 |
|------------|-------------------|
| `capacity.self_bind` | `capacity_id`, `driver_id`, `vehicle_id`, `plate_number` |
| `capacity.self_unbind` | 同上 |

### 合作伙伴（客户）

| event_code | 建议 payload 字段 |
|------------|-------------------|
| `partner.customer_created` | `customer_id` |
| `partner.customer_updated` | `customer_id` |
| `partner.customer_deleted` | `customer_id` |

### 运单（业务）

| event_code | 建议 payload 字段 |
|------------|-------------------|
| `waybill.created` | `waybill_id`, `waybill_no`，可选 `customer_id`（勿写客户全称） |
| `waybill.updated` | 同上 |
| `waybill.status_changed` | 同上，另含 `status`（数值与运单状态枚举一致） |
| `waybill.deleted` | `waybill_id`, `waybill_no`，可选 `customer_id` |

## 6. 幂等与去重（可选）

若同一业务动作可能被重试导致重复写入，可在业务层引入 `source_type` + `source_id` 唯一约束（当前表结构未强制，按需在后续迭代中加字段与唯一索引）。

## 7. 相关代码入口

- 模型：`app/modules/client/models/workbench/company_activity.py`
- 服务：`app/modules/client/services/company_activity_service.py`
- API：`app/modules/client/api/workbench/activities.py`
- 运力写入示例：`app/modules/client/services/capacity/self_capacity/capacity_service.py`（`capacity.self_bind` / `capacity.self_unbind`）
- 客户写入示例：`app/modules/client/api/partner/customer.py`（新建/编辑/删除成功后写入；摘要内客户名须先 `mask_organization_name`）
- 运单写入示例：`app/modules/client/api/waybill/waybill.py`（创建/编辑/状态/删除；摘要中含客户时使用 `mask_organization_name`，运单号可明文）
- 脱敏工具：`app/common/mask_display.py`

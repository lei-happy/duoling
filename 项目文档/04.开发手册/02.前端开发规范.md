# 前端开发规范

> 适用于 `frontend/` 目录下所有代码，技术栈为 Vue 3 + TypeScript + Vite + Element Plus + Pinia

---

## 1. Monorepo 结构

项目使用 **pnpm workspace** 管理多个子应用和共享包：

```
frontend/
├── package.json               # monorepo 根配置
├── pnpm-workspace.yaml        # workspace 声明
├── packages/                  # 共享包
│   ├── shared-types/          # @zhitu/shared-types  公共类型定义
│   └── shared-utils/          # @zhitu/shared-utils  公共工具函数
├── console/                   # 管理后台 (console.zhitu.me)
├── client/                    # 企业客户端 (wuliu.zhitu.me)
├── website/                   # 官网 (zhitu.me)
├── template/                  # EleAdminPlus 组件库源码
└── components/                # 跨应用共享组件 (@shared/ 别名)
```

### 常用命令

```bash
cd frontend

# 开发
pnpm dev:console      # 启动管理后台
pnpm dev:client       # 启动企业客户端
pnpm dev:website      # 启动官网

# 构建
pnpm build:console    # 构建管理后台
pnpm build:client     # 构建企业客户端
pnpm build:all        # 构建所有子应用
```

## 2. 共享包使用规范

### @zhitu/shared-types

定义后端接口的通用类型，所有子应用共用。

```typescript
import type { ApiResult, PageResult, PageParam } from '@zhitu/shared-types';

// ApiResult<T>  — 后端统一返回结构 { code, message, data }
// PageResult<T> — 分页结果 { list, count }
// PageParam     — 分页查询参数 { page, limit, sort, order }
```

### @zhitu/shared-utils

提供与框架无关的纯工具函数，避免在 console/client 之间重复编写。

```typescript
import { toURLSearch, download, toFormData } from '@zhitu/shared-utils';
```

#### createRequest 工厂函数

统一的 Axios 请求封装，自动处理：
- Token 注入 & 自动刷新
- 业务码解包（code 401/403）
- 错误消息格式化

```typescript
import { createRequest } from '@zhitu/shared-utils';

const request = createRequest({
  baseURL: import.meta.env.VITE_API_URL,
  tokenHeaderName: TOKEN_HEADER_NAME,
  getToken,
  setToken,
  getRefreshToken,
  setRefreshToken,
  removeRefreshToken,
  isRememberToken,
  redirectToLogin,
  toURLSearch,
});

export default request;
```

> console 和 client 的 `request.ts` 已统一使用 `createRequest` 工厂函数，各子应用只需注入本地的 token 管理和登录跳转逻辑。

## 3. 子应用目录结构

每个子应用（console / client）遵循统一的目录约定：

```
src/
├── api/                 # API 接口定义
│   ├── index.ts         # 导出公共类型（ApiResult 等）
│   └── <module>/        # 按业务模块分目录
│       ├── index.ts     # 接口函数
│       └── model/       # 请求/响应类型
│           └── index.ts
├── components/          # 应用级公共组件（含 EleAdminPlus 组件库）
├── config/              # 应用配置
│   └── setting.ts       # 常量配置（TOKEN_HEADER_NAME 等）
├── i18n/                # 国际化
├── layout/              # 布局组件
├── router/              # 路由配置
│   ├── index.ts         # 路由实例
│   └── routes.ts        # 路由表（动态菜单驱动）
├── store/               # Pinia 状态管理
│   └── modules/
│       ├── user.ts      # 用户状态
│       ├── theme.ts     # 主题状态
│       └── tab.ts       # 标签页状态
├── styles/              # 全局样式
├── utils/               # 工具函数
│   ├── request.ts       # Axios 请求实例
│   ├── token-util.ts    # Token 存取
│   └── common.ts        # 通用工具
└── views/               # 页面组件（按模块分目录）
    └── <module>/
        └── index.vue
```

## 4. API 层编写规范

### 目录约定

每个业务模块在 `api/` 下建立独立目录，包含 `index.ts`（接口函数）和 `model/index.ts`（类型定义）。

### 接口函数编写

```typescript
// api/system/user/index.ts
import request from '@/utils/request';
import type { ApiResult, PageResult } from '@/api';
import type { UserInfo, UserParam } from './model';

// 分页查询
export function pageUsers(params: UserParam) {
  return request.get<ApiResult<PageResult<UserInfo>>>('/system/user/page', { params });
}

// 新增
export function addUser(data: Partial<UserInfo>) {
  return request.post<ApiResult<unknown>>('/system/user', data);
}

// 修改
export function updateUser(data: Partial<UserInfo>) {
  return request.put<ApiResult<unknown>>('/system/user', data);
}

// 删除
export function deleteUser(id: number) {
  return request.delete<ApiResult<unknown>>(`/system/user/${id}`);
}
```

### 类型定义

```typescript
// api/system/user/model/index.ts
import type { PageParam } from '@/api';

export interface UserInfo {
  id: number;
  phone: string;
  realName: string;
  status: number;
  // ...
}

export interface UserParam extends PageParam {
  phone?: string;
  realName?: string;
  status?: number;
}
```

## 5. 组件规范

### 文件命名

- 组件文件夹使用 **PascalCase**：`CommonUpload/`、`FilePicker/`
- 单文件组件使用 **PascalCase**：`UserSelect.vue`
- 工具文件使用 **kebab-case**：`token-util.ts`、`date-util.ts`

### 组件库（template）

`template/` 目录是 EleAdminPlus UI 组件库的源码，`console/src/components/` 和 `client/src/components/` 各自内置了一份。

**重要约定**：
- 不要直接修改 `console/components/` 或 `client/components/` 下的基础组件
- 业务组件可以在各子应用的 `components/` 下新增
- 跨子应用共享的自定义组件放在 `frontend/components/` 中，通过 `@shared/` 别名引用

## 6. 状态管理 (Pinia)

按功能拆分 store 模块：

```
store/
├── index.ts           # Pinia 实例
└── modules/
    ├── user.ts        # 用户信息、权限、菜单
    ├── theme.ts       # 主题配置
    ├── tab.ts         # 标签页状态
    └── dict.ts        # 数据字典缓存
```

## 7. 路由与菜单

项目采用**动态菜单驱动路由**模式，登录后从后端获取用户有权限的菜单列表，动态注册路由。

- 菜单数据由后端 `sys_menu` 表管理
- 前端 `router/routes.ts` 定义静态路由（登录、白名单等）
- 动态路由在 `store/modules/user.ts` 中根据菜单数据生成

## 8. 环境变量

各子应用通过 `.env` / `.env.development` / `.env.production` 文件配置环境变量：

| 变量名 | 说明 |
|--------|------|
| `VITE_API_URL` | API 基础路径（如 `/api/console`、`/api/client`） |
| `VITE_APP_NAME` | 应用名称 |
| `VITE_BASE_URL` | 静态资源公共路径 |

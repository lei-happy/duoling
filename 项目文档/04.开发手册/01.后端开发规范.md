## 2. ORM 模型基类

### 平台库模型

| 基类 | 适用场景 | 提供的字段 |
|------|----------|------------|
| `PlatformModelBase` | 标准业务表（推荐默认使用） | `id`, `created_at`, `updated_at`, `is_deleted` |
| `PlatformBase` | 有领域特定主键的表（如 basicdata、region） | 无预设字段，自行定义 |

**规则**：新建模型优先继承 `PlatformModelBase`；仅当表有非 `id` 的领域主键（如 `brand_id`、`dealer_id`）或来自外部数据源同步的表时，使用 `PlatformBase`。

### 租户库模型

| 基类 | 适用场景 | 提供的字段 |
|------|----------|------------|
| `TenantModelBase` | 标准业务表（推荐默认使用） | `id`, `created_at`, `updated_at`, `is_deleted`，默认 `__table_tier__ = "core"` |
| `TenantBase` | 有领域特定主键的表 | 无预设字段，自行定义 |

**`__table_tier__` 取值**：
- `"core"` — 注册即创建
- `"business"` — 版本开通时创建
- `"premium"` — 高级版本开通时创建

## 3. 事务管理

**统一策略：依赖注入层自动管理事务**

`get_platform_db` 和 `get_tenant_db` 的 Session 在请求结束时自动 commit（成功）或 rollback（异常）。

**路由层不应显式调用 `db.commit()`**。只需在 Service 层调用 `db.flush()` 获取自增 ID 和服务端默认值即可。

```python
# ✅ 正确写法
@router.post("")
async def create_item(data: ItemCreate, db = Depends(get_platform_db)):
    row = await ItemService.create(db, data)
    await db.flush()
    await db.refresh(row)
    return success(data=ItemOut.from_model(row).model_dump())

# ❌ 错误写法（多余的 commit）
@router.post("")
async def create_item(data: ItemCreate, db = Depends(get_platform_db)):
    row = await ItemService.create(db, data)
    await db.commit()  # 不需要，session 会自动 commit
    return success(data=ItemOut.from_model(row).model_dump())
```

## 4. 异常处理

**统一策略：使用全局异常处理器**

全局异常处理器已注册在 `app.common.exceptions.register_exception_handlers` 中，会自动处理 `BizException`、`AuthException`、`PermissionException`、`TenantException`。

**路由层不应手动 try/except 业务异常**。直接让异常冒泡到全局处理器即可。

```python
# ✅ 正确写法
@router.get("/stats")
async def get_stats(db = Depends(get_tenant_db)):
    data = await SomeService.stats(db)
    return success(data=data)

# ❌ 错误写法（冗余的 try/except）
@router.get("/stats")
async def get_stats(db = Depends(get_tenant_db)):
    try:
        data = await SomeService.stats(db)
        return success(data=data)
    except BizException as e:
        return fail(e.message)
```

## 5. 分页查询

使用 `app.common.pagination.paginate` 通用分页助手，避免在每个 Service 方法中重复分页逻辑：

```python
from app.common.pagination import paginate

class MyService:
    @staticmethod
    async def page_items(db, page=1, limit=20, keyword=None):
        stmt = select(MyModel)
        if keyword:
            stmt = stmt.where(MyModel.name.contains(keyword))
        return await paginate(
            db, stmt, page, limit,
            order_by=MyModel.id.desc(),
            serializer=lambda r: MyOut.from_model(r).model_dump(),
        )
```

## 6. Schema 共享

当 console 和 client 的 Schema 字段完全一致时，在 `app.common.schemas/` 下定义共享基类，两端通过 re-export 或子类继承使用。

Console 端有额外字段时（如 `autohomeDealerId`），通过子类扩展。

## 7. API 权限校验

使用 `app.core.permissions` 中提供的 FastAPI 依赖函数进行路由级别的 RBAC 权限控制：

```python
from app.core.permissions import require_platform_admin, require_roles

# 仅平台管理员可访问
@router.get("/admin-only", dependencies=[Depends(require_platform_admin)])
async def admin_only():
    ...

# 指定角色可访问
@router.get("/ops", dependencies=[Depends(require_roles("ops_admin", "super_admin"))])
async def ops_only():
    ...
```

## 8. 文件上传

使用 `app.common.file_upload.create_file_upload_router()` 工厂函数创建文件上传路由，避免在 console 和 client 中重复编写上传逻辑。

## 9. 数据库迁移

使用 Alembic 管理平台库 (`zt_platform`) 的表结构变更：

```bash
cd backend

# 生成迁移文件
alembic revision --autogenerate -m "描述变更内容"

# 执行迁移
alembic upgrade head

# 查看当前版本
alembic current
```

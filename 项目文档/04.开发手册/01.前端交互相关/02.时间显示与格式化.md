# 时间显示与格式化

本文档约定运营后台（console）及关联前端中**时间数据的接口形态**与**页面展示格式**，避免列表、详情中出现 ISO 字符串（如含 `T`）与业务约定格式混用。

## 1. 基本原则

| 层级 | 约定 |
|------|------|
| **接口** | 后端可返回 **ISO 8601** 等标准形式（例如 `2026-03-24T21:48:20`）。便于序列化、排序与多端解析，不强制在接口层拼成「给人看的」字符串。 |
| **展示** | 页面上统一为 **`YYYY-MM-DD HH:mm:ss`**（示例：`2026-03-24 21:48:20`）。 |
| **实现位置** | 在 **前端** 将接口值格式化为展示字符串；若需国际化、用户时区，也在前端基于同一套工具扩展。 |

说明：接口里出现字母 **`T`** 是 ISO 8601 在日期与时间之间的分隔符，属于正常现象；**不要在业务代码里手工 `replace('T', ' ')` 作为主要方案**，应通过统一的格式化函数处理，保证无效值、空值行为一致。

## 2. 管理后台（console）统一工具

路径：`frontend/console/src/utils/date-util.ts`

| 导出 | 说明 |
|------|------|
| `DATE_TIME_FORMAT` | 常量 `'YYYY-MM-DD HH:mm:ss'`，可与 `el-date-picker` 的 `value-format`、`format` 等对齐使用。 |
| `formatDateTime(val, emptyPlaceholder?)` | 将接口返回的时间（字符串、时间戳、`Date` 等）格式化为统一展示格式；空值默认显示为 `-`；无法解析时返回原值的字符串形式。 |

依赖 **dayjs**（项目已依赖，与现有用法一致）。

## 3. 使用方式

### 3.1 表格列

```ts
import { formatDateTime } from '@/utils/date-util';

// columns 中
{
  prop: 'createdAt',
  label: '创建时间',
  width: 170,
  align: 'center',
  formatter: (row) => formatDateTime(row.createdAt)
}
```

### 3.2 模板中展示

```vue
<span>{{ formatDateTime(detail.createdAt) }}</span>
```

需在 `<script>` 中同样从 `@/utils/date-util` 引入 `formatDateTime`（或在组合式封装中导出）。

### 3.3 与日期选择器一致

筛选、表单中的 `el-date-picker` / 浮动标签日期组件，建议 **`value-format`（及需要的 `format`）与 `DATE_TIME_FORMAT` 一致**，避免提交与展示格式两套标准。

示例（与《浮动标签组件集成指南》中的日期范围一致）：

```vue
value-format="YYYY-MM-DD HH:mm:ss"
```

若需仅日期（无时分秒），可在 `date-util` 中另行增加 `formatDate` 等函数并在本文档补充约定。

## 4. 其他子项目

- **client / template / website** 若尚未提供同名工具，可：
  - 在各自 `utils` 中复制同一套实现；或
  - 抽到 monorepo 共享包后统一引用。

原则与 console 相同：**展示格式集中在一处定义**，业务页面不写重复的 `dayjs(...).format(...)` 片段（特殊情况除外并注释说明）。

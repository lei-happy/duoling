## 一、结论速览

- 绝大多数需求文档对应的代码**已经落地**：账号体系、客户运营中心、AI 数字员工/数字人、资源管理（车辆/驾驶员/运力中心/社会运力池）、计费引擎（运价合同/运费计算/线路）、合作伙伴（客户/承运商/平台互联）、运营调度（任务单/状态机/调令/装卸/回单）、审批中心、系统设置（水印）、运力宝（证照监控/承运商建档）、驾驶员 H5 端等。
- **核心缺口集中在两块**：
  1. **财务结算模块的"应收 + 跨任务应付"三条线**（客户侧对账/结算/发票、承运商侧对账/结算、自有司机工资单）——通用基座已就绪，具体单据未建。
  2. **移动端管理侧 / 移动端 BI 看板 / LITE 端承运商运力上报**——需求文档已有，前端工程未建。

## 四、建议排期与优先级

> 结合业务闭环价值与依赖关系给出建议，具体节奏以实际资源为准。

| 优先级 | 事项 | 理由 | 前置依赖 |
|:------:|------|------|---------|
| P0 | 财务-客户侧对账/结算/发票（§2.1 #1） | 应收是资金回笼的核心闭环，当前完全缺失 | 通用基座（✅）、运单签收聚合（✅） |
| P0 | 财务通用服务模板 + 候选池 linkage（§2.1 #4） | 是 #1~#3 的公共底座，先建可显著降低重复 | 通用基座（✅） |
| P1 | 财务-承运商侧对账/结算（§2.1 #2） | 应付跨任务批量结算，月结承运商刚需 | #4、任务级结算单（✅） |
| P1 | 财务-自有司机工资单（§2.1 #3） | 自有司机发薪闭环，联动承包结算配置 | #4、承包结算配置（✅） |
| P2 | 运力宝商业化守卫与配额补全（§2.3 #8/#9） | 决定运力宝可售卖，门控/配额底座已具备 | `require_feature`/`quota_service`（✅） |
| P2 | LITE 端承运商运力上报（§2.2 #7） | 承运商轻量协同入口，后端能力已就绪 | `carrier_capacity`/`carrier_invitation`（✅） |
| P3 | 移动端管理侧 + 移动端 BI 看板（§2.2 #5/#6） | 移动化增强，非阻塞主业务闭环 | 相关 BI/调度后端（✅） |

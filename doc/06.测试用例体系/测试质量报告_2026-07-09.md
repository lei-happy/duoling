## 三、本轮质量提升项

### 3.1 修复 open 端 HTTP 集成用例「被静默跳过」的测试基座缺陷（BUG-TEST-001）

- **现象**：全量执行时，`tests/open` 下 9 个 HTTP 集成用例（注册、更新日志、短信、LITE）恒显示 `SKIPPED [平台库 zt_platform_ci 不可连接]`，即便平台库实际可连。
- **根因**：`app.core.database.db_manager` 是**全局单例**，其平台库异步引擎会绑定到「首次初始化时的事件循环」。而 pytest-asyncio（`asyncio_mode=auto`）为每个 async 用例分配独立的函数级事件循环；当 open HTTP 用例运行时，复用了上一个用例遗留的 `_platform_session_factory`（引擎绑定在已关闭的事件循环上），探测时抛 `Event loop is closed`，被 `except Exception` 静默吞掉 → 用例整批误 skip。
- **影响**：这 9 个开放接口的 HTTP 集成路径**从未真正执行**，测试报告的「通过」存在盲区（假绿）。
- **修复**：`tests/open/conftest.py::_platform_db_reachable()` 改为每次探测前，先丢弃可能绑定在旧事件循环上的引擎/工厂，在**当前事件循环**上重建（`db_manager` 重新 `init_platform_db`），保证探测与后续 HTTP 请求在同一活跃循环上。
- **结果**：9 个用例由 skip 转为**真正执行并通过**，open 端 88/88 全通过、0 skip。

### 3.2 补齐审批中心（Approval）核心逻辑单测，从 0 到 49（覆盖 TC-CLI-APPROVAL-001、010~039）

审批中心此前**无任何自动化脚本**（06.审批中心.md 全部登记为「待补/仅手工」）。本轮新增 `tests/client/test_approval_flow.py`，聚焦**零 DB 依赖**的引擎地基逻辑：

## 五、覆盖缺口与后续建议

1. **审批中心 DB 强相关链路**：发起社会运力入池审批 → 待办出现在审批中心 → 通过/驳回触发业务回调（`events._register_approval_callbacks`），需较多种子数据与跨模块状态驱动，建议后续补集成用例（TC-CLI-APPROVAL-002~007）。
2. **异步 Worker / 外部依赖**：计费/成本 worker、双引擎回归、证照预警 worker、AI 工具编排（依赖 LLM）目前仅手工，建议以 mock/契约测试补齐关键分支。
3. **运营后台读接口批量脚本化**：`ops` 同步、`log_center`、`changelog` 等以鉴权+分页读为主，可批量补冒烟脚本。
4. **待测（未开发）项**：财务结算应收/对账、承运商独立结算、移动端 BI、LITE 前端、资质自助上报/OCR —— 按 `项目文档/05.开发计划/需求-代码落地差距清单.md` 登记，落地后再补测。
5. **测试环境统一**：当前 venv 为 Python 3.9.13，项目 README 要求 3.11+；建议对齐以消除 aiomysql 在 Windows/3.9 下 `Event loop is closed` 的关闭期 ResourceWarning 噪声（不影响结果，仅污染输出）。

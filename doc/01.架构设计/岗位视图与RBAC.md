# 岗位视图与 RBAC

> **状态**：Accepted
>
> **日期**：2026-08-24
>
> **适用范围**：租户后台角色管理、`/api/client/auth/user-info`、管理员小程序工作台

## 背景

小程序原型用「财务 / 老板 / 调度 / 车队长」组织首页，租户后台却是可自定义的 RBAC（`biz_role` 仅 seed `admin`）。若把四个中文名写成系统角色，会和「不在代码里预设业务角色」的既有约定冲突。

## 决策

岗位是角色上的**标签列表** `biz_role.personas`，不是 RBAC 角色。一个角色可挂多个岗位。

| 概念 | 作用 |
|------|------|
| `personas` | `dispatch` / `boss` / `finance` / `captain` 的有序去重列表，决定小程序能切换哪些工作台 |
| `authorities` | 唯一权限来源；视图不能放大权限 |
| 一人多岗 | 角色多选，或给用户挂多个角色；小程序按标签并集切换 |
| 租户管理员 `user_type=1` | 直接拥有四个视图，与「管理员看全菜单」一致 |

存量未打标的角色不贡献任何视图；新建角色必选。默认视图写在 `sys_user.workplace_config.defaultPersona`。

## 未采纳的方案

- **按权限前缀推断视图**：少一次配置，但综合岗会误入多套首页，语义不清晰。
- **预置四个标准角色**：偏离「岗位由运营配置、代码不预设分配」。
- **取消具名视图、纯卡片拼装**：最兼容自定义角色，但要改掉已确认的小程序信息架构。
- **persona 双写到 `sys_role`**：平台镜像今天连角色名都不回写，再镜像一层更容易漂。

## 后果

- 角色名叫什么都可以，只要标签对，小程序首页就对。
- 标签与菜单勾选可能错位（标了调度却只授财务菜单），只做文案提示，不硬拦。
- 电脑端工作台布局不随 persona 变化。

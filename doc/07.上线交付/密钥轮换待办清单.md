### 3. 推荐顺序（降低中断）

分三波，不要一上来就改数据库密码或 `APP_SECRET_KEY`。

1. **第一波（可热切换）**：阿里云 AccessKey、高德 Web 服务 Key —— 先建新的，写入 `.env` 并重启，验证通过后再禁用旧的。
2. **第二波（维护窗口）**：`JWT_SECRET_KEY`、`APP_SECRET_KEY`、MySQL 密码 —— 会踢登录态，并让部分加密数据暂时失效。
3. **第三波（可稍后）**：SSL 证书私钥重签 —— Gitee 若为私有且仅内部可见，可排后面。

第二波请选业务低峰，并提前告知：用户需重新登录；AI 对话和开放平台会短时不可用。

### 4. `APP_SECRET_KEY` 换完必须补的两件事

该密钥不只用于“应用盐值”，还派生加密 / 哈希：

1. **运营后台 → 模型 Provider**：每家 LLM 的 apiKey 要**重新填写并保存**（旧密文用旧密钥加密，解不开）。
2. **开放平台应用**：已签发的 AppSecret / MCP Token 会校验失败，需给租户**重新颁发凭证**。

未做这两步：AI 对话失败，开放 API / MCP 验签失败。

### 5. 改 MySQL 密码的顺序（不要反）

1. 先在服务器 MySQL 执行 `ALTER USER` + `FLUSH PRIVILEGES`
2. 再改服务器 `.env` 的 `DB_PASSWORD`
3. 再重启 backend / openapi / worker

平台库与租户库共用这一个密码（compose 里 `PLATFORM_DB_PASSWORD`、`TENANT_DB_PASSWORD` 都读 `DB_PASSWORD`）。改完立刻做一次登录或 `/health`，避免容器起不来又改不回去。

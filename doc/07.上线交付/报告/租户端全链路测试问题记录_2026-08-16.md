### E2E-01 录单不填运费时，对账能建、结算建不出来

- **模块**：计划录入 / 客户对账 / 客户结算
- **是否阻断开票**：是（不补运费就停在结算）
- **复现**：
  1. 新建计划（本轮 E2E 单）只填基础信息、商品车、收车门店，不填运费。
  2. 运单编辑页「运费」Tab 默认不展示（`waybill.list_show_freight_amount`，默认关）。
  3. 交车后做客户对账：候选里运费为 `--` / 0，仍可生成对账单。
  4. 新建结算单勾选该对账单 → 前端校验「认领金额要大于 0」，生成失败。
- **期望**：录单就能填运费；或对账/结算明确提示「这单还没运费，先回计划补金额」；不要让用户建一张 0 元对账单再卡死。
- **实际**：三张 E2E 运单 `freightAmount` 均为空。本轮用 `PUT /api/client/business/waybill/{id}` 各补 1800 元后，对账合计 5400，结算、开票才通过。
- **涉及**：
  - `frontend/client/src/views/operation/waybill/components/waybill-edit.vue`（运费 Tab 默认隐藏）
  - `frontend/client/src/views/finance/customer-settlement/components/settlement-create.vue`（`appliedAmount <= 0` 直接拒绝）
  - `backend/app/modules/client/services/finance/customer/customer_recon_service.py`（运费空按 0 入账）

### E2E-02 确认交车「默认全选」经常没勾上

- **模块**：调度工作台 / 确认交车
- **是否阻断**：否，勾上就能过
- **复现**：任务已到达（status=4），挂接行已卸车（item status=2）。打开「确认交车」，表里有行，复选框未勾。点「确认交车」报：**请至少勾选一行待交车的挂接货物**。
- **期望**：只有一行待交车时默认勾选，打开即可确认。
- **实际**：`action-confirm-sign.vue` 在拉完列表后立刻 `toggleAllSelection()`，表格往往还没渲染完，全选落空。
- **涉及**：`frontend/client/src/views/operation/task-workbench/components/action-confirm-sign.vue`（约 282–284 行）

### E2E-03 装车 / 到达必须先选货物，确认按钮默认禁用

- **模块**：调度工作台 / 确认装车、确认到达
- **是否阻断**：否，选完就能过
- **复现**：
  - 装车：不点「全选」或商品车卡片时，「确认本次装车」禁用。
  - 到达：没有「全选」按钮，必须勾表格行，「确认本次卸车」才可点。
- **期望**：单调令、只剩一行待装/待卸时默认选中；到达侧至少给「全选」，与装车对齐。
- **涉及**：
  - `frontend/client/src/views/operation/task-workbench/components/action-confirm-load.vue`
  - `frontend/client/src/views/operation/task-workbench/components/action-confirm-arrive.vue`

### E2E-04 承运商代填运力后，按钮仍写「通知承运商上报」

- **模块**：调度工作台 / 派车
- **是否阻断**：否，点下去其实会派车（填全了主驾/电话/车牌）
- **复现**：承运商任务（如 RW202608000069）点「派车」→ 展开「调度员代填运力（兜底）」→ 填主驾、电话、车牌。底部按钮仍是 **通知承运商上报**，不是「确认派车」或「提交代填运力」。
- **期望**：展开代填或填全三项后，按钮改成「提交代填运力」，避免调度员以为只是发了个通知。
- **实际**：`form.isProxy` 只在点提交、跑 `validate()` 时才置 true，文案来不及变。未填代填时点同一按钮，弹窗关掉并提示「已通知承运商上报运力」，任务仍停在待派车。
- **涉及**：`frontend/client/src/views/operation/task-workbench/components/action-dispatch.vue`（`confirmLabel` / `validate`）
- **附**：代填面板是 Collapse，展开动画未结束时输入框不可见，容易点空。建议默认展开或点「代填」直接打开表单。

### E2E-05 预付单打开时没有费用行，保存直接报错

- **模块**：任务费用单
- **是否阻断开票**：否（预付不是开票前置）
- **复现**：派车后选「立即创建」预付单，或工作台「新建费用单」。不点「新增费用项」直接保存 → **请至少添加 1 条费用项**。
- **期望**：打开时带一行默认费用（如油费），或保存前提示「先加一条费用」并滚到表格。
- **涉及**：
  - `frontend/client/src/views/operation/task-finance/components/finance-edit.vue`
  - `frontend/client/src/views/operation/task-finance/components/finance-item-table.vue`

### E2E-06 派车成功后预付引导框挡住后续操作

- **模块**：调度工作台 / 派车
- **复现**：自有车派车成功后弹出「是否立即创建预付单」。不点「暂不创建」/「取消」，装车等按钮点不到。
- **期望**：可接受；建议默认焦点在「暂不创建」，或改成非模态提示。
- **涉及**：`frontend/client/src/views/operation/task-workbench/index.vue`（`maybePromptPrepay`）

### E2E-07 强制取消后计划不能从高位态回到待调度（已修）

- **模块**：计划状态机
- **复现（修前）**：运输中任务强制取消，聚合器要把计划拉回待调度（1），高位态不允许跨步回退。报错类似：计划状态从「运输中」不能跳转到「待调度」。`4→1`、`5→1` 同样撞墙。
- **修复**：`backend/app/modules/client/services/state_machine/waybill_state_machine.py` 允许作业态跨步回退到 1/2；已交车（6）仍须先撤销回单；取消（7）仍不可回退。
- **验证**：`python scripts/verify/verify_task_state_chain.py 1001` → 32 通过 / 0 失败；场景 C 强制取消后 waybill=1。

## 三、页面操作备忘（给复测）

这些不是缺陷，但第一次点很容易停住：

1. 工作台筛框文案是「请输入任务单号 / 计划号」，列表主要显示任务号，用 `taskNo` 搜更稳。可用 `?keyword=RW…`。
2. 行内动作文案：确认装车 / 标记出发 / 确认到达 / 确认交车。弹窗确认键分别是「确认本次装车」「确定」「确认本次卸车」「确认交车」，不要找「确定」硬套。
3. 社会运力分配承运后常常已是待装车，不要再点「派车」。
4. 承运商 LITE 未通时，必须展开「调度员代填运力」，填主驾姓名 / 电话 / 车牌，再点底部按钮（文案见 E2E-04）。
5. 对账：先选客户，周期默认本月；交车日要落在周期内。候选条件：运单 status ∈ {5, 6}。
6. 结算：只吃**已确认**且可认领金额 > 0 的对账单；要开票须保持「需要开票」打开。
7. 开票：新建申请 → 勾结算单 → 生成 → **提交开票** → **登记开票**（填发票号码）→ 确认已开票。登记框聚焦后，浮动标签会从「请输入发票号码」收成「发票号码」。

## 四、建议修的优先级

1. **E2E-01**：不补运费就开不了票。录单露出运费，或结算空态写成「先回计划补运费」。
2. **E2E-02 / E2E-03**：装车、到达、交车默认勾选当前可操作行（或到达补全选）。
3. **E2E-04**：代填填全后改按钮文案，Collapse 默认展开。
4. **E2E-05**：预付打开带一行默认费用。
5. **E2E-08**：最终结算单补互斥校验（和承运商对账对齐）。

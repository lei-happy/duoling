## 1. 设计基调

### 1.1 大厅不是管理后台

租户端其余模块都是「管理型界面」：表格 + 搜索 + 增删改查，用户目标明确、动作确定。**大厅是「浏览型界面」**：用户是来逛的，来看看有没有合适的机会，目标模糊、需要被吸引。

两者的界面语言应该不同：

| | 管理型（现有模块） | 浏览型（大厅） |
|---|------|------|
| 主布局 | 表格，信息密度高 | **卡片流**，视觉引导强 |
| 主视觉 | 字段对齐 | **线路箭头 + 关键数字** |
| 首屏 | 搜索条 + 表格 | 筛选条 + 卡片 + 空态引导 |
| 动作 | 行内多个操作链接 | 卡片上一个主行动按钮 |

但「我发布的」是管理场景，仍用表格。所以每个大厅页面是「浏览 Tab + 管理 Tab」的组合。

### 1.2 三条 UX 原则

1. **发布必须三步内完成。** 从任务单点「发布到货源大厅」到提交成功，只允许出现一个弹层、一屏表单、一个提交按钮。任何多步向导都会杀死使用率。
2. **信息可信度要可见。** 每张卡片都要回答「这家靠不靠谱」：认证标识、成交数、评分、响应速度，缺一不可。
3. **付费引导要克制且有信息量。** 非 pro 用户看到的不是一堵墙，而是完整的市场信息 + 一句「升级后可以联系对方」。让他看见价值再谈付费。

### 2.1 1.1 期实际落地结构

上面是设计阶段的规划。真正实现时，**两个大厅的差异只在"发布"这一件事上**，列表、筛选、详情、我发布的四块的交互与字段布局高度对称，所以没有按大厅各写一套，而是收成一份共用视图 + 两个薄壳：

```text
frontend/client/src/views/ecosystem/
├── cargo-hall/
│   ├── index.vue                     # 薄壳：挂 eco-hall-view，接住发布/编辑事件
│   └── components/
│       ├── task-picker.vue           # 选任务单（待派车）
│       └── cargo-publish.vue         # 发布/编辑货源弹层
├── capacity-hall/
│   ├── index.vue                     # 薄壳，同上
│   └── components/
│       ├── capacity-picker.vue       # 选运力档案（空闲）
│       └── capacity-publish.vue      # 发布/编辑运力弹层
└── components/                       # 两个大厅共用
    ├── eco-hall-view.vue             # 大厅主视图：页签 + 筛选 + 卡片流 + 我发布的
    ├── eco-hall-filter.vue           # 筛选条（按 postType 切换货源/运力专属项）
    ├── eco-post-detail.vue           # 详情抽屉（含发布方专属的热度反馈）
    ├── eco-my-posts.vue              # 我发布的（状态页签 + 表格 + 行内动作）
    ├── eco-publish-fields.vue        # 发布弹层公共字段（联系人、报价、有效期、可见性）
    ├── eco-region-select.vue         # 按 biz_region.id 选地区
    ├── eco-extend-modal.vue          # 延长展示时长
    ├── use-post-actions.ts           # 提交送审 / 下架 / 重新上架 的确认与文案收口
    ├── eco-route-arrow.vue
    ├── eco-tenant-badge.vue
    ├── eco-post-status-tag.vue
    ├── eco-upgrade-hint.vue
    └── eco-empty-state.vue
```

与原规划的两处偏差：

1. **"我发布的"不是独立菜单，是大厅内的第三个页签**。挂牌的发布和浏览是同一件事的两面，分成两个菜单会让用户在"我发的还在不在架上"和"别人发了什么"之间反复跳。页签上带角标，提示有多少条被驳回或还是草稿。
2. **发布弹层按大厅分开、其余共用**。发布的源头不同（任务单 / 运力档案）、专属字段不同（货量车位 vs 车型证照），共用会写成一堆 `v-if`；而卡片和详情的字段差异靠 `postType` 分支就能覆盖，共用反而保证了两个大厅的手感一致。

`intent-create.vue`、`deals/`、`profile/` 属于 1.2 期（意向与成交），本期未实现。

## 3. 核心页面设计

### 3.1 货源大厅

**布局**：`ele-page` > 顶部 Tab > 筛选条 > 卡片流 > 分页

```text
┌────────────────────────────────────────────────────────────────┐
│  [ 找货源 ]  [ 我发布的 (3) ]                    [ + 发布货源 ] │
├────────────────────────────────────────────────────────────────┤
│  出发地 [浙江 · 杭州 ▾]  →  目的地 [四川 ▾]                     │
│  装车时间 [7天内 ▾]  台数 [__]-[__]  品牌 [▾]  ☑ 只看已认证     │
│  常跑线路：[杭州→成都] [宁波→重庆] [上海→西安]      [重置] [筛选]│
├────────────────────────────────────────────────────────────────┤
│ ┌──────────────────────────────┐ ┌──────────────────────────┐ │
│ │ 杭州 ──────────────→ 成都     │ │ 宁波 ─────────→ 西安      │ │
│ │ 萧山区              双流区    │ │ 北仑区          未央区    │ │
│ │                              │ │                          │ │
│ │ 8 台 · 吉利 星越L             │ │ 6 台 · 比亚迪 宋PLUS      │ │
│ │ 7月28日 装车 · 可协商         │ │ 7月26日 装车              │ │
│ │ 包车价 ¥12,000（可议）        │ │ 面议                      │ │
│ │                              │ │                          │ │
│ │ 杭州**物流 ✓已认证            │ │ 宁波**运输 ✓已认证        │ │
│ │ 已完成 23 单 · ★4.8 · 2h内回复│ │ 已完成 7 单 · ★4.6        │ │
│ │                              │ │                          │ │
│ │ 3 人想合作      [ 我要接单 ]  │ │              [ 我要接单 ] │ │
│ └──────────────────────────────┘ └──────────────────────────┘ │
└────────────────────────────────────────────────────────────────┘
```

**卡片信息的优先级**（从上到下）：线路 > 货量与货物 > 时间 > 价格 > 企业可信度 > 热度与行动。这个顺序对应找货方的决策顺序：先看顺不顺路，再看装不装得下，再看时间对不对，最后才看价钱和对方是谁。

**「我要接单」按钮的四种状态**：

| 用户情况 | 按钮 | 点击行为 |
|---------|------|---------|
| pro 且已认证 | 「我要接单」主色 | 打开发起意向弹层 |
| pro 但未认证 | 「完成认证后可联系」次要色 | 跳转企业名片页的认证引导 |
| **standard / lite / ylb** | 「升级后可联系」次要色 | 打开升级引导弹层（见 §7.2） |
| 已发起过意向 | 「洽谈中」禁用态 | 跳转我的合作 |

> 注意 standard 用户在这个页面上的状态是**「能发布、能被找、不能主动找」**：顶部的「+ 发布货源」按钮对他是完全可用的主色按钮，只有卡片上的「我要接单」是引导态。这两个按钮在同一屏出现且状态不同，必须让用户一眼理解这不是 bug——靠 §7.2 的引导弹层把话说清楚。

### 3.3 我的合作

三个 Tab，用表格 + 侧滑面板：

| Tab | 内容 | 主要动作 |
|-----|------|---------|
| 收到的意向 | 别人对我的挂牌发起的意向 | 响应 / 婉拒 / 选定 |
| 发出的意向 | 我对别人挂牌发起的意向 | 撤回 / 留言 |
| 合作记录 | 成交单列表 | 确认成交 / 上报进度 / 确认完成 / 评价 / 加为承运商 |

**未读提示**：菜单与 Tab 上带数字角标，未响应的意向要醒目。撮合类产品的成败很大程度取决于响应速度，界面必须制造紧迫感。

**成交详情**用 `EcoTimeline` 展示履约全流程（`02` §6.1 的时间线视图）。

### 3.4 企业名片

分三块：

1. **对外形象**：企业简介、主营线路（多条，可作为大厅筛选快捷项）、车队规模、擅长货类、联系人。工商信息从 `sys_tenant` 只读带出，不可编辑。
2. **认证与信誉**：认证状态与引导、客观数据展示（`04` §5.2 的指标）、收到的评价列表。
3. **隐私设置**：屏蔽名单管理、默认可见性偏好（新发布挂牌的默认公开范围）。

名片页同时是**外部视角的预览页**——提供「预览同行看到的样子」切换，让用户清楚自己对外暴露了什么。这个小功能对打消发布顾虑的作用超出预期。

### 3.5 发布弹层

从任务单发布时，弹层分两栏：

```text
┌─ 发布到货源大厅 ────────────────────────────────────┐
│                                                     │
│  ┌ 自动带出（来自任务单）───────┐  ┌ 需要你补充 ──┐  │
│  │ 杭州 萧山区 → 成都 双流区    │  │ 报价 *       │  │
│  │ 8 台 · 吉利 星越L 6台        │  │ [包车价 ▾]   │  │
│  │        比亚迪 汉 2台         │  │ ¥ [_______]  │  │
│  │ 7月28日 08:00 装车           │  │ ☑ 价格可议    │  │
│  │ 7月30日 预计到达             │  │              │  │
│  │              [ 修改信息 ]    │  │ 联系人 *      │  │
│  └─────────────────────────────┘  │ [张三      ]  │  │
│                                    │ [138****00 ] │  │
│  公开范围                           │              │  │
│  ○ 推荐：认证同行可见企业名，        │ 展示天数 *    │  │
│    联系方式在对方发起合作后互相可见  │ [7 天 ▾]     │  │
│  ○ 急单：直接公开联系方式            └──────────────┘  │
│                                                     │
│  ⓘ 客户名称、内部单号、车架号不会对外展示             │
│                                                     │
│                        [ 取消 ]  [ 提交，等待平台审核 ] │
└─────────────────────────────────────────────────────┘
```

设计要点：

- 左栏是只读回显，让用户确认「发出去的是这些信息」，配「修改信息」可展开编辑
- 右栏只有三个必填项，符合「三步内完成」原则
- 底部那句「客户名称、内部单号、车架号不会对外展示」是**打消顾虑的关键文案**，必须显眼
- 提交按钮文案直接说明下一步是审核，避免用户提交后不知道为什么没上架

## 6. 文案规范

遵循项目《人性化交互提示语》规范。以下为本模块的关键文案，开发时直接照用：

### 6.1 加载与等待

| 场景 | 文案 |
|------|------|
| 大厅列表加载 | 正在为你找货源，请稍候… / 正在为你找运力，请稍候… |
| 提交发布 | 正在提交，请稍候… |
| 发起意向 | 正在发送合作意向，请稍候… |
| 批量审核（运营端） | 正在批量通过，请稍候… |

### 6.2 成功

| 场景 | 文案 |
|------|------|
| 发布提交 | 已提交，平台会尽快审核，通常 2 小时内完成。审核通过后同行就能看到了 |
| 审核通过（免审直通） | 已发布，同行现在可以看到这条货源了 |
| 发起意向 | 合作意向已送达，对方回复后你们就能互相看到联系方式 |
| 响应意向 | 已回复，现在你们可以互相看到联系方式了 |
| 选定合作方 | 已选定，等对方确认后就可以开始了 |
| 确认完成 | 这次合作已完成，给对方评个价吧 |
| 停止展示 | 已停止展示，同行不会再看到这条信息 |

### 6.3 业务失败（BizException 文案）

| 场景 | 文案 |
|------|------|
| 任务单状态不符 | 只有还没派车的任务可以发布到货源大厅 |
| 重复发布 | 这单已经在货源大厅展示中，去看看有没有人联系 |
| 运力不空闲 | 这台车正在运输中，暂时不能对外发布 |
| 证照过期 | 道路运输证已过期，请先更新后再对外发布 |
| 挂牌已下架 | 这条信息已经不展示了，看看其他的吧 |
| 挂牌已被他人锁定 | 手慢了，这单已经有合作方了 |
| 未认证 | 完成企业认证后才能发布和联系同行，认证一般 1 个工作日内完成 |
| 版本不足（主动发起意向） | 主动联系同行是专业版的能力。你现在已经可以发布自己的货源和运力，升级后还能主动出击 |
| 版本不足（发布，lite/ylb） | 发布货源需要标准版及以上，升级后就能把吃不下的货交给同行了 |
| 正文含联系方式 | 为了保护双方，请不要在信息里直接留联系方式。同行对你的信息感兴趣时，你们会自动互相看到联系方式 |
| 越权操作 | 这条信息不属于你的企业，无法操作 |
| 超时确认 | 对方等了 24 小时没等到确认，这次合作已经取消了 |

### 6.4 空态

| 场景 | 文案 + 行动 |
|------|-----------|
| 大厅无结果（有筛选） | 这些条件下暂时没有合适的货源。换个线路试试，或者[保存为订阅]，有新货源第一时间通知你 |
| 大厅无结果（无筛选） | 大厅还比较冷清，你可以先[发布自己的货源]，让同行找到你 |
| 我发布的为空 | 还没发布过。配载完成后车不够用？[从任务单发布]，让同行来接 |
| 收到的意向为空 | 还没有人发起合作。可以试试把展示天数延长，或者调整一下报价 |
| 合作记录为空 | 还没有合作记录。谈成的合作记得在这里登记，方便跟进进度、积累信誉 |

### 6.5 明确禁止的写法

- ✗ 「请求失败」「接口异常」「加载出错」→ ✓「没能加载出来，刷新一下试试」
- ✗ 「status 不合法」「参数错误」→ ✓ 说清哪个业务条件不满足
- ✗ 「操作成功」→ ✓ 说清成功做了什么
- ✗ 「请稍后」→ ✓「请稍候」

## 7. 分版本体验设计

付费门槛只有一处——**主动发起合作意向**（详见 `00` §5.2）。除此之外所有能力对全版本开放。这是转化的关键路径，需要专门设计而不是简单加一堵墙。

### 7.1 三档体验对照

| 触点 | lite / ylb | **standard** | pro |
|------|-----------|-------------|-----|
| 菜单与两个大厅 | 可进入 | 可进入 | 可进入 |
| 大厅卡片信息 | 完整 | 完整 | 完整 |
| 「+ 发布货源/运力」按钮 | 引导态 | **主色可用** | 主色可用 |
| 卡片「我要接单/我要用车」 | 引导态 | 引导态 | 主色可用 |
| 详情抽屉 | 可看，联系方式位遮罩 | 可看，联系方式位遮罩 | 可看，解锁后显示 |
| 我发布的 | 空态引导升级 | **完全可用** | 完全可用 |
| 我的合作（响应意向、成交、履约、评价） | **完全可用** | **完全可用** | 完全可用 |
| 企业名片与屏蔽名单 | 可用 | 可用 | 可用 |

> lite / ylb 的发布按钮是引导态还是可用，取决于 `00` §9 第 8、9 条的最终决定。若确认给 ylb 开放运力发布，则 ylb 在运力大厅的发布按钮为主色可用、在货源大厅为引导态。前端统一用 `userStore.hasFeature('ecosystem_capacity_publish')` 判断，不要硬编码版本号，这样后续调整版本绑定时前端零改动。

### 7.2 两种升级引导弹层

不能用同一个弹层应付两种完全不同的用户心理：

**A. standard 用户点击「我要接单」时**

他已经在用大厅发布了，知道这里有价值，缺的是「主动出击」的能力。引导要落在具体机会上：

```text
┌─ 专业版可以主动联系同行 ─────────────────────────┐
│                                                 │
│  你已经可以把货源和运力发布到大厅，              │
│  升级专业版后还能主动出击：                      │
│                                                 │
│  ✓ 主动向同行发起合作意向                        │
│  ✓ 查看对方联系方式，直接沟通                    │
│  ✓ 订阅常跑线路，有新货源第一时间通知            │
│                                                 │
│  ── 现在大厅里 ──────────────────────           │
│  138 条货源 · 其中 23 条从你的常跑线路出发       │
│  86 条运力 · 其中 11 条正往你的方向走            │
│                                                 │
│              [ 以后再说 ]  [ 了解专业版 ] │
└─────────────────────────────────────────────────┘
```

关键是最后那两行**基于他自己的主营线路算出来的真实机会数**。抽象的功能对比说服力远不如「有 23 条货就在你常跑的线上，你现在联系不上」。

**B. lite / ylb 用户点击任意受限按钮时**

他还没有体会过大厅的价值，引导要先证明市场是活的：

```text
本月大厅有 138 条货源、86 条运力信息，已促成 24 次合作。
升级后你也可以把自己的货和车发布上来，让同行找到你。
                        [ 以后再说 ]  [ 查看版本对比 ]
```

两个弹层都跳 `/upgrade-plans`。文案中出现的数字必须是真实统计值，由后端提供接口；**灰度期数据量小的时候不要展示数字**，虚假的繁荣一眼就能被看穿，反而损害信任。

### 7.3 给挂牌方的需求侧热度反馈

standard 租户能发布但不能主动找，所以他的挂牌可能一段时间无人问询。为避免「发了没用」的挫败感，挂牌详情（仅对发布方可见）展示：

- 「本周有 12 家同行看过这条信息」
- 「其中 5 家来自四川、3 家来自重庆」（按查看方所在地聚合，不暴露具体企业）
- 无人问询超过 3 天时，给一条建议：「暂时没人联系，可以试试延长展示天数或者调整报价」

这个反馈同时也是转化素材——他会想「有 12 家看过却没人联系，是不是我该主动出击」。

## 8. 响应式与性能

| 项 | 处理 |
|---|------|
| 卡片流布局 | CSS Grid，`auto-fill` + `minmax(360px, 1fr)`，窄屏自动降为单列 |

| 表格缓存 | `ele-pro-table` 的 `cache-key` 命名：`EcosystemMyCargoTable`、`EcosystemDealTable` 等 |

# 企业端计费引擎模块 - 线路管理

> **所属阶段**：阶段四/五 - 计费引擎（资源主数据）
>
> **文档状态**：已完成
>
> **优先级**：高（内部结算标准里程/时效的基础数据）

## 一、功能概述

线路管理维护租户库 `biz_route` 主数据，记录物流公司认可的「出发地 → 目的地」标准里程（km）与预计运输时长（h）。该数据用于：

- **运单/任务录入**：按起终点 `regionId` 联想已维护线路里程（`GET /business/task/route-distance`）
- **内部结算与运营参考**：作为核定公里数、标准时效的基准
- **与运价合同的关系**：运价明细中的「线路公里数」（`biz_freight_rate.distance_km`）为客户合同侧标准值，可与 `biz_route.distance` 分别维护，二者无强制一致

核心能力（本期）：

- 线路 CRUD、启停、按起终点关键字检索
- 新增/编辑时基于地区库经纬度调用高德 **路径规划 2.0 · 驾车**（`strategy=34` 高速优先），一次返回建议里程、时长与路线折线
- 用户确认「采纳建议」后写入表单字段，仍可手改后保存
- 弹窗左右分栏：左侧表单 + 高德建议，右侧地图展示起终点标点及驾车路线折线

## 二、业务背景

### 核心业务诉求

1. **标准里程统一**：避免各业务人员手工估算不一致，以高德驾车路径规划（高速优先）为参考基准
2. **可审计、可覆盖**：系统仅提供建议值，采纳需用户显式操作；保存前允许调整
3. **坐标质量依赖地区库**：起终点坐标来自 `biz_region.longitude/latitude`（由平台 `sys_regions` 高德行政区同步或回填脚本维护）

### 与其他模块的关系

```
┌─────────────────┐     ┌──────────────────┐
│  基础数据-地区库  │────►│  biz_region       │
│  (经纬度)        │     │  longitude/lat    │
└─────────────────┘     └────────┬─────────┘
                                 │
                    ┌────────────▼────────────┐
                    │  线路管理 biz_route      │
                    │  distance / estimated_h  │
                    └────────────┬────────────┘
                                 │
              ┌──────────────────┼──────────────────┐
              ▼                  ▼                  ▼
    ┌─────────────────┐ ┌───────────────┐ ┌─────────────────┐
    │ 任务段里程联想    │ │ 运价合同       │ │ 运营/结算报表    │
    │ route-distance  │ │ distance_km   │ │ (后续)          │
    └─────────────────┘ └───────────────┘ └─────────────────┘
```

## 三、需求详情

### 3.1 线路列表

- 分页表格：线路名称、起点、终点、里程(km)、预计时长(h)、状态、创建时间
- 搜索：起点/终点关键字（文本模糊）
- 工具栏：新增线路
- 行操作：编辑、启用/停用、删除（软删）

### 3.2 新增/编辑线路

#### 3.2.1 表单字段

| 字段 | 说明 | 规则 |
|------|------|------|
| 线路编码 | 系统生成 | 编辑时只读展示 |
| 线路名称 | 展示名称 | 编辑时可改；新增时后端按起终点路径默认生成 |
| 出发地 | 行政区 | 必填，地区导航级联（`nav-tree`），提交 `originRegionId` |
| 目的地 | 行政区 | 必填，地区导航级联，提交 `destinationRegionId` |
| 里程(km) | 标准公里数 | 选填，数值 ≥ 0，精度 1 位小数 |
| 预计时长(h) | 标准时效 | 选填，数值 ≥ 0，精度 1 位小数 |
| 备注 | 补充说明 | 选填 |

起终点 `(origin_region_id, destination_region_id)` 租户内唯一，重复创建提示错误。

#### 3.2.2 弹窗布局

- 宽度约 1100px（小屏纵向堆叠）
- **左侧**：上述字段 + 高德建议区
- **右侧**：地图容器（高度约 360px），展示出发地、目的地 Marker，`setFitView` 自适应

#### 3.2.3 高德建议流程

1. **高德调用时机（节省配额）**
   - **新增**：起终点均选定且发生变化后，防抖 400ms 自动请求高德
   - **编辑打开**：不自动请求高德；展示已保存里程/时长；地图回显库中 `route_polyline` 折线（无折线时仅标点）
   - **编辑修改起终点**：与新增相同，自动请求高德并重绘折线
   - **编辑未改起终点**：可点击 **「重新获取高德建议」** 手动刷新
2. 后端读取两地 `biz_region` 经纬度，调用高德 [路径规划 2.0 · 驾车](https://lbs.amap.com/api/webservice/guide/api/newroute)：`GET https://restapi.amap.com/v5/direction/driving`，`strategy=34`（高速优先），`show_fields=cost,polyline`
3. 成功时左侧展示：**高德建议：{distanceKm} km / {estimatedHours} h**，并提供按钮 **「采纳建议」**；右侧地图绘制返回的 `polylinePath` 折线
4. 用户点击「采纳建议」→ 将建议值写入「里程」「预计时长」字段（不自动保存）
5. 用户可继续手改里程/时长，点击「保存」提交 `POST/PUT /resource/route`
6. **保存时**若本次会话已有高德折线（采纳后或算路成功），写入 `biz_route.route_polyline`（入库前抽稀至最多约 800 点）

**不自动覆盖**：未点击「采纳建议」时，不修改用户已填写的里程/时长。

#### 3.2.4 地图预览

- 使用前端 JS API Key（`VITE_MAP_KEY`）渲染地图
- 起终点 Marker 与路线 `Polyline` 均来自路径规划接口返回数据
- 路径规划在后端使用 Web 服务 Key（`AMAP_WEB_SERVICE_KEY`），须开通「路径规划 2.0」服务

### 3.3 接口约定

#### 3.3.1 驾车路径建议（实时算路，折线随保存落库）

```
GET /api/client/resource/route/driving-metrics
  ?originRegionId={int}&destinationRegionId={int}
```

响应示例（字段 camelCase）：

```json
{
  "distanceKm": 290.5,
  "estimatedHours": 4.2,
  "origin": {
    "regionId": 1,
    "name": "北京市/市辖区/东城区",
    "longitude": 116.418757,
    "latitude": 39.917544
  },
  "destination": { "regionId": 2, "name": "...", "longitude": 117.2, "latitude": 39.1 },
  "polylinePath": [[116.41, 39.91], [116.50, 39.95]],
  "strategy": 34,
  "source": "amap_v5_driving"
}
```

单位换算：

- 方案 `paths.distance`（米）→ `distanceKm = round(m/1000, 1)`
- 方案 `paths.cost.duration`（秒）→ `estimatedHours = round(s/3600, 1)`
- `polylinePath`：合并各 `step.polyline` 为 `[[lng, lat], ...]` 供前端绘制

算路策略：固定 **34（高速优先）**，写入 `strategy` 字段便于审计。

#### 3.3.2 线路 CRUD（既有）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/client/resource/route` | 分页列表 |
| GET | `/api/client/resource/route/list` | 全量列表 |
| POST | `/api/client/resource/route` | 新增（可选 `routePolyline`） |
| PUT | `/api/client/resource/route/{id}` | 编辑（可选 `routePolyline`；起终点变更且无新折线时清空） |
| DELETE | `/api/client/resource/route/{id}` | 删除 |

列表/详情 `RouteOut` 含 `polylinePath`（由 `route_polyline` 解析）。

### 3.4 异常与边界

| 场景 | 处理 |
|------|------|
| 出发地 = 目的地 | 不请求高德；提示「出发地与目的地不能相同」 |
| 地区无经纬度 | 接口业务错误；提示联系管理员同步行政区或手动填写 |
| 未配置 `AMAP_WEB_SERVICE_KEY` | 后端明确错误 |
| 高德 `status=0` | 返回 `info`/`code` 可读文案（如无道路、境外等） |
| 高德请求失败 | 前端展示错误，仍可手填里程/时长并保存 |
| 编辑已存在线路 | 打开弹窗且起终点齐全时同样可拉取建议（便于改线重算） |

### 3.5 本期不做

- 途经点 `waypoints` 表单维护
- 多条备选路线切换、路况详情展示
- 将高德建议值自动写入数据库（必须用户采纳 + 保存）

## 四、数据表

主表：`biz_route`（租户库），字段含 `origin_region_id`、`destination_region_id`、`distance`、`estimated_hours`、`route_polyline`（驾车折线 JSON）、`waypoints`（途经点预留）等。详见 `doc/03.数据库设计/02.租户业务库数据表/13.biz_route.sql`。

地区坐标：`biz_region.longitude`、`biz_region.latitude`。

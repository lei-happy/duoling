# 企业端基础数据模块 - 地区数据管理

> **所属阶段**：阶段五 - 企业端基础数据模块
>
> **文档状态**：已完成
>
> **优先级**：高（基础数据核心模块）

## 一、功能概述

地区数据管理是基础数据模块的首个子模块，为运单、路线、客户等业务模块提供统一的地区数据源。企业在开户时，系统从平台库（`sys_regions`）同步中国标准行政区划数据至租户库（`biz_region`）；在此基础上，企业可自行添加不在标准库中的自定义地区，以满足个性化业务需求。

核心设计原则：

- **系统数据只读**：从平台库同步的标准行政区划（省/市/区县）为只读数据，企业无法编辑或删除，保证基础数据一致性
- **自定义数据可控**：企业添加的自定义地区支持编辑和删除（软删除），可挂载在任意标准地区下作为子级
- **单表 + 来源标识**：通过 `source` 字段区分数据来源，避免拆表导致的树结构断裂和跨表查询复杂度，同时为后续扩展其他来源（行业标准库等）预留枚举值

## 二、业务背景

### 核心业务诉求

1. **标准地区基础**：物流业务中"发货地"、"收货地"、路线节点等大量引用地区信息，标准行政区划是基础数据保障
2. **企业个性化扩展**：不同企业有自己的业务区域划分（如港口、物流园区、工业区、专线节点），这些地区不在国标库中，需要企业自行维护
3. **数据来源可追溯**：用户需要清楚区分哪些是系统标准数据、哪些是自己添加的数据，避免误操作

### 与其他模块的关系

```
平台库 sys_regions (标准地区源)
        │
        │ 开户时同步 (source=0)
        ▼
┌─────────────────────────┐
│    biz_region (租户库)    │
│  标准地区 (source=0)      │◄──── 只读，不可编辑删除
│  自定义地区 (source=1)    │◄──── 企业自行添加/编辑/删除
└────────┬────────────────┘
         │ 被引用
    ┌────┼────┬────────────┐
    ▼    ▼    ▼            ▼
  运单  路线  客户地址    驾驶员归属地
```

## 三、需求详情

### 3.1 地区数据列表

- 树形表格展示，按层级展开（省 > 市 > 区/县 > 自定义子级）
- 默认展示省级列表，点击展开加载子级（懒加载）
- 列表字段：地区名称、地区代码、层级、来源（Tag 标签）、状态、操作
- 来源区分：
  - 系统数据：蓝色 Tag "系统"，操作列无编辑/删除按钮
  - 自定义数据：绿色 Tag "自定义"，操作列显示编辑/删除按钮
- 搜索：支持按地区名称关键字搜索（搜索时返回扁平列表）
- 工具栏：新增地区

### 3.2 新增地区

弹窗表单：

| 字段 | 说明 | 规则 |
|------|------|------|
| 地区名称 | 自定义地区名称 | 必填，同一父级下不可重名 |
| 上级地区 | 挂载的父级地区 | 选填，树形选择器；为空时创建为顶级地区 |
| 排序号 | 同级内排序 | 默认 0，数值越小越靠前 |
| 状态 | 正常/停用 | 默认正常 |

- 地区代码由后端自动生成（"C" + 日期 + 序号，如 "C20260405001"），不可手动填写
- 层级根据上级地区自动推算（上级层级 + 1，无上级则为 1）
- `source` 自动设为 1（自定义），`created_by` 记录当前用户 ID

### 3.3 编辑地区

- 仅 `source=1` 的自定义地区可编辑
- 可修改：地区名称、上级地区、排序号、状态
- 不可修改：地区代码
- 后端强校验 `source` 值，防止通过 API 修改系统数据

### 3.4 删除地区

- 仅 `source=1` 的自定义地区可删除，执行软删除（`is_deleted=1`）
- 删除前校验：
  - 该地区下有未删除的子地区 → 提示「请先删除子地区」
  - 该地区已被业务模块引用 → 提示「该地区已被使用，无法删除」（预留，当前版本不校验业务引用）

## 四、数据模型设计

### 4.1 数据表变更

表位于租户独立数据库（`zt_biz_{tenant_code}`），`__table_tier__ = "core"`（注册即创建）。

#### biz_region（行政区域表）

### 4.2 自定义地区 code 编码规则

| 类型 | 编码格式 | 示例 | 说明 |
|------|---------|------|------|
| 系统标准地区 | 纯数字（国标行政区划代码） | 110000、110100 | 由平台库同步，不可修改 |

## 五、API 接口设计

所有接口前缀：`/api/client`，需要 JWT 认证（`Authorization: Bearer {token}`）。

### 5.1 地区数据管理

| 方法 | 路径 | 说明 | 状态 |
|------|------|------|------|
| GET | `/basic-data/region/tree` | 获取地区子级列表（懒加载） | **新增** |
| GET | `/basic-data/region/search` | 按名称搜索地区 | **新增** |
| GET | `/basic-data/region/{id}` | 获取单条地区详情 | **新增** |
| POST | `/basic-data/region` | 新增自定义地区 | **新增** |
| PUT | `/basic-data/region/{id}` | 修改自定义地区 | **新增** |
| DELETE | `/basic-data/region/{id}` | 软删除自定义地区 | **新增** |

**树查询参数**（`GET /basic-data/region/tree`）：

| 参数 | 类型 | 说明 |
|------|------|------|
| parentCode | string | 父级区划代码，为空时返回顶级（省份） |

**搜索参数**（`GET /basic-data/region/search`）：

| 参数 | 类型 | 说明 |
|------|------|------|
| name | string | 地区名称关键字（模糊匹配） |
| source | int | 来源筛选 0=系统 1=自定义，不传则全部 |

**创建请求体**（`POST /basic-data/region`）：

```json
{
  "name": "物流园区A",
  "parentCode": "110105",
  "sortOrder": 0,
  "status": 1
}
```

**更新请求体**（`PUT /basic-data/region/{id}`）：

```json
{
  "name": "物流园区A（更名）",
  "parentCode": "110105",
  "sortOrder": 0,
  "status": 1
}
```

**响应字段映射**（后端 → 前端）：

| 后端模型字段 | Schema 输出字段 | 说明 |
|-------------|----------------|------|
| id | regionId | 地区 ID |
| code | code | 地区代码 |
| name | name | 地区名称 |
| parent_code | parentCode | 上级代码 |
| level | level | 层级 |
| sort_order | sortOrder | 排序号 |
| status | status | 状态 |
| source | source | 来源 0=系统 1=自定义 |
| created_by | createdBy | 创建人 ID |
| created_at | createTime | 创建时间 |
| — (子查询) | hasChildren | 是否有子级（懒加载需要） |

## 六、前端页面设计

### 6.1 地区数据管理页

- **路由**：`/basic_data/regional_data`（由 Console 下发菜单动态生成）
- **组件**：`views/basic_data/regional_data/index.vue`
- **子组件**：
  - `region-search.vue`：搜索栏（地区名称）
  - `region-edit.vue`：新增/编辑弹窗

**页面交互**：

- 树形表格，`row-key` 为 `regionId`，懒加载子级
- 表格列：地区名称、地区代码、层级（数值）、来源（Tag 标签）、状态（Tag 标签）、操作
- 来源列：`source=0` 显示蓝色 Tag "系统"，`source=1` 显示绿色 Tag "自定义"
- 操作列：系统数据无按钮；自定义数据显示「编辑」「删除」
- 工具栏：新增按钮（创建自定义地区）
- 搜索时切换为扁平列表展示搜索结果；清空搜索恢复树形展示
- 每行"新增子级"按钮，点击后打开弹窗并预选当前行作为上级地区

### 6.2 菜单层级

```
基础数据
└── 地区数据    /basic_data/regional_data
```

### 6.3 前后端字段适配

前端 TypeScript 模型使用小驼峰命名（`regionId`、`parentCode`），后端 ORM 使用下划线命名（`parent_code`、`sort_order`）。在后端 Schema 层的 `from_model()` 方法中做映射转换，与项目现有模式一致。

## 八、测试要点

### 8.1 地区数据展示

1. 首次加载显示省级列表（约 34 条），来源均为"系统"蓝色 Tag
2. 展开省份显示城市列表，展开城市显示区县列表，层级和父子关系正确
3. 系统数据行操作列无编辑/删除按钮

### 8.2 新增自定义地区

1. 新增顶级自定义地区（无上级），验证层级为 1
2. 新增某标准区县的子级自定义地区，验证层级为 4
3. 验证地区代码自动生成（"C" 开头）
4. 验证同一父级下名称重复校验
5. 新增后列表正确刷新，来源显示"自定义"绿色 Tag

### 8.3 编辑自定义地区

1. 编辑自定义地区的名称、排序号、状态，验证数据正确更新
2. 验证不可编辑系统地区（按钮不显示 + API 层拦截）
3. 验证不可修改地区代码

### 8.4 删除自定义地区

1. 删除无子级的自定义地区，验证软删除（`is_deleted=1`），列表中不再展示
2. 删除有子级的自定义地区，验证拦截提示
3. 验证不可删除系统地区（按钮不显示 + API 层拦截）

### 8.5 搜索

1. 按名称搜索标准地区（如"北京"），验证返回结果包含名称匹配的地区
2. 按名称搜索自定义地区，验证结果正确
3. 清空搜索后恢复树形展示

## 一、市场背景

### 1.1 为什么 20 台以上自有车队强需求「车辆资产」能力

| 痛点 | 无系统时 | 业务后果 |
|------|---------|---------|
| 保险/年检到期无人盯 | Excel、微信群 | 罚款、停运、拒赔风险 |
| 保养靠经验 | 「感觉该保了」 | 大修与趴窝 |
| 维修记录散落 | 发票夹、聊天记录 | 单车成本算不清 |
| 调度不知车能否派 | 口头同步 | 误派、时效违约 |
| 经营账缺养车成本 | 毛利只减任务支出 | 决策偏乐观 |

行业共识：**档案 + 到期提醒 + 维保台账 + 费用分析** 是标配；与 **TMS 派单状态联动**、把资产成本纳入经营分析，是综合物流系统的差异化空间。

### 1.2 产品形态对照

| 形态 | 代表 | 相对我们 |
|------|------|---------|
| 纯管车 SaaS | 至简管车、车队管家、泛普等 | 车务细，但难进运单利润账 |
| 车联网 + AI | G7、Samsara、Motive | 硬件重；工单/OOS 可借鉴 |
| TMS 内嵌 | 本产品方向 | 原生联动运力；资产成本可进经营分析 |

## 二、目标客户

| 细分 | 诉求 | 版本 |
|------|------|------|
| 自有 20～80 台专线/城配 | 别漏检、修完同步调度 | standard → pro |
| 80～500 台车队 | 单车成本、计划保养 | 直签或升 pro |
| 轻资产外协为主 | 合规建档即可 | 标准版证照监控为主，非维保刚需 |
| 承运商上报 | 完成上报 | lite |

## 三、竞品能力矩阵（摘要）

国内管车软件普遍具备：提醒、维修记录、保养、费用；配件/轮胎为加厚层。  
国际 Samsara / Motive：预防性保养、工单、Out of Service。  
公开材料中，**「维修中自动不可派单 + 资产成本进同一套 TMS 利润」** 很少作为一等公民——这是我们应赢的点。

详见初版桌面调研结论；取舍不变：

| 优先级 | 能力 | 归属 |
|--------|------|------|
| P0 | 证照到期监控 | 车辆资产 · 证照监控（standard+pro） |
| P0 | 维修工单 + 运力联动 | 车辆资产 · 维修保养（pro） |
| P0 | 保养计划与提醒 | 维修保养（pro） |
| P1 | 保险/年检台账、资产卡片/折旧、单车资产成本 | 资产成本（pro） |
| P2 | 事故、配件、司机报修、利润分析对接 | 三期 |

## 四、差异化结论

1. **运力状态联动**（原生 TMS）  
2. **证照与维保同入口、不同 feature**——标准版保合规，专业版做闭环与成本  
3. **固定资产在线化**——补齐业务运营成本之外的资产成本，服务老板/财务  
4. **不做成独立管车 SaaS**——不绑硬件、不做重 CMMS/总账  

> 一句话：标配提醒与工单要做扎实；用 **联动 + 资产成本进经营账** 拉开专业版与标准版差距。

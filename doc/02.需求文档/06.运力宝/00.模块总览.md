## 一、产品定位与设计目标

### 1.1 定位

运力宝不是把综合业务系统"砍功能"得到的阉割版，而是**从客户痛点切入的独立小产品**：

- 综合业务系统（standard / pro）的实施门槛高——要先把客户、合同、车辆、驾驶员、运力等基础数据维护齐全，业务才能流转。
- 运力宝**只解决两件事**：①车辆/驾驶员资质档案与到期监控；②外协（社会/承运商）运力建档。客户开箱即用、当天见效。
- 客户在用运力宝沉淀的运力数据，未来升级到综合系统时**可直接复用、零迁移**。

> 一句话定位：**"先把运力管起来、把证照看住"的入口级产品，是综合业务系统的获客与数据沉淀前哨。**

### 1.2 设计目标

| # | 目标 | 落点 |
|---|------|------|
| 1 | **独立可售**：作为平行版本独立开通、独立计费 | 新增 `version_code = ylb`，与 lite/standard/pro 平级 |
| 2 | **小而美、低门槛**：聚焦运力建档 + 证照监控，不绑大而全的业务流 | feature 清单只含底座 + 运力域 + `fleet_compliance` |
| 3 | **核心差异化能力**：资质到期主动提醒 | 独立的"证照监控引擎"（worker），见 `02` |
| 4 | **数据可复用、可叠加升级**：升级到 standard/pro 数据不迁移 | 复用同一租户业务库 + feature 叠加授权 + 增量建表 |
| 5 | **不拖累 API 性能**：到期扫描独立进程跑 | 仿运费计算引擎，独立 `backend-compliance-worker` 容器 |
| 6 | **商业化闭环**：功能买了才能用、配额买了才够用 | `require_feature` 功能门控 + `QuotaService` 配额校验，见 `04` |

### 1.3 不在本期范围

| 不做 | 原因 | 未来路径 |
|------|------|---------|
| 短信/钉钉/企微到期推送通知 | 本期先做站内看板与列表预警，闭环最小可用 | 复用通知中心 + worker 命中后投递 |
| 证照影像 OCR 自动识别到期日 | 依赖 OCR 能力与字段映射 | 远期接入 AI 数字员工 OCR |
| 承运商运力的完整准入审批流 | 本期建档默认直通（approval_status=2 已通过） | 升级到 standard/pro 走审批中心 |
| 运力宝独立 App / 小程序 | 本期聚焦企业端 Web | 引擎与端无关，远期复用 |

## 二、版本矩阵与 feature 边界

### 2.1 版本矩阵（`sys_product_version`）

| version_code | 版本名 | 定位 | max_users | max_vehicles | 价格 | 与 ylb 关系 |
|---|---|---|---|---|---|---|
| `lite` | 轻量版 | 承运商邀请激活专用（被上游邀请上报运力） | 5 | 20 | 免费 | **平行**，互不替代 |
| **`ylb`** | **运力宝** | **车队自用：运力建档 + 证照监控** | **10** | **50** | **999/年** | **本产品** |
| `standard` | 标准版 | 中型车队综合业务 | 20 | 100 | 2999/年 | ylb 可叠加升级 |
| `pro` | 专业版 | 大型车队 + 数据分析/结算 | 100 | 500 | 9999/年 | ylb 可叠加升级 |

> 事实源：`backend/scripts/platform_sync/snapshots/product_version.json`

### 2.2 ylb 的 feature 清单（`version_feature.json` → `ylb`）

ylb = **底座** + **基础数据** + **运力域全量** + **证照监控**：

| 分组 | feature_code | 说明 |
|------|--------------|------|
| 底座 | `base_dashboard` `base_log` `base_config` `base_dict` `base_organization` `base_role` `base_system` `base_user` `log_center` | 组织/账号/角色/字典/日志等共用底座 |
| 基础数据 | `basic_data` `basic_data_region` `basic_data_vehicle_brand_series` | 地区、品牌车系 |
| 运力中心 | `capacity_center` | 一级目录 |
| 自有运力 | `capacity_self` `capacity_self_list` `capacity_self_driver` `capacity_self_vehicle` `capacity_self_trailer` `capacity_self_log` | 自有车/司机/挂车建档 |
| 社会运力 | `capacity_social` `capacity_social_list` `capacity_social_approval` | 社会运力池 |
| 承运商运力 | `capacity_carrier` `capacity_carrier_list` `capacity_carrier_approval` | 外协承运商运力建档（见 `03`） |
| **证照监控** | **`fleet_compliance`** | **运力宝核心差异化能力（见 `02`）** |

> 事实源：`backend/scripts/platform_sync/snapshots/version_feature.json`

### 2.3 `fleet_compliance` 在各版本的归属

证照监控不是 ylb 独占——综合版客户同样需要：

| 版本 | 含 `fleet_compliance` | 说明 |
|------|----------------------|------|
| `lite` | ✗ | 承运商基础版不含 |
| `ylb` | ✓ | 核心卖点 |
| `standard` | ✓ | 综合版同样纳入证照监控 |
| `pro` | ✓ | 同上 |

## 三、叠加升级路径（ylb → standard / pro）

升级是**纯叠加**，不是替换：

```mermaid
flowchart LR
    A["客户开通 ylb<br/>运力建档 + 证照监控"] -->|"沉淀运力/证照数据"| B["叠加授权 standard/pro"]
    B --> C["feature 取并集<br/>运力数据原样保留"]
    C --> D["runner 幂等增量建表<br/>补齐业务表 仅新增"]
    D --> E["综合业务系统可用<br/>零数据迁移"]
```

关键保证：

- **同一租户业务库**：ylb 与 standard/pro 共用 `zt_biz_{tenant}` 库，升级不换库、不导数据。
- **feature 叠加授权**：`sys_tenant_product` 可并行持有多条有效版本记录，最终 feature 取并集；配额取各版本 `max_*` 的最大值（见 `04`）。
- **增量建表幂等**：升级后由租户迁移 runner 按新 feature 的 `required_tables` 补建缺失业务表，已存在表/列自动跳过（见 `05`）。

## 四、菜单与权限

| 一级菜单 | 二级菜单 | 路径 | feature_code | 现状 |
|---------|---------|------|--------------|------|
| 运力中心 | 自有运力 / 社会运力 / 承运商运力 | `/capacity/...` | `capacity_*` | 已实现 |
| 运力中心 | 证照监控 | `/capacity/compliance` | `fleet_compliance` | ylb v1 实现 |

> ⚠️ **菜单可见性注意**：证照监控菜单（`sys_menu` 中 `feature_code = fleet_compliance`）历史上以"未实现占位"身份 `visible=0` 入库；`seed_client_menus` 为 preserve-ui 模式不会翻转既有 `visible`。存量环境需一次性执行 `python -m scripts.fix.show_ylb_menus` 置为可见（详见 `05`）。

API 侧所有运力域与证照接口均加了功能守卫 `Depends(require_feature(...))`，未开通对应 feature 的租户即使绕过菜单也会被 403 拦截（fail-closed，见 `04`）。

## 五、术语表

| 术语 | 含义 |
|------|------|
| 运力宝 / ylb | 本产品代号，平行版本之一 |
| 证照监控引擎 | 周期扫描各类运力资质到期字段、生成预警的独立 worker |
| 预警（Alert） | `biz_compliance_alert` 中一条"某主体某证照的最新到期状态"记录 |
| 主体类型（subject_type） | 预警主体：自有司机/车辆、社会运力司机/车辆、承运商运力司机/车辆 |
| 证照类型（doc_type） | 驾驶证 / 从业资格证 / 保险 / 年检 / 道路运输证 |
| 预警级别（level） | expired(已过期) / critical(临界) / warning(预警) |
| 处理状态（status） | open(待处理) / dismissed(已忽略) / resolved(已消除) |
| 承运商运力建档 | 把外协承运商的车/司机及其证照存档（`biz_carrier_capacity` 三表） |
| 功能守卫（require_feature） | API 级 fail-closed 功能门控 |
| 配额校验（QuotaService） | 创建车辆/员工前按版本 `max_*` 上限拦截 |
| 叠加升级 | ylb 客户加购 standard/pro，feature 取并集、数据零迁移 |

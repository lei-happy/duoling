# 运力宝 - 承运商运力建档技术设计

> 关联：[00.模块总览](00.模块总览.md) · [02.证照监控引擎技术设计](02.证照监控引擎技术设计.md) · [资源管理模块/03.社会运力池](../02.企业端/02.资源管理模块/03.社会运力池.md)

承运商运力 = 挂在某个**承运商档案 `biz_carrier`** 名下的"车 + 人 + 证照"单元。与"社会运力"对称建模，区别在于主表多一个 `carrier_id` 归属维度。

## 一、为什么需要这个模块

- 社会运力池解决的是"散户车/人"建档；而很多车队的外协是**走承运商（公司）**承运的，需要按承运商归集其名下的车/人/证照。
- 运力宝要"把外协运力管起来"，必须覆盖**承运商维度**的运力建档，并纳入证照监控。

## 二、与社会运力的对照

采用与社会运力一致的"主表 + 车子表 + 人子表"三表结构，保证字段命名一致、监控逻辑可复用：

| 维度 | 社会运力 | 承运商运力 |
|------|---------|-----------|
| 主表 | `biz_social_capacity` | `biz_carrier_capacity` |
| 车子表 | `biz_social_capacity_vehicle` | `biz_carrier_capacity_vehicle` |
| 人子表 | `biz_social_capacity_driver` | `biz_carrier_capacity_driver` |
| 归属维度 | 无 | **`carrier_id` → `biz_carrier`** |
| feature | `capacity_social_*` | `capacity_carrier_*` |
| 监控主体类型 | `social_driver` / `social_vehicle` | `carrier_driver` / `carrier_vehicle` |

> 首版定位：录入 + 证照监控 + 调度可选。为简化，创建即生效（`approval_status=2 已通过` / `status=1 正常`），**审批流作为后续增强对接审批中心**（`capacity_carrier_approval` + 审批引擎）。

## 三、数据模型（三表）

> 目录：`backend/app/modules/client/models/capacity/carrier_capacity/`
> 表级：均为 `__table_tier__ = "business"`，由 `capacity_carrier_list` 的 `required_tables` 自动建表

### 3.1 主表 `biz_carrier_capacity`

| 字段 | 说明 |
|------|------|
| `carrier_capacity_code` | 承运商运力编号 `C{YYYY}{NNNNN}`，唯一 |
| `carrier_id` / `carrier_name` | 归属承运商（`biz_carrier.id`）+ 名称冗余快照 |
| `driver_name` / `driver_phone` / `driver_id_card` | 司机姓名/手机/身份证（冗余检索，手机号做唯一性校验） |
| `plate_number` / `vehicle_type_label` | 车牌号（冗余检索 + 唯一性）+ 车型快照 |
| `source` / `source_remark` | 来源（代录入 / 自报 等）+ 备注 |
| `approval_status` / `approval_user_id` / `approval_time` / `approval_remark` / `approval_instance_id` | 审核状态机（首版默认已通过；`approval_instance_id` 预留审批中心回写） |
| `status` / `status_remark` | 启用状态 0未生效/1正常/2停用/3黑名单 |
| `rating_*` / `order_count` / `last_dispatched_at` / `evaluation_summary` | 考核评级与调度统计（预留字段） |
| `created_user_id` / `updated_user_id` / `remark` | 审计与备注 |

索引：`carrier_capacity_code`(唯一)、`carrier_id`、`driver_phone`、`plate_number`、`status`。

### 3.2 车子表 `biz_carrier_capacity_vehicle` / 人子表 `biz_carrier_capacity_driver`

与社会运力同名子表对齐，1:1 挂在主表 `carrier_capacity_id` 下，承载车辆/司机明细与**证照到期字段**：

- 车：`inspection_expire`（年检）、`insurance_expire`（保险）、`transport_license_no/transport_license_expire`（道路运输证）等。
- 人：`license_no/license_expire`（驾驶证）、`qualification_no/qualification_expire`（从业资格证）等。

这些到期字段正是证照监控引擎扫描的输入（见 `02` §三）。

## 四、API

> 路由前缀：`/capacity/carrier_capacity/list`，守卫：`Depends(require_feature("capacity_carrier_list"))`
> 文件：`backend/app/modules/client/api/capacity/carrier_capacity/list.py`

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/capacity/carrier_capacity/list` | 分页（keyword / carrierId / status） |
| GET | `/capacity/carrier_capacity/list/{cc_id}` | 详情（主表 + 车 + 人） |
| POST | `/capacity/carrier_capacity/list` | 新建（校验承运商存在、手机/车牌唯一） |
| PUT | `/capacity/carrier_capacity/list/{cc_id}` | 编辑 |
| PUT | `/capacity/carrier_capacity/list/{cc_id}/status` | 状态变更（停用/黑名单等） |
| DELETE | `/capacity/carrier_capacity/list/{cc_id}` | 删除（软删） |

路由级 `_ensure_cc_tables` 依赖：老租户库首次访问时幂等补建三张表，不依赖部署顺序。

服务：`backend/app/modules/client/services/capacity/carrier_capacity/carrier_capacity_service.py`（编号生成、承运商校验、唯一性校验、CRUD、状态变更）。

## 五、前端

> 目录：`frontend/client/src/views/capacity/carrier-capacity/`
> API：`frontend/client/src/api/capacity/carrier-capacity/`

- 列表页：搜索（承运商、状态、关键字）+ 数据表 + 编辑弹窗。
- 编辑弹窗：承运商远程搜索（`biz_carrier`）+ 司机信息 + 车辆信息（含各类证照到期日）。

## 六、与证照监控的衔接

承运商运力录入后，证照到期由证照监控引擎统一扫描（`_scan_carrier_drivers` / `_scan_carrier_vehicles`），生成 `carrier_driver` / `carrier_vehicle` 主体的预警，无需本模块额外处理。详见 [02.证照监控引擎技术设计](02.证照监控引擎技术设计.md)。

## 七、后续增强

| 项 | 说明 |
|---|------|
| 准入审批 | 升级版接入审批中心，`approval_status` 走 `capacity_carrier_approval` + 审批引擎实例 |
| 考核评级 | 启用 `rating_*` 字段，按承运次数/时效/异常打分 |
| 调度联动 | `order_count` / `last_dispatched_at` 与运营调度模块打通 |

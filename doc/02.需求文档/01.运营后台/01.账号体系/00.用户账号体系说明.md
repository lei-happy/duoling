# 用户账号体系说明

> **所属阶段**：跨阶段（平台底座 + 企业端员工管理）
>
> **文档状态**：已完成
>
> **优先级**：高（登录、多租户、员工同步的设计依据）

## 一、功能概述

本文档说明智图 SaaS 中**平台用户**与**企业（租户）**之间的关系，以及登录凭证（账号、密码、手机号）在**全平台范围内**的唯一性与一致性原则。该体系支撑：

- 运营后台（Console）平台管理员登录
- 客户端（Client）企业员工登录（含多企业选择）
- 企业端员工管理与「租户员工 ↔ 平台账号」同步（路线 A：`biz_user` 与 `sys_user` / `sys_user_tenant` 联动）

## 二、业务背景

系统采用 **SaaS 多租户架构**：

- **平台库**维护全局可登录账号（`sys_user`）及用户与企业的关联（`sys_user_tenant`）。
- **租户库**维护企业内业务视角的员工（`biz_user`）、部门、角色等。

客户端登录接口仅认证 **平台库**中的 `sys_user`（见 `AuthService.client_login`），因此任意能在客户端登录的自然人，在平台侧必须对应**一条**平台用户记录；同一自然人在多个企业任职时，通过多条 `sys_user_tenant` 关联实现「一号多企业」，而不是在平台侧复制多条 `sys_user`。

## 三、核心设计原则

### 3.1 一个用户 = 一个平台用户 ID（全平台唯一）

- 自然人（或一个可登录主体）在平台侧对应 **`sys_user` 表中的一条记录**，主键 `id` **全平台唯一**。
- 该用户加入多个企业时，不为其在每个企业再创建新的 `sys_user`，而是通过 **`sys_user_tenant`** 增加「用户 + 企业编码」关联行。
- 企业端员工表 **`biz_user`** 描述的是**租户内**的人事与权限视角；通过员工管理流程与平台账号同步后，仍指向上述**同一个** `sys_user.id`（或与之绑定的同一登录身份）。

### 3.2 一个用户 = 一个密码（与租户数量无关）

- 登录密码存储在 **`sys_user.password`**（哈希），**不按租户拆分**。
- **任意租户**的管理员在企业端对该用户执行**重置密码**时，修改的是**同一条** `sys_user` 上的密码。
- **原则**：无论该用户关联了几个租户，**全平台仅有一份密码**；在租户 A 重置后，使用该账号登录租户 B、租户 C 时，**必须使用新密码**。
- 产品提示建议（前端/文案）：重置密码成功时，可提示「该账号在全部已关联企业中均使用新密码登录」，避免运营或企业管理员误解为「仅本企业生效」。

### 3.3 手机号（当前与后续规划）

- 当前模型中 **`sys_user.phone` 在平台侧唯一**，常用于开租户时识别「是否已有平台账号」并复用 `sys_user`，避免重复造号。
- **后续能力（规划）**：支持用户在合规校验（验证码、权限）前提下**变更手机号**。变更后仍应对应**同一条** `sys_user`（同一 `id`），并同步更新各业务触点可见的联系方式；具体流程、风控与审计要求在「手机号变更」专项需求中展开，本文档仅锁定**账号主键不变、仍为一用户一密码**的前提。

## 四、与客户端员工管理（路线 A）的关系

企业端新建/维护员工时，在平台侧创建或更新 **`sys_user` + `sys_user_tenant`**，并与租户库 **`biz_user`** 保持一致（密码哈希一致、状态按规则映射等）。在此前提下：

- 员工在**任一**关联租户内被**重置密码**，均更新**同一** `sys_user.password`，与 **3.2** 一致。
- 若同一手机号已存在平台用户，则**复用**该 `sys_user` 并新增/恢复 `sys_user_tenant`；此时仍只有**一份**密码，需与产品规则（如用户名与手机号是否必须一致）在界面层说明清楚。

## 五、数据关系简表（逻辑）

| 概念 | 主要载体 | 说明 |
|------|-----------|------|
| 平台登录账号 | `sys_user` | 全平台唯一用户 ID；全局唯一用户名；手机号平台唯一 |
| 用户与企业的关系 | `sys_user_tenant` | 同一 `user_id` 可对应多条，每条一个 `tenant_code` |
| 租户内员工 | `biz_user` | 租户内人事与角色；与平台账号通过同步策略对齐 |
| 密码 | `sys_user.password` | 全平台唯一一份，与租户数量无关 |

## 六、非目标（本文档不展开）

- 客户端菜单与 `sys_role` / `biz_role` 的镜像细节（见企业端基础模块与开发实现）。
- 手机号变更功能的页面流程、接口与安全策略（见后续专项需求）。

## 七、测试要点（账号体系相关）

1. 同一 `sys_user` 关联租户 A、B：在租户 A 重置密码后，使用新密码应能在租户 B 完成登录（在 `UserTenant` 均为有效状态的前提下）。
2. 新建员工后，平台库存在对应或可复用的 `sys_user` 与正确的 `sys_user_tenant`。
3. 后续上线「变更手机号」后：变更前后 `user_id` 不变，密码策略仍符合 **3.2**。

# 意见反馈（Client 提交 + Console 处理）

> 状态：设计稿 · 联动 Console 运营后台「用户之声 / 意见反馈」与 Client 企业客户端 · 复用既有 `sys_feedback` 表扩展实现

## 1. 背景与目标

平台库已预留 `sys_feedback`（意见反馈）表与 ORM，Console 菜单「用户之声 → 意见反馈」已配置，但页面为租户列表占位，后端 API 与租户端入口均未实现。租户用户缺少便捷的产品反馈通道，运营侧也无法受理与回复。

本次需求目标：

1. **Client 提交**：租户端提供随处可达的提交入口，支持类型、标题、内容、截图与联系电话。
2. **Client 进度**：用户可查看本人（管理员可看本租户）反馈的处理状态与官方回复。
3. **Console 处理**：运营在「用户之声 / 意见反馈」中筛选、查看并更新状态与回复。

设计原则：**复用 `sys_feedback`，不新建重复表**；数据归属平台库；Client 经登录态读写平台库（对齐 Changelog / Banner）。

## 2. 方案决策

| 方案点 | 决策 | 理由 |
|---|---|---|
| 内容载体 | 复用并扩展 `sys_feedback` | 表与状态枚举已预留，避免双份维护 |
| 数据归属 | 平台库 `zt_platform` | 跨租户汇总，Console 直接处理；Client 用 `get_platform_db` |
| Client 入口 | 顶栏图标（快捷提交）+ 用户下拉「意见反馈」列表页 | 提交便捷 + 进度可查；不依赖 client 菜单 / feature |
| 数据范围 | 普通用户仅本人；企业管理员（`user_type=1`）本租户全部 | 兼顾隐私与管理员统筹 |
| 提交后编辑 | 一期不支持用户改稿/撤回 | 降低状态冲突；运营侧可改状态并回复 |
| 功能码 | 不挂 `feature_code` | 全租户可用，与顶栏 Changelog 一致 |
| 一期边界 | 仅「意见反馈」；版本评价 / 路线图仍占位 | 控制范围 |

## 3. 数据表设计（平台库）

### 3.1 `sys_feedback` — 意见反馈表（既有 + 本次扩展）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | BIGINT | PK | 主键 |
| tenant_code | VARCHAR(32) | NULL, indexed | 租户编码 |
| user_id | BIGINT | NOT NULL | 反馈用户 ID |
| **user_name** | **VARCHAR(64)** | **NULL** | **提交时昵称快照（本次新增）** |
| **contact_phone** | **VARCHAR(20)** | **NULL** | **联系电话（本次新增）** |
| title | VARCHAR(200) | NOT NULL | 反馈标题 |
| content | TEXT | NOT NULL | 反馈内容 |
| feedback_type | SMALLINT | NOT NULL | 0-建议 1-缺陷 2-投诉 3-其他 |
| status | SMALLINT | NOT NULL | 0-待处理 1-处理中 2-已解决 3-已关闭 |
| reply | TEXT | NULL | 平台回复 |
| images | TEXT | NULL | 截图 URL 列表（JSON 数组） |
| **handler_id** | **BIGINT** | **NULL** | **处理人平台用户 ID（本次新增）** |
| **handler_name** | **VARCHAR(64)** | **NULL** | **处理人姓名快照（本次新增）** |
| **replied_at** | **DATETIME** | **NULL** | **最近回复时间（本次新增）** |
| created_at / updated_at / is_deleted | | | 平台基类标准字段 |

枚举：

- `FeedbackStatusEnum`：PENDING=0 / PROCESSING=1 / RESOLVED=2 / CLOSED=3
- `FeedbackTypeEnum`：SUGGESTION=0 / BUG=1 / COMPLAINT=2 / OTHER=3

运营侧状态允许灵活调整，一期不做硬状态机校验。`images` 示例：`["/uploads/feedback/xxx.png"]`。

## 4. API 设计

### 4.1 Client `/api/client/feedback`

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `` | 提交反馈（写入 tenant_code / user_id / user_name，status=待处理） |
| GET | `` | 分页列表（按角色 scope；支持 status / feedback_type / keyword） |
| GET | `/{id}` | 详情（越权返回「找不到这条反馈」） |

鉴权：登录态；库：`get_platform_db`；不挂 `require_feature`。

列表 scope：

- `user_type == 1`（企业管理员）：`tenant_code = 当前租户`
- 其他：`user_id = 当前用户` 且同租户

### 4.2 Console `/api/console/feedback`

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `` | 全量分页 + 筛选（关键词 / 状态 / 类型 / 租户 / 时间范围） |
| GET | `/{id}` | 详情（含租户名称） |
| PUT | `/{id}/handle` | 更新 status + reply；写 handler；reply 非空时刷新 replied_at |

### 4.3 上传

`ALLOWED_SCENES` 增加 `feedback`；Client 使用 `/api/client/file/upload`，单张 ≤5MB，最多 5 张。

## 5. 前端方案

### 5.1 Client

1. **顶栏** `header-feedback.vue`：图标打开提交抽屉；底部链到「查看我的反馈」。
2. **用户下拉**：新增「意见反馈」→ 静态路由 `/user/feedback`。
3. **我的反馈页**：列表（类型 / 状态 / 标题 / 时间 / 是否有回复）+「我要反馈」+ 详情抽屉（内容、截图、状态、回复、处理人）。
4. **提交表单**（共用）：类型、标题、内容、截图（≤5）、联系电话（默认当前手机号）。

文案：loading「正在提交反馈，请稍候…」；成功「反馈已提交，我们会尽快处理」；失败「提交失败，请稍后重试」。

### 5.2 Console

替换 `views/customer_voice/feedback` 占位页：

- `ele-page` + 搜索 + `ele-pro-table`
- 列：租户、提交人、手机、类型、标题、状态、提交时间、是否已回复、处理
- 处理抽屉：只读原文/截图；可写状态与回复；成功提示「已更新处理结果」

菜单复用既有「意见反馈」，无需 platform_sync 新增。

# 产品版本升级说明（Console 撰写 + Client 展示 + 关键版本强制弹框）

> 状态：设计稿 · 联动 Console 运营后台与 Client 企业客户端 · 复用既有 `changelog` 模块扩展实现

## 1. 背景与目标

平台已存在 `changelog`（产品更新日志）模块：Console 端「产品管理 / 更新记录」可撰写版本号、更新标题、更新内容（Markdown）、发布日期，官网（website）通过公开接口展示。但该内容此前**未面向租户端登录用户展示**，用户无法在系统内感知产品迭代。

本次需求目标：

1. **Console 撰写**：运营/产品在后台针对每次产品更新撰写版本号、升级说明（复用现有更新记录页面，增强能力）。
2. **Client 展示**：租户端（企业客户端）增加查看版本升级记录的入口，方便用户查看历次更新内容，提升体验。
3. **关键版本强制弹框**：创建升级说明时可勾选「弹框提醒」。开启后，租户端用户打开系统即**强制弹框**查看该说明；**用户看过后按用户维度记录已读，下次不再弹出**，减少打扰。

设计原则：**复用 `changelog` 模块，不新建重复表/模块**。仅在配置表增加「是否弹框」标志位，并新增「用户已读」记录表支撑“只弹一次”。

## 2. 方案决策

| 方案点 | 决策 | 理由 |
|---|---|---|
| 内容载体 | 复用 `sys_changelog` | 已有版本号/标题/内容(Markdown)/发布日期/状态，避免双份维护 |
| 弹框开关 | `sys_changelog` 增列 `is_popup` | 单字段即可表达“关键版本强提醒” |
| 已读记录 | 新增 `sys_changelog_read` | 按用户维度记录，实现“看过后不再弹” |
| 数据归属 | 平台库 `zt_platform` | 版本说明全平台统一，Console 直接 CRUD；Client 带登录态读平台库（与 Banner 一致） |
| Client 入口 | 顶栏全局图标 + 抽屉 | 全租户随处可达，不受产品版本 feature 裁剪影响，无需新增 client 菜单 |
| Client 弹框 | 登录进入系统时自动拉取未读弹框项 | 满足“打开系统强制弹框” |

## 3. 数据表设计（平台库，`sys_` 前缀）

### 3.1 `sys_changelog` — 产品更新日志表（既有，本次新增 1 列）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | BIGINT | PK | 主键 |
| version | VARCHAR(50) | NOT NULL | 版本号（如 v1.2.0） |
| title | VARCHAR(200) | NOT NULL | 更新标题 |
| content | TEXT | NULL | 更新内容（Markdown） |
| release_date | DATE | NOT NULL | 发布日期 |
| sort_order | SMALLINT | default 0 | 排序号（越大越靠前） |
| status | SMALLINT | default 1 | 状态 0-停用 1-已发布 |
| **is_popup** | **SMALLINT** | **NOT NULL, default 0** | **租户端是否弹框强提醒 0-否 1-是（本次新增）** |
| created_at / updated_at / is_deleted | | | 平台基类标准字段 |

### 3.2 `sys_changelog_read` — 用户已读记录表（本次新增）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | BIGINT | PK | 主键 |
| changelog_id | BIGINT | NOT NULL | 更新记录 ID |
| tenant_code | VARCHAR(32) | NULL | 租户编码（冗余，便于统计） |
| user_id | BIGINT | NOT NULL | 用户 ID |
| read_at | DATETIME | NOT NULL | 已读时间 |
| created_at / updated_at / is_deleted | | | 平台基类标准字段 |

唯一索引：`uk_changelog_user (changelog_id, user_id)` —— 保证同一用户对同一版本说明只记一条，天然幂等。

**弹框判定（Client）**：`status=1` 且 `is_deleted=0` 且 `is_popup=1` 且 当前 `user_id` 在 `sys_changelog_read` 中无对应记录 → 需要弹框。

## 4. API 设计

### 4.1 Console `/api/console/changelog`（既有，Schema 扩展 `is_popup`）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `` | 分页查询（status 过滤） |
| GET | `/{id}` | 详情 |
| POST | `` | 新建（可传 `is_popup`） |
| PUT | `/{id}` | 更新（可改 `is_popup`） |
| DELETE | `/{id}` | 软删除 |

### 4.2 Client `/api/client/workbench/changelog`（本次新增）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `` | 已发布版本升级说明分页列表（查看历史更新） |
| GET | `/popup` | 当前用户未读、需强制弹框的说明列表 |
| POST | `/read` | 标记 `{ changelog_ids: [] }` 为已读，下次不再弹框 |

鉴权：均需登录态（`get_current_user`），服务端从 Token 取 `user_id / tenant_code`。数据库使用平台库 Session（`get_platform_db`）。未挂 `require_feature`，保证全部租户可见。

## 5. 前端方案

### 5.1 Console：更新记录页 `views/product/changelog`

- 编辑弹窗新增「弹框提醒」开关（`is_popup`），并附文案说明其效果。
- 列表新增「弹框提醒」列（`弹框 / 否` 标签）。
- 其余能力（版本号、标题、发布日期、排序、状态、Markdown 内容）保持不变。

### 5.2 Client：顶栏「版本升级说明」入口 `layout/components/header-changelog.vue`

- 顶栏图标（`Promotion`）+ 未读弹框角标；点击打开右侧抽屉，用时间线展示历次已发布更新（Markdown 渲染，复用 `ByteMdViewer`）。
- **进入系统自动弹框**：组件 `onMounted` 调 `GET /workbench/changelog/popup`，若有未读弹框项则弹出对话框，多条时支持“下一条 / 我知道了”翻阅。
- **已读即不再弹**：对话框关闭（点“我知道了”或关闭按钮）即调用 `POST /workbench/changelog/read` 标记全部弹框项已读；失败为 best-effort，不影响使用。
- 弹框不可点击遮罩/ESC 关闭，保证关键说明被看到。

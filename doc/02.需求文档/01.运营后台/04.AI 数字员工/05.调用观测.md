# 运营后台 - 调用观测

> 父文档：[00.模块总览.md](00.模块总览.md)
>
> 对应代码：`frontend/console/src/views/ai/observe/index.vue` · `backend/app/modules/ai/api/console/observe.py` · `backend/app/modules/ai/services/audit_service.py`

## 一、功能概述

「调用观测」用于运营**跨租户**审计 AI 调用情况：

1. 顶部统计大盘：近 N 天 Token 用量、按工具聚合的调用次数和延迟。
2. Tab 1 工具调用日志：每次工具调用一行（含 `denied / cancelled / pending_confirm`），可看脱敏后的参数与结果摘要。
3. Tab 2 会话浏览：列出某租户所有 AI 会话，点击进入抽屉回放完整消息流（user / assistant / tool）。

数据全部来自**租户独立库**的 `biz_ai_*` 表，运营通过 `tenantCode` 切换查看不同租户。

## 二、需求详情

### 2.1 顶部租户切换

- 数据源：`GET /api/console/ai/observe/tenants`，返回**已开通 `ai_assistant` 产品功能**的租户编码列表。
- SQL 路径：`sys_tenant → sys_tenant_product → sys_product_version → sys_version_feature → sys_product_feature(feature_code='ai_assistant')`。
- 切换租户后自动重新加载：统计大盘、工具调用日志、会话列表。

### 2.2 统计大盘

调用 `GET /api/console/ai/observe/stats?tenantCode=xxx&days=7`，展示：

| 卡片 | 数据 | 说明 |
|------|------|------|
| 近 N 天 Prompt Tokens | `total_prompt_tokens` | 来自 `biz_ai_session.total_prompt_tokens` 累加 |
| 近 N 天 Completion Tokens | `total_completion_tokens` | 来自 `biz_ai_session.total_completion_tokens` 累加 |
| 工具调用 Top（表格） | `tool_stats[]` | 按 `tool_code` 聚合 |

`tool_stats` 字段：

| 字段 | 说明 |
|------|------|
| `tool_code` | 工具编码 |
| `total` | 调用总次数 |
| `success` | 成功数 |
| `failed` | 失败数 |
| `denied` | 拒绝数（PermissionGuard） |
| `avg_latency_ms` | 平均延迟（毫秒） |

> Token 总量是历史累计值，不按 `days` 过滤；`tool_stats` 按 `created_at >= NOW() - INTERVAL days` 过滤。

### 2.3 Tab 1：工具调用日志

工具栏：

- 状态下拉：`success / failed / denied / pending_confirm / cancelled`
- 工具编码模糊搜索
- 会话 ID 精确匹配
- 用户 ID 精确匹配（API 支持，前端表单未暴露但可后续扩展）

列表字段：

| 列 | 说明 |
|----|------|
| ID | 主键 |
| 会话 ID | `session_id` |
| 用户 ID | `user_id` |
| 工具 | `tool_code` |
| 状态 | Tag 着色：`success=success / failed=danger / denied=warning / pending_confirm=info / cancelled=info` |
| 延迟(ms) | `latency_ms` |
| 时间 | `created_at` |
| 详情 | 点击 popover 展示参数（`params`）/ 结果摘要（`result_summary`）/ 错误（`error_message`），均已脱敏 |

排序：`id DESC`。分页 20/50/100。

### 2.4 Tab 2：会话浏览

工具栏：

- 标题 / 会话号模糊
- 数字员工编码精确
- 用户 ID 精确

列表字段：

| 列 | 说明 |
|----|------|
| ID | `biz_ai_session.id` |
| 标题 | 首条用户消息摘要（`title`） |
| 数字员工 | `employee_name (employee_code)` |
| 用户 ID | `user_id` |
| 消息数 | `message_count` |
| Tokens (P/C) | `totalPromptTokens / totalCompletionTokens` |
| 最后消息 | `last_message_at` |
| 创建时间 | `created_at` |
| 操作 | 「查看」按钮 |

排序：`last_message_at DESC, id DESC`。

点击行或「查看」打开右侧抽屉，调用 `GET /api/console/ai/observe/sessions/{id}/messages`，展示：

- 顶部 meta：租户、数字员工、用户 ID、消息数、Tokens
- 消息流（按 `id ASC`）：每条消息按 role 着色：
  - `user`：浅灰背景，圆角左对齐
  - `assistant`：浅蓝背景，含 `tool_calls` 时展示嵌套块（工具名 + arguments JSON）
  - `tool`：浅绿背景，展示 `tool_name` + `content`
  - `system`：默认色（一般不入库，留兜底显示）
- 异常消息额外渲染 `error_message` 红色块。

### 2.5 跨租户库查询机制

由于会话 / 消息 / 工具日志在租户独立库（`zt_biz_{tenant_code}`），Console 路由层手动获取该租户的 SessionFactory：

```python
db_manager._get_or_create_tenant_engine(tenant_code)
factory = db_manager._tenant_session_factories[tenant_code]
async with factory() as session:
    data = await AuditService.xxx(session, ...)
```

不依赖 `TenantMiddleware`（Console 上没有租户中间件），租户 engine 按需创建并缓存。

> 当前实现没有对运营触发的租户库连接做关闭策略，长期运行后可能驻留多个租户连接池；如租户量过大需后续增加 LRU/idle 关闭逻辑。

## 四、API 接口设计

前缀：`/api/console/ai/observe`，全部需要平台 JWT。

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/tenants` | 已开通 `ai_assistant` 的租户编码列表 |
| GET | `/tool-logs` | 工具调用日志分页（指定 tenantCode） |
| GET | `/stats` | 单租户统计概览（近 N 天） |
| GET | `/sessions` | 会话分页 |
| GET | `/sessions/{session_id}/messages` | 会话消息回放 |

### 4.1 租户列表

`GET /api/console/ai/observe/tenants`

响应：


## 五、前端页面设计

- 路由：`/ai/observe`
- 主组件：`frontend/console/src/views/ai/observe/index.vue`（约 580 行）
- 抽屉详情：内嵌在主组件，`el-drawer rtl 50%`。

页面交互要点：

- 租户下拉切换后，`onTenantChange` 同时刷新统计、工具日志、会话列表。
- 工具日志详情用 `el-popover` 展开，避免占用整页布局。
- 会话浏览的行点击与「查看」按钮等价，注意 `@row-click` 与「查看」按钮的 `@click.stop` 防冒泡。
- 抽屉消息流按 role 着色（`ai-msg--user / ai-msg--assistant / ai-msg--tool / ai-msg--system`），并展示 `model_used` / `finish_reason` 等元信息便于排查。
- `tool_calls` 在 assistant 消息内嵌渲染：工具名 + `arguments` JSON pre 标签，避免与正文 `content` 混在一起。
- 当前未做导出 CSV / 时间范围筛选，远期可补充。

## 六、测试要点

1. 租户列表：未开通 `ai_assistant` 的租户不出现在下拉中；新开通后**需重新加载页面**才会刷新（前端未做主动重拉）。
2. 跨租户切换：从 `acme` 切到 `demo` → 大盘 / 工具日志 / 会话列表全部更新；不会泄漏 `acme` 数据到 `demo` 视图。
3. 工具日志状态过滤：状态选 `denied` → 仅显示被 PermissionGuard 拒绝的记录；点详情可看到拒绝原因（脱敏后参数 + `error_message`）。
4. `pending_confirm` 状态：当客户端高风险确认未完成（用户没有点确认/取消）→ 该日志一直停留为 `pending_confirm`，运营可识别"卡住"的会话。
5. 统计：`days=7` → `tool_stats` 仅含近 7 天数据；改 `days=30` → 重新加载。
6. 会话回放：抽屉内 user/assistant/tool 配色清晰；`tool_calls` 在 assistant 消息中展开，arguments JSON 可读。
7. 消息超长截断：`limit=200` 上限；如某会话 >200 条消息，需手动调整 `limit` 或后续接 `cursor` 分页（远期）。
8. `result_summary` 已脱敏：手机号 / 身份证 / api_key 不在前端可见。
9. 删除（软删除）的会话：`is_deleted=1` 的会话不在列表显示，但工具日志查询 `session_id` 仍可查到（数据保留以便审计）。

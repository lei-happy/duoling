# 运营后台 - 工具中心

> 父文档：[00.模块总览.md](00.模块总览.md)
>
> 对应代码：`frontend/console/src/views/ai/tool/index.vue` · `backend/app/modules/ai/api/console/tool.py` · `backend/app/modules/ai/services/tool_service.py` · `backend/app/modules/ai/tools/`

## 一、功能概述

「工具中心」管理 AI 数字员工**可调用的能力单元**。工具实现位于代码（`@register_tool` 装饰器声明），表 `ai_tool` 仅用于存储元数据，承担三件事：

1. Console 列表展示与启停（运营可在不发版的情况下临时下线某个工具）。
2. 与 [01.数字员工管理.md](01.数字员工管理.md) 的工具绑定关系（`ai_employee_tool.tool_id`）的外键载体。
3. 与代码注册表对账（启动时 / Console 手动按钮 upsert，已删除工具标记 `is_builtin=0`）。

> **设计取舍**：工具签名（参数 schema、风险等级、所需权限）与代码强绑定，运营**不能在 Console 编辑**这些字段；只能切换 `status` 启停。新增工具需在后端写代码 + `@register_tool` 注册，发版后从 Console 点「从代码同步」即可见。

## 二、需求详情

### 2.1 列表页

工具栏：

- 关键字搜索（编码 / 名称模糊）
- 分类下拉（数据来源 `GET /ai/tool/categories`）
- 状态下拉（启用 / 停用）
- 「从代码同步」按钮（关键操作）

页面顶部信息条：

> 「工具实现位于代码中（`@register_tool` 装饰器）。本页只用于查看与启停，不可直接编辑工具签名。」

列表字段：

| 列 | 说明 |
|----|------|
| 编码 | 工具 `code`（如 `waybill.search`） |
| 名称 | 工具人类可读名 |
| 分类 | `category` |
| 描述 | 提供给 LLM 的 function description |
| 风险 | `low` / `medium` / `high` Tag |
| 需确认 | `confirm_required` Yes/No |
| 权限码 | `required_permission`，对应 `sys_menu.menu_code` |
| 代码内置 | `is_builtin=1` 显示「是」，孤立工具显示「已下线」 |
| 状态 | 启停开关，调 `PUT /{tool_id}/status` |

排序：默认按 `category, id ASC`。分页 20/50/100。

### 2.2 「从代码同步」操作

`POST /api/console/ai/tool/sync` → `ToolRegistry.sync_to_db(platform_db)`：

1. 把代码内 `@register_tool` 注册表的所有工具 upsert 到 `ai_tool`。
2. 已存在的行 → 更新元数据字段（`name/category/description/params_schema/required_permission/risk_level/confirm_required/is_builtin`），**保留 `status` 不覆盖**，避免覆盖运营手动启停。
3. DB 有但代码没有的工具 → 标记 `is_builtin=0`（不下线，留运营决策是否人工删除）。
4. 全程不删除任何记录。

返回：

```json
{
  "code": 0,
  "data": { "inserted": 0, "updated": 8, "orphan": 0 },
  "message": "工具同步完成"
}
```

前端通过 ElMessage 展示结果（如「同步完成：新增 0，更新 8，孤立 0」），随后重新加载列表与分类。

### 2.3 启停切换

`PUT /api/console/ai/tool/{tool_id}/status`，请求体 `{ "status": 0 | 1 }`。

- 工具被停用后：
  - `PermissionGuard.check` 第一层校验失败，对话中工具调用直接返回 `denied`，错误信息「工具 {code} 已停用」。
  - Console 数字员工编辑弹窗仍可勾选（不阻塞），但保存后引擎运行时会拒绝。

### 2.4 删除

当前未提供 Console 删除接口（避免误操作清掉员工绑定）。需要清理孤立工具时由 DBA 直接 `UPDATE ai_tool SET is_deleted=1`。

## 三、工具协议

### 3.1 注册装饰器

`backend/app/modules/ai/tools/registry.py:register_tool`：

```python
@register_tool(
    code="waybill.search",
    name="查询运单",
    category="waybill",
    description="按关键词分页查询...",
    params_schema=WaybillSearchParams,  # 必须是 BaseModel
    permission="biz:waybill:list",
    risk_level="low",
    confirm_required=False,
)
async def search_waybill(ctx: ToolContext, **kwargs) -> ToolResult:
    ...
```

工具实现签名约定：

- 入参：`ctx: ToolContext`（含 `db/platform_db/user/tenant_code/session/extras`） + 业务参数 `**kwargs`，其中 `**kwargs` 由 LLM 输出 JSON 反序列化得到。
- 返回：`ToolResult`（`success/data/message/error`）；也允许返回 `dict` 或任意值（自动包装）。

### 3.2 wire 命名编码

OpenAI / Kimi / 通义千问的 function 协议都校验 `function.name ∈ ^[a-zA-Z][a-zA-Z0-9_-]{0,63}$`，不允许点号。约定：

- 内部 `code` 用点号分段（`waybill.search`）以示业务域。
- 送 LLM 时由 `encode_tool_name(code)` 把 `.` 替换成 `__` → `waybill__search`。
- 接收 LLM 工具调用时 `decode_tool_name(wire_name)` 反向还原 → `waybill.search`。
- 因 `code` 内部禁含 `__`，该映射可逆且幂等。
- 工具结果 `tool` 消息回包给 LLM 时 `name` 也使用 wire 名，以与 `assistant.tool_calls` 内的工具名保持一致。

## 四、内置工具清单

当前代码内已注册的工具（按 category 排序）：

| 工具 code | 名称 | 分类 | 风险 | 需确认 | 权限码 | 描述要点 |
|----------|------|------|------|--------|--------|----------|
| `waybill.search` | 查询运单 | waybill | low | 否 | `biz:waybill:list` | 按关键词 / 客户 / 状态分页查询当前租户的运单 |
| `waybill.get_detail` | 查询运单详情 | waybill | low | 否 | `biz:waybill:list` | 按 ID 查询单条运单详情 |
| `waybill.batch_create` | 批量录入运单 | waybill | **high** | **是** | `biz:waybill:add` | 批量入库，需用户确认；建议先 `file.parse_excel` |
| `vehicle.search` | 查询车辆 | vehicle | low | 否 | `resource:vehicle:list` | 按关键词 / 类型 / 状态分页查询车辆 |
| `customer.search` | 查询客户 | customer | low | 否 | `partner:customer:list` | 按关键词 / 类型 / 状态分页查询客户 |
| `file.parse_excel` | 解析 Excel/CSV | file | low | 否 | — | 返回表头 + 列类型推断 + 样本行 |
| `file.map_columns` | 列映射转目标行 | file | low | 否 | — | 把上传文件的列按映射转成目标字段命名的行列表；支持 `constant_fields` 整批统一回填（如追问确认客户后统一填 `customerId`） |
| `image.extract_waybill` | 识别图片运单信息 | file | low | 否 | — | 把运单截图/照片交给视觉大模型，判断 `has_waybill` 并抽取结构化行；视觉模型由录单员 `model_config.vision_provider_code / vision_model` 指定 |

> 详细参数定义见各 `backend/app/modules/ai/tools/*.py` 内的 Pydantic 模型；运行流程详见 [../../02.企业端/06.AI 数字人模块/03.附件与文件解析.md](../../02.企业端/06.AI%20数字人模块/03.附件与文件解析.md)。
>
> **图片识别说明**：`image.extract_waybill` 内部单独调用一次视觉大模型（无 tools），把图片 base64 后以 `image_url` 送入，返回 `{has_waybill, rows[], notes}`。视觉能力被隔离在工具内部，因此主对话模型只需支持 function calling 的文本模型即可。

### 4.1 高风险工具

`waybill.batch_create` 是当前唯一高风险工具：

- `risk_level="high"` 且 `confirm_required=True`。
- 引擎在调用前会写 `pending_confirm` 日志、生成 `confirm_token`、推 SSE `confirm.required`，等待用户在客户端点击「确认执行」后才实际入库。
- 详细状态机见 [../../02.企业端/06.AI 数字人模块/02.高风险确认与权限.md](../../02.企业端/06.AI%20数字人模块/02.高风险确认与权限.md)。

## 五、数据模型设计

### 5.1 `ai_tool`

平台库；软删除；唯一索引 `code`。

| 字段 | 类型 | 索引 | 说明 |
|------|------|------|------|
| id | BIGINT PK | — | — |
| code | VARCHAR(128) | UK | 工具编码（与 `@register_tool` 一致） |
| name | VARCHAR(128) | — | 名称 |
| category | VARCHAR(64) | idx | `waybill / vehicle / customer / file / ...` |
| description | TEXT | — | LLM 看到的 function description |
| params_schema | JSON | — | OpenAI function 协议入参 schema（同步时由 Pydantic `model_json_schema()` 生成，递归剔除 `title`） |
| required_permission | VARCHAR(128) | — | 权限码（`sys_menu.menu_code`） |
| risk_level | VARCHAR(16) | — | `low/medium/high`，默认 low |
| confirm_required | SMALLINT | — | 0/1，默认 0 |
| is_builtin | SMALLINT | — | 1=代码注册的内置工具；0=已与代码失联（孤立） |
| status | SMALLINT | idx | 0=停用 / 1=启用，默认 1 |
| created_at / updated_at / is_deleted | — | — | — |

## 七、前端页面设计

- 路由：`/ai/tool`
- 主组件：`frontend/console/src/views/ai/tool/index.vue`
- 无编辑弹窗；状态用 `el-switch` 直接切换。

页面交互要点：

- 「从代码同步」按钮放在工具栏右侧，type=warning plain，避免与「新增」按钮混淆（本页无新增）。
- 风险列 Tag 颜色：`high=danger / medium=warning / low=info`。
- `isBuiltin=false` 时强提示「已下线」（红色 Tag），暗示运营核对是否需要清理 `ai_employee_tool` 残留绑定。
- 「需确认」列直接展示「是 / 否」，颜色 `warning / info`。

## 八、测试要点

1. 后端启动后，`ToolRegistry.sync_to_db` 在 lifecycle 中自动执行（参见 `app.core.events:lifespan`）；首次启动 `inserted=8, updated=0, orphan=0`，二次启动 `inserted=0, updated=8, orphan=0`。
2. 手动停用 `waybill.search` → 客户端调用该工具时立即返回 `denied`，`tool.result.error` 内容为「工具 waybill.search 已停用」。
3. 一键同步幂等：连续两次调用 `/sync`，第二次应 `inserted=0, updated=N, orphan=0`。
4. 删除代码中某工具的 `@register_tool` → 重新启动 → 同步后该工具 `is_builtin=0`，列表「代码内置」列展示「已下线」。
5. wire 命名编码：测试 `waybill.search ↔ waybill__search` 互转幂等；以 `waybill__search` 为输入再编码不会得到 `waybill____search`。
6. 启用 / 停用切换不影响 `ai_employee_tool` 绑定数据，仅影响运行时 `PermissionGuard` 校验通过性。

# LITE 端 - 承运商运力上报（接口契约）

> 状态：契约阶段（占位实现 + 文档化），具体落地见 LITE 端项目排期。

## 1. 背景

调度工作台改造后，企业把任务分配给承运商时（``carrier_type=2``），仅写入承运方
快照，不强制要求企业调度员选择具体运力。具体运力由承运商通过自己的
"LITE 端"在收到调度通知后**自行上报**。本文档定义承运商上报运力的接口契约，
后端先以"占位实现"形式提供（仅做合法性校验 + 调用既有 ``assign_carrier``），
后续由 LITE 端落地时配合实际签名校验、消息推送等增强。

## 2. 流程

```
企业调度员 → 企业端"派车"动作 → 任务 status: -1→0
            ↓
            （承运商类型任务）
            ↓
LITE 端承运商 ← 短信/站内消息通知（任务编号 + 一次性签名 token）
LITE 端承运商 → POST /api/lite/carrier/task/{id}/dispatch
              （携带运力快照 + 签名 token）
              ↓
            后端校验 → 写入 task carrier 快照 → status: 0→1（已派车）
              ↓
            企业端工作台/移动端实时推送状态变化
```

如果承运商不响应，调度员可在企业端使用"代填运力"兜底面板（``isProxy=true``）。

## 3. 接口

### 3.1 承运商上报运力

```
POST /api/lite/carrier/task/{task_id}/dispatch
Headers:
  X-Lite-Token: <一次性 JWT，含 carrier_id / task_id / exp>
Body:
{
  "capacityId": 9999,                      // 可选；若 LITE 端有运力库
  "mainDriverName": "李司机",              // 必填
  "mainDriverPhone": "13800000000",        // 必填
  "mainDriverIdCard": "110...",            // 可选
  "plateNumber": "京A12345",               // 必填
  "trailerPlateNumber": "京A98765"         // 可选
}

Response:
{
  "code": 0,
  "data": {
    "taskNo": "T2026052100001",
    "status": 1,                           // 已派车
    "dispatchedAt": "2026-05-21T22:30:00"
  }
}
```

### 3.2 校验规则

- ``X-Lite-Token`` 必填且未过期；token 中 ``carrier_id`` 必须等于任务的
  ``carrier_id``；``task_id`` 必须等于路径参数。
- 任务当前 ``status`` 必须 ∈ ``{0 待派车}``（已派车则拒绝重复上报）。
- 任务的 ``carrier_type`` 必须 == ``2``（仅承运商类型任务可走此接口）。
- ``mainDriverName / mainDriverPhone / plateNumber`` 三字段必填，不依赖 LITE
  端是否有自有运力库。

### 3.3 落地写入

后端校验通过后等价调用：
```python
TaskService.assign_carrier(
    db, task_id,
    TaskAssignCarrierRequest(
        carrier=TaskCarrierInfo(
            carrierType=2,
            carrierId=task.carrier_id,
            capacityId=payload.capacityId,
            mainDriverName=payload.mainDriverName,
            mainDriverPhone=payload.mainDriverPhone,
            mainDriverIdCard=payload.mainDriverIdCard,
            plateNumber=payload.plateNumber,
            trailerPlateNumber=payload.trailerPlateNumber,
            carrierName=task.carrier_name,
        ),
        isProxy=False,
    ),
)
```

LITE 端上报与企业端"代填运力"兜底（``isProxy=true``）落地路径相同，
仅审计来源不同。

## 4. 占位实现

当前后端代码位置：``backend/app/modules/open/api/lite_carrier_dispatch.py``。

占位实现：
- 仅暴露 ``POST /api/lite/carrier/task/{task_id}/dispatch`` 端点
- 校验 token 是否非空（先跳过签名细节）
- 调用 ``TaskService.assign_carrier`` 落地承运方快照与状态推进

LITE 端项目落地时，应替换为真正的 JWT/HMAC 校验、消息推送回调，并补齐：
- 邀请短信链接（一次性 token 颁发）
- 企业端 / LITE 端的双向状态同步
- 承运商运力库 CRUD（``biz_carrier_capacity`` 等表）

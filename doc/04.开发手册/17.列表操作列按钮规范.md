# 列表操作列按钮规范

> **适用范围**：企业端 Client（`frontend/client`）数据表格「操作」列。  
> **目的**：统一权限显隐、外显数量、「更多」交互、按钮顺序与图标，避免各模块各写一套。  
> **参考实现**：计划列表  
> `frontend/client/src/views/operation/waybill/components/waybill-pool.vue`  
> `frontend/client/src/views/operation/waybill/waybill-pool-registry.ts`

---

## 1. 总则

### 1.1 基于功能权限

- 行内操作必须挂菜单按钮权限码（有对应 `menu_code` 时），通过 **`BtnItems`** 的 `permission` / `anyPermission` 控制显隐（底层已过滤无权限项；下拉为空时「更多」不渲染）。
- 仅行状态可点、产品上不单独控权的辅助动作（如部分只读「详情」）可暂不挂码，但**不得**用「没配权限点」绕过本应受控的写操作。
- 后续在菜单配置中补齐按钮权限后，须同步把 `permission` 挂上。

### 1.2 外显最多 2 个（含「更多」）

过滤（权限 + 行状态）后的可见动作 `visible`：

```text
若 visible.length <= 2 → 全部平铺，不出「更多」
若 visible.length >= 3 → 外显 = [visible[0], 更多(visible.slice(1))]
```

- 「更多」本身占 1 个外显位；整列最多看到 2 个入口。
- **最外层主按钮** = 配置顺序中、当前行真正可见的第一项（不是写死「一定是修改/详情」）。

### 1.3 「更多」悬停展开

- 统一使用 **`btn-items`** + `preset: 'more'` + `dropdownItems`。
- `EleButtons` 已对更多菜单强制 `trigger: 'hover'`，**禁止**新业务页手写 `el-dropdown trigger="click"` 作为操作列标准。
- 存量例外（如任务单台账）可后续按本规范收敛，新模块不得再复制 click 模式。

### 1.4 顺序：与菜单按钮配置对齐（文档约定）

- 代码中的 `actions[]` / `rowActions` 顺序须与菜单管理里该页**按钮权限**的 `sort_order` 保持一致。
- **不**在运行时读取菜单 `sortNumber` 排序；改菜单顺序时，同步改前端配置数组。
- 危险操作（删除等）靠后；下拉内可用 `divided: true`、`danger: true`。

**为何不用运行时读菜单？** 操作列常含「仅状态可见、尚未建按钮权限」的动作；运行时排序依赖权限点配齐，改造面大。文档约定即可保证与后台配置心智一致。

**外显由谁决定？** 采用「有序动作表 + 槽位算法」：配置顺序对齐菜单 → 过滤可见项 → 按 §1.2 占位。不推荐给每个动作手写 `outer: true`（多状态易乱）。

### 1.5 「更多」内须有图标

- 下拉每一项必须配置 `icon`。
- 优先使用 `@/components/icons`（EleAdminPlus 再导出）或 `@element-plus/icons-vue`。
- 缺合适图标时：用项目 SVG 技能生成后放到 `frontend/client/src/components/icons/`，并在 `icons/index.ts` 导出，再给按钮使用。
- 不同动作避免共用同一图标（如「详情」与「计算明细」须可区分）。

### 1.6 操作列宽度（防裁切）

Element Plus / `ele-pro-table` 的 **`fixed: 'right'` 操作列无法按单元格内容真正自适应**。列宽过小会导致：

- 按钮文案被裁成「计算明…」
- 「更多」右侧下拉箭头被遮挡、点不到

**必须**按「最坏外显文案」预留宽度，不要拍一个偏小的固定 `width`：

| 外显形态（过滤后） | 建议 `minWidth`（含图标与间距，偏保守） |
|---|---|
| 仅 1 个二字按钮（如「详情」） | ≥ 80 |
| 首项 +「更多」 | ≥ 160 |
| 两个平铺且含四字文案（如「详情」「计算明细」） | ≥ 200 |

落地要求：

1. 操作列使用 **`minWidth`（可同时设同等 `width`）**，数值覆盖图标 + 最长外显文案 + 分隔线 +「更多」箭头 + 单元格内边距。
2. 单元格容器 `white-space: nowrap`，禁止操作区换行或被 `overflow: hidden` 裁切。
3. 可按动作标题估算宽度（计划列表参考 `resolveActionColumnMinWidth`），避免手写魔法数后漏改。
4. 若页面启用了 `cache-key` 列宽缓存，加宽后须**升级 cache-key**（或清本地缓存），否则用户仍看到旧的窄列宽。

## 2. 标准写法

### 2.1 模板

```vue
<template #action="{ row }">
  <btn-items
    divider
    type="link"
    :wrap="false"
    :items="actionItems(row)"
  />
</template>
```

### 2.2 槽位组装（伪代码）

```ts
function buildActionColumnItems(row): ButtonItem[] {
  // 1. 按配置顺序生成候选（含 permission、icon、onClick）；行状态不满足则跳过
  const visible = actions
    .map((a) => toButtonItem(a, row))
    .filter(Boolean) as ButtonItem[];

  // 2. 槽位算法
  if (visible.length <= 2) {
    return visible.map((it) => ({ ...it, type: 'link' }));
  }
  const [primary, ...rest] = visible;
  return [
    { ...primary, type: 'link' },
    { preset: 'more', dropdownItems: rest }
  ];
}
```

### 2.3 权限字段示例

```ts
{
  title: '修改',
  permission: 'business:waybill:edit',
  icon: EditOutlined,
  onClick: () => openEdit(row)
}
```

## 3. 参考实现（计划列表）

| 文件 | 职责 |
|------|------|
| `waybill-pool-registry.ts` | 各状态池 `rowActions` 顺序；`resolveActionColumnMinWidth` 估算操作列宽 |
| `waybill-pool.vue` 的 `buildAction` / `actionItems` | 行状态门禁、permission、图标、槽位算法 |

约定摘要：

- 有编辑场景的池：`edit` 靠前（对应 `business:waybill:edit`），删除靠后（`business:waybill:delete`）。
- 无编辑的池（如调度中）：`detail` 靠前，保证过滤后首项为「详情」。
- 尚无独立菜单码的动作（详情、计算明细、重算、锁定等）仍按状态显隐；菜单补齐后挂上 `permission`。
- 操作列宽由 `resolveActionColumnMinWidth` 按外显文案估算，避免「计算明细 / 更多箭头」被裁切。

## 4. 自检清单

- [ ] 操作列使用 `btn-items`，未新增 click 型手写下拉
- [ ] 过滤后 ≤2 个动作时无「更多」；≥3 时为「首项 + 更多」
- [ ] 「更多」悬停可展开，且每一项有区分图标
- [ ] 有菜单按钮权限的动作已挂 `permission`，无权限用户看不到
- [ ] `rowActions` / `actions` 顺序与菜单按钮 `sort_order` 一致（或已注明差异原因）
- [ ] 操作列 `minWidth` 覆盖最坏外显（含图标、四字文案、「更多」箭头），无裁切
- [ ] 若有 `cache-key`，加宽后已升级 key，避免沿用旧窄列宽

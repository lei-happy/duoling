# 租户端主题锁定与自定义主题入口

## 1. 背景与现状

租户端（`frontend/client`）原本内置「自定义主题」功能（右上角设置入口 → 主题设置抽屉，可切换皮肤背景、常用布局、顶栏/侧栏风格、主题色等）。

出于品牌统一诉求，现已**关闭自定义主题功能**：企业不允许自定义，所有企业强制使用统一的品牌主题。

### 当前锁定的品牌主题配置

以下取值严格对照主题设置面板截图，全部定义在 `frontend/client/src/store/modules/theme.ts` 的 `DEFAULT_STATE`：

| 配置项 | 字段 | 值 | 面板显示 |
| ------ | ---- | -- | -------- |
| 主题色 | `color` | `#0065FF` | 品牌主色 |
| 皮肤背景 | `skinConfig` | `null` | 经典主题（无背景） |
| 常用布局 | `layoutName` | `'default'` | 常规布局 |
| 顶栏风格 | `headerStyle` | `'dark'` | 暗色顶栏 |
| 侧栏风格 | `sidebarStyle` | `'light'` | 亮色侧栏 |
| 导航模式 | `layout` | `'mix'` | 混合菜单 |
| 混合菜单分割 | `menuItemTrigger` | `'route'` | Route |
| Logo 置于顶栏 | `logoInHeader` | `true` | 打开 |
| 页签显示图标 | `tabIcon` | `false` | 关闭 |
| 路由切换动画 | `transitionName` | `'fade'` | 淡入淡出 |
| 圆角主题 | `roundedTheme` | `true` | 打开 |
| 暗黑 / 色弱模式 | `darkMode` / `weakMode` | `false` | 关闭 |

> 其余外观项均使用 `DEFAULT_STATE` 中的默认值（页签风格 `simple`、固定顶栏/侧栏/主体、内容区铺满、侧栏排它展开等）。
> 页签相关的「固定主页页签 / 刷新保留页签 / 页面切换缓存」属于 `store/modules/tab.ts`，其默认值已与面板一致，无需改动。

### 品牌定制颜色（CSS 变量覆盖）

主题设置面板只能选风格，无法精确指定顶栏/菜单的具体色值，因此以下两处品牌色通过覆盖组件库 CSS 变量实现，定义在 `frontend/client/src/styles/layout.scss`：

| 部位 | CSS 变量 | 品牌值 | 组件库默认 |
| ---- | -------- | ------ | ---------- |
| 暗色顶栏背景 | `--ele-header-dark-bg` | `#081629` | `#001529` |
| 左侧菜单选中背景 | `--ele-menu-item-active-bg` | `#E8F3FF` | 主色 `light-9` |
| 左侧菜单悬停背景 | `--ele-menu-item-hover-bg` | `#E8F3FF` | `transparent` |
| 展开子菜单容器背景 | `--ele-menu-child-bg` | `transparent` | `rgba(0,0,0,0.02)` |

```scss
/* 暗色顶栏背景色（变量挂在 .ele-admin-layout 上，用更高特异性覆盖） */
.ele-admin-layout.ele-pro-layout {
  --ele-header-dark-bg: #081629;
}
/* 左侧菜单相关背景色（变量挂在 .ele-menu 上，排除顶栏水平菜单） */
.ele-menu:not(.el-menu--horizontal) {
  --ele-menu-item-active-bg: #e8f3ff; /* 选中项背景 */
  --ele-menu-item-hover-bg: #e8f3ff; /* 悬停背景 */
  --ele-menu-child-bg: transparent; /* 展开子菜单去掉灰色底 */
}
```

> 说明：`--ele-menu-item-active-bg` 定义在 `.ele-menu` 元素上，无法通过祖先节点的 `layoutCustomStyle` 覆盖，必须用等于/高于 `.ele-menu` 特异性的选择器覆盖。要调整其它色值时，可先在组件库主题映射 `ele-admin-plus/es/style/themes/default.scss` 中查到对应变量名（`header`/`sidebar`/`menu` 等分组），再在此处覆盖。

## 2. 涉及的代码位置

关闭自定义主题一共改动了 3 个文件，理解这些改动点是后续「重新开启入口」和「设置通用主题」的前提。

### 2.1 `frontend/client/src/store/modules/theme.ts`（核心）

- **`DEFAULT_STATE`**：主题状态默认值，即当前的品牌主题配置。上表所有值都在这里定义。
- **`THEME_CACHE_RESTORE_PROPS`**：允许从本地缓存（localStorage）恢复的属性白名单。
  - 自定义主题关闭后，仅恢复与外观无关的运行时状态：`['collapse']`（侧栏折叠）。
  - 其余外观属性一律回落到 `DEFAULT_STATE`，即使 localStorage 里残留了旧的自定义值也会被忽略。
- **`state()`**：初始化时只按 `THEME_CACHE_RESTORE_PROPS` 白名单从缓存恢复，不再全量读取缓存。
- **`recoverTheme()`**：强制 `skinConfig = null`（固定经典主题），不再读取缓存的皮肤背景。

### 2.2 `frontend/client/src/store/modules/user.ts`

- 登录 `fetchUserInfo` 中，**移除了「从服务端 `userInfo.themeConfig` 恢复主题外观」的逻辑**。
- 主题固定为品牌配置，不再受服务端历史自定义影响。

### 2.3 `frontend/client/src/layout/components/header-right.vue`

- **移除了右上角「主题设置」入口按钮**及其打开抽屉（`openSetting` / `useModal`）的逻辑。
- 设置抽屉相关组件（`setting-drawer.vue`、`setting-theme.vue`、`setting-layout.vue`、`setting-skin.vue`）仍保留在代码库中，但已无入口可达。

## 3. 如何重新打开「自定义主题」入口

当需要临时调试主题、或希望重新放开自定义能力时，按需回滚以下改动。

### 3.1 仅恢复入口按钮（最小改动）

在 `frontend/client/src/layout/components/header-right.vue` 中恢复设置入口：

1. `<template>` 末尾（暗黑模式开关之后）加回主题设置按钮：

```vue
<!-- 主题设置 -->
<layout-tool @click="openSetting" style="position: relative">
  <el-icon>
    <MoreOutlined />
  </el-icon>
</layout-tool>
```

2. `<script setup>` 中补回依赖与打开抽屉的方法：

```ts
import { useI18n } from 'vue-i18n';
import { LayoutTool, useModal } from 'ele-admin-plus';
import { MoreOutlined /* , ... */ } from '@/components/icons';

const { t } = useI18n();
const { openModal } = useModal();

/** 打开主题设置抽屉 */
const openSetting = () => {
  openModal({
    modalId: 'theme-setting-drawer',
    type: 'drawer',
    asyncComponent: () => import('./setting-drawer.vue'),
    props: {
      size: 268,
      title: t('layout.setting.title'),
      zIndex: 199999,
      bodyStyle: { padding: 0, height: '100%' },
      modalClass: 'ele-setting-drawer'
    },
    keepAlive: true
  });
};
```

> 完整原始代码可参考本次改动前的 Git 历史（`git log -p frontend/client/src/layout/components/header-right.vue`）。

### 3.2 让自定义生效并持久化（完整放开）

只恢复按钮后，抽屉里的调整**在刷新后仍会被品牌配置覆盖**（因为 `theme.ts` 仍在忽略缓存）。若要让企业自定义真正生效并跨会话保留，需同时回滚：

1. `theme.ts` → `state()`：改回全量从缓存恢复（`skinConfig` 除外）：

```ts
const cache = getCacheSetting();
Object.keys(state).forEach((key) => {
  if (key !== 'skinConfig') {
    const value = cache[key];
    if (typeof value !== 'undefined') {
      state[key] = value;
    }
  }
});
```

2. `theme.ts` → `recoverTheme()`：改回从缓存恢复皮肤背景（使用 `getCacheSkinConfig`，并补回其 import）。
3. `user.ts` → `fetchUserInfo`：改回「从服务端 `themeConfig` 恢复主题」的逻辑（补回 `useThemeStore`、`cacheSetting` 两个 import）。

> 同样可直接对照本次改动前的 Git 历史进行回滚。

## 4. 修改后如何设置为「通用主题」

「通用主题」= 把某一套外观设为 `DEFAULT_STATE`，让所有企业统一使用。推荐流程：

1. **临时开启入口**：按 [3.1](#31-仅恢复入口按钮最小改动) 恢复设置入口按钮（无需放开持久化）。
2. **在面板中调好外观**：打开主题设置抽屉，按目标效果调整皮肤背景、常用布局、顶栏/侧栏风格、主题色、Logo 位置等。
3. **读取实际配置值**：调整后，浏览器会把配置写入 localStorage。打开开发者工具 → Application → Local Storage，读取键 **`theme`**（见 `frontend/client/src/config/setting.ts` 的 `THEME_CACHE_NAME`），其中即为完整主题配置 JSON。关键字段：
   - `color`：主题色
   - `headerStyle` / `sidebarStyle` / `mixSidebarStyle`：顶栏 / 侧栏 / 双侧栏风格（`light` | `dark` | `primary`）
   - `layout` / `sidebarLayout`：布局类型
   - `logoInHeader`、`tabInHeader`、`colorfulIcon`、`tabStyle` 等其余开关
   - `layoutName`：常用布局名称（如 `default` = 常规布局）
   - `skinConfig`：皮肤背景（经典主题为 `null`）
4. **回填到 `DEFAULT_STATE`**：将上述值写入 `frontend/client/src/store/modules/theme.ts` 的 `DEFAULT_STATE` 对应字段，作为新的品牌通用主题。
5. **收尾**：撤销第 1 步临时恢复的入口按钮（重新隐藏），保持 `theme.ts` / `user.ts` 的「忽略缓存 / 服务端」逻辑不变。这样新配置对所有企业生效，且企业仍无法自定义。
6. **（可选）清理历史缓存**：由于当前逻辑已忽略缓存与服务端历史值，通常无需额外清理；如需彻底移除旧数据，可清空 localStorage 的 `theme` 键或调用后端主题重置接口。

> 说明：`headerStyle`、`sidebarStyle` 等外观项与 `layoutName` 是相互独立的。`layoutName` 仅用于面板中高亮「当前选中的常用布局」，实际渲染以各外观字段为准。因此把 `layoutName` 设为 `'default'` 的同时，可自由锁定与「常规布局」预设不同的顶栏/侧栏风格（当前品牌主题即属于这种情况：常规布局 + 暗色顶栏 + 亮色侧栏）。

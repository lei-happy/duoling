# 列表筛选区布局规范

> **适用范围**：企业端 Client（`frontend/client`）及同类子应用中，**带列表数据**的业务页面顶部「筛选 / 搜索条」区域。  
> **目的**：保证各模块视觉与交互一致，避免自定义 flex 与栅格混用导致的错位、换行异常；新模块开发请直接对照参考实现拷贝结构后再改字段。

---

## 1. 总则

### 1.1 浮动标签

- 筛选区内**所有**输入类控件（文本、下拉、日期、级联等）须使用 **`FloatingLabel`**（`@shared/FloatingLabel/index.vue`）。
- 标签文案、占位与交互细节见：[09.浮动标签组件集成指南.md](./09.浮动标签组件集成指南.md)。

### 1.2 自适应换行（先铺满一行，再换第二行）

- 使用 **Element Plus `el-row` + `el-col`** 的 24 栅格实现换行，**禁止**用自定义 `display:flex` 包裹整行筛选控件来「模拟」布局（易与按钮区、日期高度不一致）。
- **大屏（`lg`）**：同一 `el-row` 内各 `el-col` 的 **`span`（`:lg`）之和宜为 24**，先占满第一行；筛选项较多时拆成**第二个 `el-row`**，同样用栅格控制第二行。
- **小屏**：通过 `:md` / `:sm` / `:xs`（通常 `xs="24"`）让字段纵向堆叠，实现**自然换行**。

### 1.3 在整体区域中保持居中、对齐

- 外层统一使用 **`<ele-card search-form>`**，与系统其它列表页一致，利用全局对 `search-form` 的样式保证卡片内边距与基线统一。
- **单行模式**：一行内筛选项与右侧「搜索 / 重置」在同一 `el-row` 中排布，依赖栅格列高一致，使 **`btn-items` 与 `FloatingLabel` 底对齐**（参考驾驶员模块）。
- **多行模式**：第二行放置「时间范围 + 次要条件 + 操作按钮」时，操作列样式参考运单模块的 `waybill-search-bar__col-actions`；若行内控件高度仍不齐，可为 `el-row` 增加 **`align="middle"`** 辅助垂直居中。

## 2. 单行模式（推荐：筛选项可在一行内排完）

**参考实现（标准范例）**：

`frontend/client/src/views/capacity/self_capacity/driver/components/driver-search.vue`

**结构要点**：

```text
<ele-card search-form>
  <el-form label-width="0" @keyup.enter="search" @submit.prevent="">
    <el-row :gutter="8">
      <!-- 若干 el-col，每项一个 FloatingLabel，:lg 等之和为 24 -->
      <el-col :lg="4" :md="8" :sm="12" :xs="24">
        <el-form-item label-width="0px">
          <btn-items :wrap="false" :items="[ 搜索, 重置 ]" />
        </el-form-item>
      </el-col>
    </el-row>
  </el-form>
</ele-card>
```

- **`gutter`**：与参考一致使用 **`8`**（或与产品已有列表统一，勿随意改大改小）。
- **最后一列**：固定放 **`el-form-item` + `btn-items`**，`label-width="0px"`，`preset: 'search'` / `'reset'`。
- **栅格分配**：按字段宽度分配 `:lg`，保证 **`lg` 下总和为 24**；字段数量与驾驶员模块类似时，可直接对齐其 `5 + 5 + 5 + 5 + 4` 等比例再微调。

## 3. 多行模式（筛选项较多、需独立第二行）

**参考实现（标准范例）**：

`frontend/client/src/views/business/waybill/components/waybill-search.vue`

**结构要点**：

```text
<ele-card search-form class="xxx-search-card">
  <el-form class="xxx-search-bar" label-width="0" ...>
    <el-row :gutter="10" class="xxx-search-bar__row">
      <!-- 第一行：主要筛选 -->
    </el-row>
    <el-row :gutter="10" class="xxx-search-bar__row xxx-search-bar__row--second">
      <!-- 第二行：时间范围、次要条件、操作按钮 -->
      <el-col ... class="xxx-search-bar__col-actions">
        <el-form-item label-width="0px">
          <btn-items ... />
        </el-form-item>
      </el-col>
    </el-row>
  </el-form>
</ele-card>
```

- **第一行**：主筛选条件（关键字、客户、状态、出发地/目的地等）。
- **第二行**：日期范围、其它次要条件；**操作按钮仍在最后一列**，并通过 **`xxx-search-bar__col-actions`** 控制表单项与按钮的边距、与上一行视觉对齐（scoped + 非 scoped 样式与运单文件保持一致即可）。
- **`gutter`**：运单参考为 **`10`**，新模块多行布局建议与运单**保持一致**，除非设计统一调整。
---

## 4. 与列表主体的衔接

- 筛选卡片**下方**接 **`ele-card` + `ele-pro-table`**，列表页整体结构参考已有资源/运单模块：`xxx-search` 组件 `@search` 触发父级 `reload(where, 1)`。
- 搜索表单 **`buildWhere` / `emit('search', payload)`** 与 `RouteParam`、`WaybillParam` 等类型对齐，参数命名与后端 Query 一致（camelCase）。

---

## 5. 反例（不要做）

- 用 **纯 flex 自定义** 替代 `el-row` / `el-col` 作为筛选区主布局（易出现与 `btn-items`、日期选择器**垂直不对齐**）。
- 筛选控件使用 **`el-form-item` + `label` 传统左对齐** 而不用 `FloatingLabel`（与系统规范不一致）。
- 在 `el-col` 外再套多层无意义 `div` 且加上 **`align-items: stretch` 等补丁样式**「硬对齐」——应回到标准栅格范例。

# 行政区域同步 · 线上部署与回滚

## 部署前

1. **备份平台库地区表**
   ```bash
   mysqldump -h <host> -u <user> -p zt_platform sys_regions > sys_regions_backup_$(date +%Y%m%d).sql
   ```
2. 确认 `.env` / 环境变量已配置 `AMAP_WEB_SERVICE_KEY`
3. 在 staging 环境完整跑通一次同步 + 回填

## 部署步骤

| 顺序 | 操作 | 验证 |
|------|------|------|
| 1 | 部署后端代码 | 服务正常启动 |
| 2 | `cd backend && make migrate-apply-local` 或 `alembic upgrade head` | `sys_regions` 含 `longitude`/`latitude`/`citycode`；存在 `region_sync_job` 表 |
| 3 | 运营后台 → 数据同步 → 行政区域同步 → 发起同步 | 任务状态 `success`，`total_count` > 0 |
| 4 | 抽查平台数据 | level 1~4 有数据；省/市/区县 `longitude`/`latitude` 非空 |
| 5 | `python -m scripts.fix.backfill_tenant_region_coords --dry-run` | 预览各租户待更新条数 |
| 6 | `python -m scripts.fix.backfill_tenant_region_coords` | 企业端地区列表可见坐标 |
| 7 | 新注册租户冒烟 | `biz_region` level≤3 坐标非空 |

## 回滚

1. 停止新的同步任务
2. `alembic downgrade e3f7a2b91c04`（或对应 revision 的 downgrade）
3. 从备份恢复 `sys_regions`：
   ```bash
   mysql -h <host> -u <user> -p zt_platform < sys_regions_backup_YYYYMMDD.sql
   ```

## 风险说明

- **街道 code**：level=4 使用 `district_adcode * 10000 + seq` 合成，仅平台库使用，不同步至租户
- **1~3 级 code**：与国标 adcode 一致，存量租户 `biz_region.code` 无需变更
- **API 限流**：默认并发 2、间隔 350ms；失败可重新触发同步任务

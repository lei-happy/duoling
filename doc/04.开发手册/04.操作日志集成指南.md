# 操作日志集成指南

## 1. 概述

操作日志系统通过 `@operation_log` 装饰器，自动采集租户端（Client）用户的写操作行为，并**异步双写**到平台库 `sys_operation_log` 和租户库 `biz_operation_log`。

- **Console 端**（运营后台）通过「日志中心 → 操作日志」集中查看所有租户的操作记录
- **Client 端**（企业端）通过「系统管理 → 操作记录」查看本租户的操作记录

开发者在新增业务模块时，只需在 API 端点添加装饰器即可完成集成，无需关心日志写入细节。

---

## 2. 快速接入

### 2.1 三步完成集成

**第一步：导入依赖**

在 API 文件顶部添加：

```python
from starlette.requests import Request
from app.common.operation_log import operation_log
```

**第二步：添加装饰器**

在需要记录日志的端点（POST / PUT / DELETE）上，**紧接 `@router.xxx` 之后**添加装饰器：

```python
@router.post("")
@operation_log(module="车辆管理", action="新增", description="新增车辆")
async def create_vehicle(
    request: Request,     # ← 必须声明 request 参数
    data: VehicleCreate,
    db: AsyncSession = Depends(get_tenant_db),
    _=Depends(get_current_user),
):
    vehicle = await VehicleService.create_vehicle(db, data)
    return success(data=vehicle.model_dump())
```

**第三步：声明 `request: Request` 参数**

确保被装饰的函数签名中包含 `request: Request` 参数。装饰器依赖此对象获取用户身份、租户编码、IP 等上下文信息。

### 2.2 完整示例

以下展示一个模块的所有写操作如何集成日志：

```python
"""
企业端 XX管理 API
"""
from typing import Optional

from fastapi import APIRouter, Depends, Query
from sqlalchemy.ext.asyncio import AsyncSession
from starlette.requests import Request

from app.common.operation_log import operation_log
from app.core.dependencies import get_tenant_db, get_current_user
from app.common.response import success
from app.modules.client.schemas.xx import XxCreate, XxUpdate
from app.modules.client.services.xx_service import XxService

router = APIRouter()


# ✅ GET 接口不需要加装饰器
@router.get("")
async def page_items(
    page: int = Query(1, ge=1),
    page_size: int = Query(20, alias="limit", ge=1, le=100),
    db: AsyncSession = Depends(get_tenant_db),
    _=Depends(get_current_user),
):
    data = await XxService.page_items(db, page=page, page_size=page_size)
    return success(data=data)


# ✅ 新增 —— POST
@router.post("")
@operation_log(module="XX管理", action="新增", description="新增XX")
async def create_item(
    request: Request,
    data: XxCreate,
    db: AsyncSession = Depends(get_tenant_db),
    _=Depends(get_current_user),
):
    item = await XxService.create_item(db, data)
    return success(data=item.model_dump())


# ✅ 编辑 —— PUT
@router.put("/{item_id}")
@operation_log(module="XX管理", action="编辑", description="编辑XX")
async def update_item(
    request: Request,
    item_id: int,
    data: XxUpdate,
    db: AsyncSession = Depends(get_tenant_db),
    _=Depends(get_current_user),
):
    item = await XxService.update_item(db, item_id, data)
    return success(data=item.model_dump())


# ✅ 删除 —— DELETE
@router.delete("/{item_id}")
@operation_log(module="XX管理", action="删除", description="删除XX")
async def delete_item(
    request: Request,
    item_id: int,
    db: AsyncSession = Depends(get_tenant_db),
    _=Depends(get_current_user),
):
    await XxService.delete_item(db, item_id)
    return success()
```

## 3. 装饰器参数说明

```python
@operation_log(module: str, action: str, description: str = "")
```

| 参数 | 类型 | 必填 | 说明 | 示例 |
|------|------|------|------|------|
| `module` | str | 是 | 业务模块名称，与产品菜单对应 | `"车辆管理"`、`"运单管理"` |
| `action` | str | 是 | 操作类型，描述动作分类 | `"新增"`、`"编辑"`、`"删除"`、`"状态变更"` |
| `description` | str | 否 | 操作的具体描述 | `"新增车辆"`、`"变更运单状态"` |

### 3.1 命名规范

**module** — 使用产品侧菜单的中文名称，保持一致性：

| 产品模块 | module 值 |
|---------|----------|
| 员工管理 | `"员工管理"` |
| 角色管理 | `"角色管理"` |
| 组织架构 | `"组织架构"` |
| 数据字典 | `"数据字典"` |
| 车辆管理 | `"车辆管理"` |
| 挂车管理 | `"挂车管理"` |
| 驾驶员管理 | `"驾驶员管理"` |
| 客户管理 | `"客户管理"` |
| 路线管理 | `"路线管理"` |
| 运单管理 | `"运单管理"` |
| 账号安全 | `"账号安全"` |

**action** — 使用统一的动作词汇：

| 操作场景 | action 值 |
|---------|----------|
| 创建资源 | `"新增"` |
| 修改资源 | `"编辑"` |
| 删除资源 | `"删除"` |
| 批量删除 | `"批量删除"` |
| 启用/禁用 | `"状态变更"` |
| 分配权限 | `"分配菜单"` |
| 修改密码 | `"修改密码"` |

## 4. 自动采集的字段

装饰器会自动采集以下信息，开发者无需手动处理：

| 字段 | 来源 | 说明 |
|------|------|------|
| `user_id` | `request.state.current_user` | 当前操作用户 ID |
| `username` | `request.state.current_user.phone` | 当前操作用户手机号 |
| `tenant_code` | `request.state.tenant_code` | 当前租户编码（由中间件注入） |
| `request_method` | `request.method` | HTTP 方法（GET/POST/PUT/DELETE） |
| `request_url` | `request.url.path` | 请求路径 |
| `request_body` | 函数参数中的 Pydantic 模型 | 请求参数（优先提取 body，其次提取路径参数） |
| `response_body` | 函数返回值 | 响应结果 |
| `ip` | `X-Forwarded-For` / `request.client.host` | 客户端 IP |
| `elapsed_time` | 自动计算 | 请求耗时（毫秒） |
| `status` | 异常捕获 | 1=成功，0=失败 |

## 5. 存储架构

### 5.1 双写机制

每次操作日志同时写入两个数据库，使用**独立事务**，不影响业务主流程：

```
Client API 请求
    │
    ├─ 业务逻辑执行 → 返回响应
    │
    └─ asyncio.create_task (异步后台写入)
         ├─ 平台库 zt_platform.sys_operation_log   （含 tenant_code 字段）
         └─ 租户库 zt_biz_{code}.biz_operation_log  （无 tenant_code 字段）
```

### 5.2 数据表结构

**平台库 `sys_operation_log`**（Console 端日志中心查询此表）：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT PK | 主键 |
| tenant_code | VARCHAR(32) | 租户编码，用于跨租户查询 |
| user_id | INT | 操作用户 ID |
| username | VARCHAR(50) | 操作用户名 |
| module | VARCHAR(50) | 操作模块 |
| action | VARCHAR(50) | 操作类型 |
| description | VARCHAR(255) | 操作描述 |
| request_method | VARCHAR(10) | 请求方法 |
| request_url | VARCHAR(255) | 请求 URL |
| request_body | TEXT | 请求参数（截断至 2000 字符） |
| response_body | TEXT | 响应结果（截断至 2000 字符） |
| ip | VARCHAR(50) | IP 地址 |
| elapsed_time | INT | 耗时（ms） |
| status | SMALLINT | 0=失败 1=成功 |
| created_at | DATETIME | 创建时间 |

**租户库 `biz_operation_log`**（Client 端操作记录查询此表）：

字段与 `sys_operation_log` 相同，但**不含 `tenant_code`** 字段。

## 6. 注意事项

### 6.1 装饰器顺序

`@operation_log` 必须放在 `@router.xxx` **之后**（即更靠近函数定义）：

```python
# ✅ 正确顺序
@router.post("")
@operation_log(module="XX管理", action="新增", description="新增XX")
async def create_item(request: Request, ...):
    ...

# ❌ 错误顺序 —— 装饰器不会生效
@operation_log(module="XX管理", action="新增", description="新增XX")
@router.post("")
async def create_item(request: Request, ...):
    ...
```

### 6.2 GET 接口不记录

查询类接口（GET）通常不需要记录操作日志。只对产生**副作用**的写操作（POST / PUT / DELETE）添加装饰器。

### 6.3 `request: Request` 参数必须存在

装饰器通过 `kwargs` 查找 `Request` 对象。如果函数签名中没有 `request: Request`，日志中的用户信息、租户编码、IP 等字段将为空。

### 6.4 异步非阻塞

日志写入通过 `asyncio.create_task` 在后台异步执行，不会增加 API 响应延迟。即使日志写入失败，也不影响业务响应。

### 6.5 独立事务

日志使用独立的数据库 Session 写入。即使业务事务回滚，操作日志仍然会被保留，确保审计完整性。

### 6.6 请求参数提取策略

装饰器按以下优先级提取请求参数：

1. **Pydantic Body** — 如果函数参数中有 `BaseModel` 实例（如 `data: VehicleCreate`），优先提取其 `model_dump()` 结果
2. **路径参数** — 如果没有 body（如 DELETE 请求），则提取路径参数（如 `vehicle_id`）
3. 自动跳过 `request`、`db`、`current_user` 等框架注入参数

### 6.7 数据截断

`request_body` 和 `response_body` 会被自动截断至 **2000 字符**，防止超大请求/响应撑爆数据库。
